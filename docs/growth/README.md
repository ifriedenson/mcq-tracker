## Do them in this order

Order matters. The forum thread and Discord message are permanent and indexed, so they should exist *before* the Reddit post drives anyone to search for you.

### 1. GitHub star prompt — 2 minutes, do it now

`grow.md` §4.6 already points readers at the listing. Nothing to post.

### 2. Forum thread — `grow.md` §4.3

- Go to `forum.obsidian.md` → **Share & showcase** → **Plugins**.
- New topic. Title and body from §4.3, unchanged.
- Add the tag **`plugin-release`** — this is what makes it discoverable to people watching releases.
- It is permanent and indexed, so get it right once. If you edit later, edit the first post rather than replying to yourself.

### 3. Discord — `grow.md` §4.4

- You need the **developer** role before you can post in `#updates`. Request it in the Obsidian Discord using the form linked from `github.com/obsidianmd/obsidian-releases`.
- One message. Do not repost for every patch release; save it for something a user would notice.

### 4. Reddit launch — `grow.md` §4.1

- `r/ObsidianMD`, **flair `showcase`**. Self-promotion without that flair gets removed.
- Post from your own account, not a project account. Both plugins that grew did this.
- **Block out the first four hours.** This is the part that actually works: Spaceforge's positioning happened entirely in comment replies, not in the post. Answer every comment, including the sceptical ones, using §4.5.
- Do not post the same text to Reddit and the forum the same day. Rewrite the opening line if you reuse anything.

### 5. Newsletters — `grow.md` §4.7

- **This Week in Obsidian** — `thisweekinobsidian.substack.com`, community-run, open source. Reply to an issue or email the address on the Substack.
- **Obsidian Stats** — `obsidianpluginstats.substack.com`. It runs a weekly "plugins worth checking out" list and is the same outfit as the stats site everyone reads.
- One email each, plain text, no attachment. If nobody answers, that is normal; do not follow up more than once.

### 6. Creator outreach — `grow.md` §4.8

- Target two kinds separately: Obsidian productivity channels, and exam-prep channels. They want different pitches; §4.8 has both.
- **Attach or link the demo vault.** `samples/sample-vault` already exists with a README and openable question notes. Zip it, or send the repo link plus the sample vault path. This is the whole offer — nobody wants to author test questions on camera.
- Send individually. Reference a specific video so it is obviously not a template.

### 7. Next release — `grow.md` §4.2

- Ship something a user asked for (the Tally form is the input), then post the update with the version in the title.
- This is the highest-leverage repeatable step in the whole doc: Spaceforge's run rate roughly doubled after its v1.1.0 post (§1).
- Cadence: every 3–4 weeks, not every patch.

## What to record afterwards

Fill in a row of the metrics table in `grow.md` §7 every Monday. Four numbers, two minutes:

1. **Downloads** — the listing page or Obsidian Stats.
2. **Listing reviews** — currently 0, which is the cheapest thing to fix.
3. **GitHub stars and issues.**
4. **Tally responses** — `tally.so/r/PRDe1d`.

A post that produces downloads but no reviews and no form responses did not produce engaged users. Judge the first four hours by comments, not by the counter.
