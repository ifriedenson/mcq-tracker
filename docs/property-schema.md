# Property schema and Dataview examples

MCQ Tracker keeps every question and card as a normal Markdown note. The note body is
readable without the plugin, and the properties below are the stable data contract that
other plugins, Dataview queries and scripts can read. The plugin only writes a property
when it has a value, except for the tracking block, which is created with defaults.

This page documents the fields the plugin reads and writes. It is a description of the
current format, not a promise that every field exists on every note: use Dataview's
`row.property` or `row["property with spaces"]` with a fallback when a field is optional.

**Schema version 1.** This is the public data contract for question and card notes.
Changes are additive: existing property names and meanings stay stable. A change that
would break a reader ships with a migration and a new schema version.

## Question notes

| Property | Type | Meaning |
| --- | --- | --- |
| `question_id` | string | Stable ID generated by the plugin. Used to find duplicates and link history. |
| `item_type` | string | `question` for a question note. Cards use `card` or `vocab`. |
| `answer` | string | Correct answer. The importer also understands `correct_answer`, `correct`, `answer_key` and `key`. For a select-all question the value is a set, such as `A, C` or `A and C`. For numeric answers, separate alternatives with `|` and write ranges as `1..2` or `[1, 2]`. |
| `question_type` | string | `mcq`, `spr`, `true_false` or `select_all`. Aliases such as `tf`, `sata` and `select-all-that-apply` are recognised. Any other value is self-graded. |
| `tolerance`, `tolerance_type` | number, string | Optional numeric-answer tolerance. `tolerance_type` is `absolute` (default), `relative` or `percent`. |
| `sig_figs`, `sig_figs_mode` | number, string | Optional significant-figure check. `sig_figs_mode` is `at_least` (default) or `exact`. Fractions are exempt because they are exact. |
| `units`, `answer_unit` | string | Optional physical unit for a numeric answer, such as `m` or `m/s`. Compatible units are converted before comparison; incompatible dimensions are rejected. The separate `unit` property remains the course/unit classification. |
| `accepted_answers`, `accepted_variants` | list or string | Extra accepted numeric or text answers, in addition to `answer`. |
| `variables` | object, list or string | Numeric ranges, lists or fixed values for a parameterized question, for example `a: 2..9` or `a=2..9; b=1..5`. |
| `answer_formula` | string | Safe arithmetic formula for the computed answer, using the variable names and `{{name}}` placeholders. |
| `calculation` | string | Literal arithmetic expression used to verify a numeric answer, for example `6 * 7`. The evaluator is restricted and never uses `eval`. |
| `variant_seed`, `last_variant` | number, string | Written after a parameterized attempt: the seed used and the values (`a=3;b=2.5`). |
| `choice_1` … `choice_8` | string | Answer choices, in display order. |
| `correct_choices` | string | One-based choice numbers, for example `2` or `1,3`. |
| `stimulus_id` | string | Shared ID for a passage or figure used by several questions. |
| `official_question_id` | string | The source's own ID, when it has one (for example a SAT Question Bank ID). The plugin's ID stays in `question_id`. |
| `source_question_id`, `pdf_question_id`, `original_id` | string | Older or source-specific ID names read by the duplicate check. |
| `test`, `section`, `domain`, `skill`, `unit` | string | Classification used by filters, stats and tests. |
| `difficulty` | string | `easy`, `medium` or `hard` when the source provides it. |
| `course` | string | Course tag, when the import or template supplies one. |
| `stimulus` / passage body | Markdown | A passage can live in the note body or in a linked note; `stimulus_id` links the set. |

### Tracking block

These properties are appended with defaults by the normaliser. `correct_count` is never
greater than `attempts`, and `accuracy` is derived rather than stored.

| Property | Type | Meaning |
| --- | --- | --- |
| `result` | string | `correct`, `incorrect`, `skipped` or `unknown`. |
| `date attempted` | string | ISO timestamp of the latest attempt. Quoted in Dataview because of the space. |
| `first_attempted` | string | ISO timestamp of the first attempt. |
| `attempts` | number | Total attempts. |
| `correct_count` | number | Total correct attempts. |
| `streak` | number | Current correct streak. |
| `time_spent_total` | number | Total seconds spent. |
| `last_time_spent` | number | Seconds spent on the latest attempt. |
| `last_answer` | string | The answer chosen or typed on the latest attempt. |
| `last_confidence` | string | Self-reported confidence, when the review asks for it. |
| `last_error_type` | string | Error tag such as `careless` or `misread`. |
| `flagged` | boolean | Whether the learner flagged the note for later. |
| `next_review` | string | `YYYY-MM-DD` due date for the simple ladder or FSRS. |
| `srs` | string | Compact FSRS state. Empty when FSRS has not scheduled the note. |
| `history` | list | Append-only attempts, one string per attempt (see below). |

`history` entries use:

```text
2026-10-29T14:05:00|correct|42|B|3|careless|a-mh3k2-8f1c2a
timestamp|result|seconds|answer|confidence|error|attempt_id|variant
```

Fields after the timestamp may be empty. Rows written before 1.76.0 omit the final
attempt id; the reader accepts both forms, and new rows always carry an id. The id makes
a retry or a phone/desktop merge safe: the same row is never counted twice. The optional
eighth field stores the parameterized variant values (`a=3;b=2.5`).

### Study status

| Property | Type | Meaning |
| --- | --- | --- |
| `study_status` | string | `active`, `known`, `excluded`, `suspended` or `buried`. |
| `known_days` | number | Snooze length written with a Known action. |
| `known_until` | string | Date until which a known item is hidden from normal practice. |
| `excluded_on` | string | Date the item was excluded. |
| `excluded_reason` | string | Optional note explaining the exclusion. |
| `suspended_on` | string | Date the item was suspended; it stays hidden until restored. |
| `buried_until` | string | Date the buried item returns; bury ends at the next day boundary. |

## Card and vocabulary notes

Cards use the same tracking block as questions, so one review queue and one scheduler
work for both. The card-specific fields are:

| Property | Type | Meaning |
| --- | --- | --- |
| `card_id` | string | Stable card ID. A note with `card_id` but no `item_type` is still recognised as a card. |
| `item_type` | string | `card` or `vocab`. |
| `deck` | string | Deck name. Cards in a configured deck folder inherit its course. |
| `course` | string | Course tag, from the card, its deck or its folder. |
| `card_type` | string | `basic`, `reversed`, `cloze` or `image-occlusion`. Basic is the default and is normally omitted. |
| `answer_mode` | string | Per-card override: `flip`, `type` or `speak`. |
| `grading_strictness` | string | Per-card override: `strict`, `standard` or `lenient`. |
| `accepted_variants` | list | Extra answers accepted by the typed-answer grader. |
| `part_of_speech`, `language` | string | Vocabulary-specific fields. |
| `image`, `mask_x`, `mask_y`, `mask_w`, `mask_h`, `mask_label` | string/number | Image-occlusion fields. Coordinates are percentages. |
| `question_set`, `choice_1` … `choice_8`, `correct_choices`, `time_limit` | mixed | Present when a card came from a quiz set; keeps the original choices. |

The card body uses headings rather than a proprietary format:

```markdown
## Front
What is a cell?

## Back
The basic unit of life.
```

Vocabulary uses `## Term`, `## Definition` and optionally `## Example`. Cloze cards use
`{{c1::answer}}`; reversed cards swap the displayed sides at review time. An `## Image`
section points at an image already in the vault.

## Provenance and import fields

These fields let a card or question show where it came from and let repeated imports
update the existing note instead of creating a duplicate.

| Property | Type | Meaning |
| --- | --- | --- |
| `import_source` | string | Source file or folder. |
| `import_format` | string | Importer that created the note, for example `anki`, `quizlet`, `quizlet-pdf` or `csv`. |
| `imported_on` | string | Date of the import. |
| `import_batch` | string | Groups notes written in one import. |
| `import_key` | string | Stable key used to recognise the same source note on a later import. |
| `import_source_url` | string | Source URL, when one was supplied. |
| `source_pdf`, `source_page`, `source_heading`, `source_note`, `source_link` | string | Link back to the document, page, heading or note. |
| `answer_source`, `explanation_source` | string | Where the answer and explanation came from, including AI-generated ones. |
| `ai_generated`, `ai_model` | string | Marks AI-written content and records the model. |
| `anki_note_id`, `anki_card_id`, `anki_guid` | string | The source note, card and GUID from an imported `.apkg`, used by later syncs. |
| `anki_deck`, `anki_model`, `anki_ord` | string/number | The source deck, model name and card ordinal. |
| `anki_due`, `anki_interval`, `anki_reps`, `anki_lapses` | number | Anki's scheduling fields at import or sync time; kept as metadata rather than translated into a different scheduler. |
| `anki_synced_hash`, `anki_remote_hash` | string | Content hashes from the last successful sync; they let a later sync tell a local edit from an Anki edit. |
| `anki_last_sync` | string | ISO timestamp of the last successful AnkiConnect exchange. |
| `answer_source` | string | On an FRQ attempt: `typed`, or `photo` when the answer began as a vision transcript of handwritten work. |
| `answer_pages` | number | On a photo-sourced FRQ attempt: how many photos were read, in order. |

## Dataview examples

These are examples for the [Dataview](https://github.com/blacksmithgu/obsidian-dataview)
plugin. Dataview is a separate MIT-licensed plugin; the queries are ordinary queries over
the properties above and do not require any Dataview-specific code in this plugin.

### Questions due for review

```dataview
TABLE attempts, correct_count, next_review, result
FROM "Questions"
WHERE question_id AND next_review
SORT next_review ASC
```

### Accuracy by skill

```dataview
TABLE length(rows) AS notes, sum(rows.attempts) AS attempts,
  round(sum(rows.correct_count) / sum(rows.attempts) * 100) AS accuracy
FROM "Questions"
WHERE question_id AND attempts > 0
GROUP BY skill
SORT accuracy ASC
```

### Cards due today

```dataview
TABLE deck, attempts, next_review
FROM "Cards"
WHERE card_id AND next_review <= date(today)
SORT next_review ASC
```

### Recently missed questions

```dataview
TABLE result, last_error_type, row["date attempted"] AS last_attempt
FROM "Questions"
WHERE result = "incorrect"
SORT row["date attempted"] DESC
LIMIT 20
```

### One row per attempt

The `history` list is a list of strings, not nested objects, so use DataviewJS when you
need a row per attempt:

```dataviewjs
for (const page of dv.pages('"Questions"').where(p => p.history)) {
  for (const entry of page.history) {
    const [when, result, seconds, answer, confidence, error, attemptId] = String(entry).split("|");
    dv.table(["Question", "When", "Result", "Seconds", "Answer", "Confidence", "Error", "Attempt"],
      [[page.file.link, when, result, seconds, answer, confidence, error, attemptId]]);
  }
}
```

## CSV export

The **Export practice results to CSV** command writes the same data as two files: a
per-note summary and one row per attempt. The CSV column names match the property names
above, so a spreadsheet or notebook can join the export back to the notes by
`question_id` or `card_id`. CSV writing quotes separators and neutralises cells that begin
with a spreadsheet formula marker; the note properties themselves are never modified.

## Data contract

- **Identity.** A question has `question_id`; a card or vocabulary item has `card_id`.
  These IDs are stable and are what exports and other plugins should join on. Source IDs
  such as `official_question_id` are separate and never replace the plugin's ID.
- **Dates.** `next_review` is `YYYY-MM-DD`. `date attempted` and `first_attempted` are
  local wall-clock timestamps to the minute. New `history` rows use local wall-clock
  timestamps to the second. None of these values carries a timezone suffix.
- **History is append-only.** Each review adds one row and new rows carry a unique
  `attempt_id`. Readers must not rewrite, sort or deduplicate the list by timestamp;
  two devices can review the same note in the same minute.
- **Derived fields.** `attempts`, `correct_count`, `time_spent_total`, `streak`, `result`
  and the `last_*` fields are derived from the review history. The repair command can
  rebuild them after a sync merge; `next_review` and the scheduler state are not changed
  by that repair.
- **Optional fields.** A missing property means "not set", not zero or false. Use a
  fallback in Dataview queries. The tracking block is created with defaults, but older
  notes can predate any later field.
- **Compatibility.** New properties may appear in a later release. Existing properties
  are not renamed or repurposed without a migration. Unknown properties are left alone.

## Compatibility notes

- Fields are case-sensitive. The plugin writes lower-case names such as `question_id`,
  `next_review` and `date attempted`.
- `history` is append-only. Avoid rewriting or sorting it outside the plugin if you use
  FSRS or the attempt history.
- `correct_choices` is one-based, matching the displayed `choice_1` … `choice_8` order.
- Dataview's `date()` accepts the ISO `YYYY-MM-DD` form used by `next_review`; older notes
  with an empty date are simply excluded by a `next_review` filter.
- This schema is shared by questions and cards. New fields are additive; existing fields
  will not be renamed without a migration. See **Schema version 1** above.
