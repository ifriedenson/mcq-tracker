# 1.272.0 — Annotator: EPUB annotation

Annotator's EPUB annotation was the last Partially covered reader gap: the plugin
could read EPUBs only as documents, and nothing could be highlighted or annotated in
one. This release adds a dependency-free EPUB reader and an annotation sidecar, so a
book can be opened, annotated and reopened with its annotations intact.

## What is new

- **`src/epub.js`** opens an EPUB as the ZIP it is: `META-INF/container.xml` names the
  package document, the package's manifest and spine give the reading order, and each
  XHTML chapter is reduced to plain text with its heading as the chapter title.
  Scripts, styles and tags are dropped, chapter text is capped at 200,000 characters
  and a book at 300 chapters (both report `truncated`), and stored or deflated entries
  are read through the existing `inflateRaw` helper. `paragraphsOf` and
  `annotateParagraphs` map a chapter's paragraphs to exact character ranges so a
  highlight can be drawn on the paragraph it belongs to.
- **`src/epub-annotations.js`** is the sidecar model: `Book.epub.annotations.md` holds a
  small frontmatter block (book path and a content hash) and one JSON block of
  annotations (`id`, `chapter`, `start`, `end`, `quote`, `note`, `color`, `tags`).
  Quotes are anchored by searching the real chapter text, so an annotation that does
  not occur there is refused rather than stored at a guessed offset; the same range
  updates instead of duplicating; ids are sequential and never reused; tags are
  bounded to six of 24 characters; and damaged JSON is reported, not silently dropped.
  `epubAnnotationLink` writes `[[Book.epub#chapter=2&annotation=ann-3]]`.
- **`src/epub-reader-modal.js`** is the reader: chapter-by-chapter navigation, the
  paragraphs that already carry an annotation marked with their notes, a colour
  choice, **Highlight**/**Update highlight** on each paragraph, and **Remove** per
  annotation. Every action goes through the plugin, then re-reads the sidecar, so what
  is on screen is what is in the vault.
- **`src/plugin.js`** adds `epubBook`, `epubAnnotations`, `addEpubHighlight`,
  `deleteEpubAnnotation`, `openEpubReader`, `openActiveEpubReader`,
  `openEpubAnnotations` and two commands: **EPUB: open the reader** and
  **EPUB: open this book's annotations**. The book is only ever read; the sidecar is
  created on the first highlight and modified afterwards. A missing book, a non-EPUB
  path, a chapter outside the book and an unanchored quote are refused with a message
  and no write.

## Tests

`tests/epub.test.js` (10 tests) builds a real EPUB in memory with the plugin's own ZIP
writer and proves: the container/package/spine are read in order with script and
style content dropped; an empty, non-ZIP, container-less and spine-less book is
refused; an annotation round-trips through the sidecar unchanged; a second annotation
gets a fresh id and chapters filter correctly; an unanchored quote, blank quote,
damaged JSON and bad entry are refused or reported; the same range updates and
removal works; `epubBook` reads from the vault, `addEpubHighlight` writes
`Book.epub.annotations.md`, and `epubAnnotations` re-reads it on reopen; deleting and
adding through the plugin persists; and every refusal writes nothing. The paragraphs
and modal tests drive `annotateParagraphs` and the reader's `mark`/`remove` argument
mapping.

`docs/capability-inventory.md` is regenerated from the bundle by
`scripts/regen-inventory.js`, so the new groups, commands and citing tests match
`main.js` exactly.

## Limits

No EPUB is written, so highlights are not burned into the book's markup. There is no
CFI or DOM-range anchoring: annotations are anchored to character offsets in the
extracted chapter text, which is stable for the same file (the sidecar records a hash
to spot a replaced book) but does not follow a re-flowed edition. Fixed-layout EPUBs,
comics and DRM-protected books are read as text or refused like any other unreadable
container. No dependency, provider, account or network request was added.
