# 1.307.32 (Nov 23, 2026)

Folded into: 1.307.33

A weekday-repeating study task now keeps today when today is its next
weekday, and the suite no longer depends on the day it runs.

**What changed.** `repeatFollowUp` (`src/study-workspace.js`) advanced a
weekday rule from the task's own due date, but then threw that date away
when it was today: a Friday or weekend due date finished on Monday
skipped to Tuesday, and the three `tests/task-recurrence.test.js` cases
that pin it went red every Monday. The rule now keeps the natural next
weekday when it is today, and rolls forward — strictly past today — only
when that date is already in the past, so a long-overdue weekday rule
still lands tomorrow rather than on a finished day. Daily and weekly are
unchanged.

**Fewer date-dependent tests.** Those three cases hardcoded Nov 20–23;
they now anchor on the next Friday after the local day (`futureFriday()`
and `shift()` in the test file), and a new test calls `repeatFollowUp`
with explicit `today` values, so the today-lands rule is proven on any
run date instead of only on Mondays.

**Inventory drift closed.** `docs/capability-inventory.md` is
regenerated and the `ankiConnect` row cites
`tests/security-inventory.test.js`, which the 1.307.31 security pass
added; `docs/release-notes/1.307.1.md` now states the corrected rule.

Full suite: 3,173 tests, 3,173 pass, 0 fail, in UTC and `Etc/GMT+12`;
`npm run check` clean. `main.js` is rebuilt from 384 modules at about
4.3 MB. No setting key, note format, command, review schedule or network
default changed.
