# 1.288.4 — Community-review CSS cleanup

This patch answers the two CSS findings in the 1.288.3 community-plugin
review without removing a feature. It is the next version after 1.288.3.

## Changes

- **Text decoration uses the supported form.** The five `text-decoration-line`
  declarations (`styles.css:718`, `4269`, `8311`, `11568`, `12863`) are now the
  single-keyword `text-decoration` shorthand. The review scanner flags every
  `text-decoration-*` longhand as partially supported at its 1.7.4 baseline;
  the shorthand probes clean.
- **One height in the phone full-screen panel.** The `100vh` fallback at
  `styles.css:14360` is gone; the panel keeps `height: 100dvh` and
  `max-height: 100dvh`. The manifest requires Obsidian 1.8.7, where `dvh` is
  available, so no supported app loses the full-screen height.
- **The hygiene guard follows the scanner.** `tests/release-hygiene.test.js`
  now forbids the longhands (not the shorthand) and checks every declaration
  block for a duplicate `height`, so the two review findings cannot return
  unnoticed.

## Review findings left as designed

The behavior findings are unchanged and intentional: the direct `fs`/`child_process`
usage is the optional desktop OpenCode installer; the unmodified MIT-licensed
PDF++ 0.40.31 vendor bundle adds its own `child_process`, Electron IPC and
`new Function` uses. Vault enumeration and clipboard access are ordinary plugin
features.
`main.js` remains 6,787,753 bytes, so the Obsidian Sync Standard 5 MB file
limit still applies to this release.
