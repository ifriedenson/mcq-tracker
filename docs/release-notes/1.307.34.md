# 1.307.34 (Nov 23, 2026)

The local transcription slice was driven end to end on Linux with a real
whisper.cpp build, the registry-pinned model and a real speech recording, using
the shipped modules themselves. The run exposed one real defect, and the one
plan row that had shipped as a promise — the lecture-compile bridge — is now
wired.

**The real run.** The program was built from the pinned `v1.8.6` source tag with
CMake (Linux has no official published asset, which the installer already says),
and the `base.en-q5_1` model was downloaded and hash-verified by
`src/whisper-install.js` into a disposable vault's plugin data folder. The audio
was `samples/jfk.wav` from that same tagged source. The shipped plugin then built
this argv and started one real process:

```
whisper-cli -m .obsidian/plugins/mcq-tracker/whisper/models/ggml-base.en-q5_1.bin \
  -f .obsidian/plugins/mcq-tracker/whisper/tmp/run-mwtjrln9/recording.wav \
  -l en -t 4 -otxt -oj -of .obsidian/plugins/mcq-tracker/whisper/tmp/run-mwtjrln9/transcript
```

It exited **0** in **1.85 s**, against the two-minute deadline floor the runner
computed for an 11-second recording, and wrote
`Recordings/Transcripts/jfk.md` with `type: transcript`, `audio:
Recordings/jfk.wav`, `duration: "00:11"`, `language: en`, `transcribed_by:
whisper.cpp`, `model: base.en-q5_1` and `transcribed_on: 2026-11-23`. The body
was `**[00:00]** And so my fellow Americans, ask not what your country can do for
you, ask what you can do for your country.` A second run on a 240-second silent
WAV was cancelled 1.5 s in: the child was killed, no note was written, and the
temporary folder was removed.

**The defect it found.** `decodeRecording` only knew the renderer's
`AudioContext`, so a WAV — the one format whisper.cpp reads — could not be
transcribed anywhere without a renderer decoder, including a headless run.
`src/whisper-wav.js` gains `decodePcm16Wav`, which reads a 16-bit PCM RIFF file
into float channels, and `src/whisper-run.js` tries it before reaching for the
audio context; anything else still takes the existing decode path. A WAV now
needs no decoder at all, and `decodeRecording` is proven both ways in the suite.

**The plan row that was still a promise.** `docs/whisper-plan.md` slice 5 said a
transcript becomes another valid lecture-compiler input, but the compiler read
only `studyToolsSettings().lectureLog.lectures`. `transcriptLectureRow`
(`src/whisper-note.js`) now maps a transcript note to a compiler row — course
from the frontmatter or `Recordings`, title from the recording name, date from
`transcribed_on`, and the spoken text with the heading and `[mm:ss]` markers
removed — and `plugin.transcriptLectureRows()` reads the transcript folder when
the module is on. The **Compile one study note** card merges those rows into the
same deterministic compile, with no new AI path, provider, prompt or output
section. The real `jfk.md` from the run compiled into one lecture section.

**Tests and records.** Three tests are added: the WAV decoder round trip, a WAV
decoded with no audio context, and the transcript-to-compiler bridge (including
the disabled-module case). Tests: **3,190 pass, 0 fail**; `npm run check` clean;
`main.js` rebuilt at 4,394,815 bytes from 390 modules; inventory regenerated
(474 groups, 3,341 exports, 255 commands). No setting key, note format, existing
command, review schedule or network default changed.

**Still the owner's.** A real microphone recording, a live Obsidian window, a
multilingual model and a 45-minute lecture's memory use were not exercised here;
those steps stay in `docs/whisper-smoke-test.md`. This run used real speech, so
transcript accuracy was observable, but the smoke sheet's qualitative judgement
of accents and noise remains the owner's.
