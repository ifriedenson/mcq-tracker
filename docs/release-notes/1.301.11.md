# 1.301.11 — The answer check now runs on section-only keys

## What changed
- **Verification was skipped, not failed.** The blind check in the OpenCode
  agent path only ran when a note already had an `answer` property to compare
  against. A note whose key was written only under `## Answer` silently skipped
  the check and was saved with `verified: false`, `verification: unchecked`.
  It now resolves the key with `findAnswerKey` first, so the check runs and its
  result is written.
- An answer the document itself supplied (`answer_source: pdf`) is still left
  alone: that path is not an AI claim and does not need a second opinion.
- Practice, the import audit and the answer check now all read the key through
  the same function, so they cannot disagree about whether a note is answered.

## Why
The AP World import produced 27 notes with their key only under `## Answer`.
Two consequences followed from one wrong reader: the summary called them
unanswered, and the independent check never ran on them. 1.301.10 fixed the
report; this release fixes the check.

## Verification
- `tests/import-batch-window.test.js`: an agent run that writes a note with the
  key only in the reveal callout now sends `B` to `verifyDraftQuestions`, saves
  `answer: B`, and records `verification: match` / `verified: true`.
- Existing notes need no re-import; a new import will now check them.
- No note format, setting key, review schedule or network default changed.
