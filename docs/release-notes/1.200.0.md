# MCQ Tracker 1.200.0

Complex domain coloring in the Reference Graph.

## What changed

- The Graph tab has an opt-in **complex** checkbox. With it on, the first
  visible expression is evaluated in `z` and drawn as a domain-coloring raster:
  hue is the argument, lightness is the magnitude, and non-finite samples are
  transparent.
- Complex expressions use the same restricted parser as the Calculator:
  `z`, `x`, `y`, `i`, `pi`, `e`, `tau`, arithmetic, powers, roots, logarithms,
  trigonometric and hyperbolic functions, and `abs`, `arg`, `conj`, `re`, `im`.
  Invalid expressions show their message under the row.
- The raster is produced by the pure `src/graph-complex.js` module. The view
  copies it into the existing canvas scene, so the grid, axes, PNG export and
  print sheet still use one painting path.
- Complex mode is saved in Reference settings; older settings load with it off.

## Verification

- `npm test` passes: **1,480 tests, 0 failures**.
- `npm run check` passes: no dynamic code and `main.js` matches `src/`.
- Focused coverage: finite/invalid colors, positive-real hue, deterministic
  pixel buffers, window validation, pixel limits, the Graph tab toggle,
  `putImageData` painting, the complex-image marker in the built graph,
  persistence, and an invalid complex row.

## Licence

No dependency was added and no third-party code was copied. The domain-color
mapping and rasterizer are written locally.

Known limitations: complex mode draws the first visible expression only; the
Graph tab has not had a live Obsidian visual pass.
