# 1.307.1 — Review work that comes back on its own

## Why
Mission item 2: recurrence, narrowly. Not the 🔁 scheduling grammar — a study
task can say "come back tomorrow", "come back on weekdays" or "come back next
week", and completing it schedules the next one. "Water plants" does not belong
here; "review Biochem deck every Monday" does.

## What a task can carry
| Rule | Set from | Next due after completion |
| --- | --- | --- |
| `daily` | repeat button, `every day`, `daily` | next day |
| `weekday` | repeat button, `every weekday`, `weekdays` | next Monday–Friday |
| `weekly` | repeat button, `every week`, `weekly`, `every Monday` | seven days later |

The task list's repeat button cycles off → daily → weekdays → weekly → off, and
a row with a rule carries a `🔁 daily` / `🔁 weekdays` / `🔁 weekly` pill.

## How advancement works
`repeatFollowUp` advances from **the task's own due date**, not from today, and
always lands strictly after today:

- **daily** — one day, so 31 January → 1 February, 2027-02-28 → 2027-03-01,
  2028-02-28 → 2028-02-29, and 2028-02-29 → 2028-03-01.
- **weekday** — the next Monday–Friday; a Friday due date lands on Monday and a
  weekend due date lands on Monday too.
- **weekly** — seven days, keeping the weekday it was set on, so an overdue
  "every Monday" still lands on a Monday (the overdue-weekly pin in
  `tests/study-tasks-plus.test.js` moved from "restart from today" to this).

The due **time** (`HH:MM`) is preserved, along with the course, tags and high
priority. The successor is a normal row in `studyTasks`, so it is written to
data.json, shows up in the task list and the due queue, and the configured
mirror note is refreshed with a Tasks-compatible line:

```
- [ ] Review Biochem 📅 2026-11-23 ⏰ 08:15 🔁 every weekday
```

## One successor, never two
`repeatFollowUp` only answers for a finished row, and `plugin.updateStudyTask`
pairs it with `hasFollowUp`, which refuses to queue a row with the same title,
due date and rule that is already open. Finishing twice, or finishing,
reopening and finishing again, therefore yields exactly one successor.

## Evidence — driven, not asserted
Through the built bundle in a **real Obsidian 1.15.1 window** (Xvfb + CDP, the
plugin installed in a vault), calling the plugin's own `addStudyTask` and
`updateStudyTask`:

| Case | Input due | Successor due | Time |
| --- | --- | --- | --- |
| daily month-end | 2027-01-31 | 2027-02-01 | 18:00 |
| weekday, Friday | 2026-11-20 | 2026-11-23 (Mon) | 08:15 |
| weekly | 2027-01-29 | 2027-02-05 | — |
| weekly, overdue (Saturday) | 2000-01-01 | 2026-11-21 (Sat) | 06:30 |
| daily, leap year | 2028-02-28 | 2028-02-29 | — |
| daily, leap day | 2028-02-29 | 2028-03-01 | — |
| double completion | 2027-03-01 | one open successor, 2027-03-02 | 12:00 |

The same run read the rows back from the vault's `data.json`
(`LiveDaily due=2027-02-01 time=18:00 repeat=daily done=False`, and so on),
confirmed the Task list DOM shows `🔁 weekdays` and the successor, and left the
mirror note on disk with:

```
- [ ] LiveOldWeekly 📅 2026-11-21 ⏰ 06:30 🔁 every week
- [ ] LiveWeekday   📅 2026-11-23 ⏰ 08:15 🔁 every weekday
- [x] LiveWeekday   📅 2026-11-20 ⏰ 08:15 🔁 every weekday
```

`tests/task-recurrence.test.js` repeats all of it in the suite through the same
handlers (12 tests: advancement, leap/month/year rolls, overdue rules, saved
data + reload, double completion, mirror line and refresh, UI cycle).

## Checks
`node --test`: 2,968 pass, 0 fail. `npm run check`: clean. No setting key, note
format, review schedule, network default, the 1.307.0 hub fix or the 1.307.0
time parsing changed.

## Still open
- Recurrence is deliberately three rules; no "every N days", no "second
  Tuesday", no month-based rules.
- There is no "end repeat" control beyond cycling the rule back to off; a
  stopped repeat leaves the finished rows as they are.
