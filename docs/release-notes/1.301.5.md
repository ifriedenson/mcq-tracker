# 1.301.5 — Import failures that explain themselves

## What changed
- **The batch summary keeps the reason.** Every failed file in the
  end-of-batch completion summary now shows its error text under the
  `Could not import` state, and files that produced no notes show the
  skipped reason (e.g. `No questions found`, or the agent note about
  OpenCode file-edit permissions) instead of a bare state with no detail.
- **Empty errors fall back to an actionable message.** `friendlyError`
  and the import's `showError` path no longer surface an empty string or a
  bare `Error`: they name the file/request and the next step (check that
  OpenCode is running with a connected provider, or switch to Direct AI).
- **The agent watchdog tells lost contact apart from idle.** Repeatedly
  unreadable agent status now fails fast with `Lost contact with OpenCode`
  instead of waiting out the full idle period. A genuinely quiet agent
  reports how long it was quiet, what it was last seen doing, and the
  likely fix (allow file edits for the vault in OpenCode permissions),
  with Direct AI as the permission-free alternative.

## Why
A two-PDF OpenCode-agent import reported `0` notes for both files with an
error message that carried no information: the intermediate failure screen
advanced to the next file, and the final summary dropped every per-file
reason. The watchdog's single `stopped responding` message also covered
two different situations (wedged server vs. idle/permission-gated agent).
