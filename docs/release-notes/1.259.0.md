# MCQ Tracker 1.259.0

Released Nov 5, 2026.

## Advanced Tables: CSV/TSV import, transpose, header row and counts

The rendered-table toolbar now has twenty-five actions: the eight row/column structure controls, eight formatting and alignment controls, **↑**/**↓** sorting, **Σ** formulas, **CSV** export, **Paste**/**Replace** import, **T↔** transpose, **H** header toggle and **N×M** size readout.

**Import.** `parseDelimitedTable` reads pasted CSV or TSV: quoted fields keep commas, tabs and line breaks, `""` inside a quoted field is one quote, the delimiter is a tab when the first line contains one and a comma otherwise, CRLF and LF both work, and a trailing newline is ignored. `importTableData` adds the rows below the body (**Paste**) or swaps the body for them (**Replace**). Every cell goes through the existing `escapeCell`, so a quoted `|` stays inside its cell and never starts a column. A table with a blank header and no body rows takes its header and column count from the paste; any other table keeps its header, alignment and width. An empty paste, an unclosed quote, a paste wider than the table, more than 500 rows, more than 40 columns or a cell over 4,000 characters is refused before anything is written.

**Transpose.** `transposeTable` makes the first column the new header and each remaining column one body row. Alignment returns to default because it belonged to the old columns, and transposing twice restores the original table. A table with no body row, or one whose transpose would exceed 40 columns or 500 rows, is refused.

**Header row.** `toggleHeaderRow` moves row 0 between the header and the body: turning it off installs a blank header row and pushes the old header into the first body row, and turning it back on promotes that first body row to the header again. Nothing is deleted, the two states undo each other exactly, and a table with no body row has nothing to promote and is refused.

**Counts.** `tableCounts` returns the row count, body-row count, column count and header state, and the **N×M** button reports them in a notice. It reads the table and never writes the note.

`updateTableCsvImport`, `updateTableTranspose` and `updateTableHeader` all share `updateTableBlock`, so import, transpose and the header toggle use the same live-editor/`vault.modify` queue as every other table action and keep padded columns, alignment, escaped pipes, CRLF and the `TBLFM` comments attached to a table. The clipboard read lives in `plugin.importTableCsv`; the other actions enter through `plugin.updateTableTranspose`, `plugin.updateTableHeader` and `plugin.reportTableCounts`. Every toolbar button commits an in-progress cell edit before the change, and the size readout writes nothing.

Import widens a table only when it has a blank header and no body rows; replacing rows in a populated table keeps its column count and refuses a wider paste rather than silently adding columns. Transposing drops the old alignment because the new columns come from rows. Merged cells remain out of scope: finishing them needs a decision between HTML tables, continuation markers and leaving them excluded, so this release does not touch them.
