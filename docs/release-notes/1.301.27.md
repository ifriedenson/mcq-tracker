# 1.301.27 — A frozen answer check restarts OpenCode and asks again

## What changed
- **A frozen check recovers instead of failing.** `verifyQuestionDraft` now asks
  through a small `ask()` wrapper. If the request fails with a connection or
  server-trouble message, the plugin calls `recoverAiConnection()` — which stops
  and restarts the managed OpenCode server (`ensureOpenCode`) or re-checks the
  server the user runs, then **re-sends the identical question with the same
  model**. One frozen request no longer costs the note its check.
- **Only connection trouble is retried.** `isConnectionFailure()` at module scope
  separates "wrote nothing new", "stopped answering", "Can't reach OpenCode",
  timeouts, socket/network errors and 502/503/504 from a reply that arrived but
  made no sense ("did not return a usable answer letter"), from an unusable key,
  and from the request caps. A nonsense reply is not retried, so a weak model
  cannot make the import loop.
- **Nothing restarts after Stop.** `verifyDraftQuestions(items, { shouldStop, onNotice })`
  passes the stop check down; if the import was stopped or the window closed, the
  original error is kept and no server is started behind the user. Consensus
  votes pass `noRetry` so a panel cannot restart the server once per vote.
- **The checking line says what is happening.** `onNotice` text is appended to the
  ticking status, e.g. `Checking answer 4 of 27: Q04... (6:02) OpenCode stopped
  answering, so it is being restarted, and then this same answer is asked again...`.
  `waitClock` keeps `this.paintWait` so a notice repaints at once instead of on the
  next second.

## Why
The owner asked for a frozen check to reconnect to OpenCode and then come back to
the same question so every question ends up verified, rather than being skipped.

## Verification
- `tests/answer-verification.test.js`: a "wrote nothing new for 6 minutes" failure
  produces the order `ask 1 → stop → start → ask 2`, the note verifies, and the
  notice names the restart; a nonsensical reply is asked once with no restart and
  keeps its `usable answer letter` error; a stopped import performs the ask, then
  neither retries nor restarts.
- `tests/import-batch-window.test.js`: a real two-file batch whose first check
  freezes asks twice, restarts once, shows `OpenCode stopped answering` on the
  checking line, and writes the note `verified: true`.
- No note format, setting, review schedule or network default changed.
