# 1.267.0

## Kairos interaction parity

1.265.0 brought Kairos's document model into **Time blocks**. This release adds
the interactions and files that still made Kairos worth keeping, so a Time
blocks user has no reason to run both plugins. It remains original,
dependency-free JavaScript: no Kairos source, styles or copy was used.

### Direct manipulation

- **Day timeline.** A pointer rail draws a block by dragging empty time, moves a
  block by dragging it, and resizes it from the bottom edge. Mouse and touch
  share one 15-minute snap; the pure geometry is `snapMinutes`,
  `shiftBlockTimes`, `resizeBlockTimes` and `timeRangeFromDrag`.
- **Four-state tasks.** The checkbox is now a status button: click cycles open →
  half-done → done, right-click cancels, and a 550 ms press cancels on touch.
- **Week drops.** Drag a block onto another day column to move it there; drag a
  task onto a day to move it into that day's Unscheduled block.
- **Intensity.** Timeline shows a 14-day strip of planned minutes as levels 0–5.

### Projects, files and migration

- **Project and domain files.** Markdown files under the configured folders carry
  `mcq/project` or `mcq/domain` tags, colour, course and a dated lifecycle
  history with intensity. The user's body is preserved on every write, and
  Kairos's `kairos/project` / `kairos/domain` tags are accepted on import.
- **Status controls.** The Projects view records active, inactive and archived
  states with an optional 0–5 intensity for the selected day.
- **Write-back.** Routines.md and Backlog.md now write as well as import, with
  buttons in their views and three commands.
- **Kairos settings import.** **Time blocks: import Kairos settings** reads
  `.obsidian/plugins/kairos/data.json` and copies the timeline hours, schedule
  heading, folders, file paths and routine/association switches into the local
  settings, so Kairos can be removed after one import.
- **Guided tour.** A seven-step modal walks through the day, block, task, routine,
  backlog and Markdown basics, with **Open Day view** at the end.

### Remaining differences

Fit-days width, grid row lines/shading, follow-grid and highlight-across-views
are cosmetic switches Kairos offers and this planner does not. The tour guides
rather than detecting each gesture. Neither is a reason to keep Kairos.

Tests: **2,148 pass**, `npm run check` clean, `main.js` rebuilt across 304
modules at **5145606 bytes**. Coverage is in `tests/time-blocks-parity.test.js`
beside the existing Time blocks suites. Pointer gestures are not unit-tested
because the DOM harness has no layout; their geometry and every plugin mutation
are.
