# 1.255.0 — A remote go-to keeps its file and destination

Released Nov 4, 2026.

## What changed

- **A remote link is retargeted in place.** `updateLink({ target: "remote", file, to })` writes
  `/A << /S /GoToR /F << /Type /Filespec /F (path) /UF (path) >> /D [page /Fit] >>` onto the same
  annotation, deleting any old `/A` or `/Dest`, so the link still goes to another file instead of
  becoming an address or a page jump. `/D` names the page by its 1-based number in the other
  document — the same form `remotePage` already reads — and the path is carried in a file
  specification's `/F` and `/UF` hex strings.
- **Its destination can be a name in the other file.** `updateLink({ target: "remote", file, name })`
  writes `/D` as a PDF name when the destination is a token (`Chapter4`) and as its text otherwise
  (`Chapter 4`), which is exactly what `destinationName` reads back. `readLinks` reports
  `target: "remote"`, `file` and either `to` or `name`, so a re-read returns what was set.
- **A target alone picks the kind.** `{ file }` still means `launch`; `{ file, to }` and
  `{ file, name }` mean `remote`, so a remote retarget can no longer be mistaken for a launch or fall
  back to a URL. Address, page, launch and named retargets are unchanged.
- **The kind survives every other edit.** A move, a resize, a width change, a border style, a custom
  dash with its phase, a highlight change and any other style edit never touch the action, so a
  remote link stays `/GoToR` with its file and destination. One undo step; only **Save a copy**
  writes.
- **The editor row.** **Change to** gains **Remote**, with **Remote file** and **Remote page or
  name** fields (a number is a page in the other file, anything else a destination name); the status
  reads `now opens notes2.pdf page 5` or `now opens notes2.pdf at Chapter 4`, and the change hint
  says a remote link keeps its kind.
- **Refusals, each with a message and no byte change:** an empty or non-string remote path, one with a
  NUL/control character or over 2,000 characters; no destination at all; a page that is not a whole
  number from 1 to 100,000; a name that is empty, not a string, over 200 characters or contains a
  control character; a page and a name together; an address on a remote link; a page on a launch
  link; and any payload supplied for the wrong kind. Every 1.254.0 launch/named refusal, the
  1.253.0 dash-phase rules, the 1.252.0 border/dash rules and the five deliberate refusals still
  stand, as does the refusal of actions this editor does not model (`/JavaScript`, `/SubmitForm`,
  `/Named` …).

## Verification

- Four new tests were written first and run against 1.254.0: the two engine retarget tests returned
  `ok: false` (`[false, undefined, undefined, undefined, undefined]`) because `target: "remote"` was
  not a known kind, and the window test failed the same way. After the change: engine **90 pass /
  0 fail**, window **25 pass / 0 fail**.
- What they assert: a remote page retarget emits `/S /GoToR` with a file specification whose `/F`
  reads `notes2.pdf` and a `/D` of `[5 /Fit]`, and re-reads as `remote` with that file and page; a
  remote name retarget writes `/D` as the destination's text and re-reads as the name; a remote link
  keeps its file, page, width, dash phase 3 and outline highlight through a new area and a move to
  page 4; every bad path, bad page, bad name, page-plus-name and wrong-kind payload is refused while
  the saved bytes stay identical; the window test drives **Change to Remote** on the built `main.js`,
  retargets the page, restyles it, switches the destination to a name, gets a refusal for an empty
  file, saves a copy and re-reads the remote kind, its file, its name and the style with its phase.
- Full suite **1927 pass**, `npm run check` clean across **297 source files**, `main.js` current
  across **298 modules** at **4,976,540 bytes**, and `git diff --check` clean.

## Limits

- Remote targets are written, not verified: the editor never opens the other file, so it cannot check
  that the path exists or that the page number or destination name is defined there. A wrong guess is
  the author's, and the link simply fails in a viewer.
- The dash phase remains this editor's own `[phase [lengths]]` encoding (1.253.0), and the five
  deliberate refusals (XFA, encrypted files, rewording text, hierarchical field names, guessing
  bookmark views) are unchanged.
