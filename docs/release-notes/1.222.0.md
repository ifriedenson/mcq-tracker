# MCQ Tracker 1.222.0

The Study agent now streams its replies token by token and keeps a real
conversation library inside the panel. Both AI backends are covered: the Direct
API streams through its provider's Server-Sent Events, and OpenCode reads the
server's `/event` stream while its blocking send runs. When a provider or server
does not stream, the same request still finishes with the complete reply and the
user sees no error. No dependency, provider, key or network request was added,
and Obsidian Copilot source was not used.

## Streaming

`src/chat-stream.js` is a small SSE reader shared by every path. It buffers
bytes until a blank line, accepts `data:` payloads split across chunks, ignores
malformed events and `[DONE]`, reads OpenAI-style
`choices[0].delta.content` (string or parts) and Anthropic
`content_block_delta.delta.text`, and stops immediately when its `AbortSignal`
is aborted while keeping the text it already delivered.

- **Direct API:** `ApiClient.streamChat` posts the same request as before with
  `stream: true` and a `text/event-stream` accept header. A JSON response is
  treated as one complete delta, so an endpoint that ignores `stream` still
  works; a runtime without `fetch` uses the existing `requestUrl` path
  unchanged. HTTP errors surface with the provider's message and are not
  retried by the streaming code.
- **OpenCode:** `OpenCodeClient.stream` subscribes to `/event`, keeps events
  whose `properties.sessionID` matches the session, ignores non-text, synthetic
  and ignored parts, and reports `properties.delta` while the normal blocking
  `send` finishes. Streaming there is an optimisation: no event stream, a
  missing `fetch` or an unknown event shape simply produces no deltas, and the
  panel still refreshes the finished messages from the server.

The panel renders the growing reply in its own assistant bubble with a caret.
The completed text replaces it, so citations, **Copy**, **Regenerate**,
**Retry**, **Save chat**, **Insert into active note** and Markdown rendering all
keep working exactly as before.

## Cancelling

**Stop** and **Esc** cancel mid-stream for both backends. The text received so
far is committed once as the assistant turn, with the question that produced it
when the history does not already end with that question. A late reply is
ignored. The next request therefore sends a consistent transcript, and
**Regenerate**/**Retry** replace the partial assistant turn instead of adding a
second user turn. For OpenCode, the panel keeps the partial locally when the
server's transcript does not contain it, merges it after the refresh, and never
duplicates it when the server did persist it.

## Conversation library

The active conversation stays in `settings.ai.studyChat` and gains
`studyChatId`, `studyChatTitle` and `studyChatUpdatedAt`; archived conversations
live in the new bounded `settings.ai.chatSessions`. `src/chat-sessions.js` owns
the pure rules: ids, a title from the first question, one record per id,
newest-first ordering, a 20-conversation cap, rename and remove.

The panel lists the active conversation and the archive newest first, each with
its title and local timestamp. Opening a row moves that record out of the
archive and back into the panel, so its history is exactly the one that
continues; **New chat** archives the current conversation before clearing.
Rename updates the same record (or the active conversation), delete removes it,
and neither creates a saved note, so no duplicate or orphaned entry is left.
Reopening the Study agent restores the same active conversation and list.
**Save chat** still writes a new note and adds a numeric suffix rather than
overwriting an existing one.

## Tests

- `tests/chat-stream.test.js` drives the parser with split chunks, malformed
  events, an abort mid-stream, OpenAI and Anthropic shapes, a fake SSE `fetch`,

  incremental chunks drawn live, Stop and Esc mid-stream with one kept partial
  reply and a late reply ignored, a non-streaming provider, streamed reply then
  regenerate, retry after a mid-stream error, OpenCode streaming with a server
  refresh, and the library (archive, resume with continued history, rename,
  delete, newest-first order, no duplicate notes, restore after reopen and no
  overwrite of a saved chat note).
