# 1.307.28 (Nov 19, 2026)

Two Tier-1 follow-ups from the brainstorm: settings you can lose now have a
safety net, and every AI question-write path is pinned to its blind-check
verdict by one table-driven test.

**Back up plugin settings now** and **Restore plugin settings from a backup**
are new palette commands. The study-bundle export covers question and card
*notes*, but every schedule, preset, goal, task list and AI setting lives in
`data.json`, and nothing backed that file up. Backups are timestamped JSON
copies beside `data.json` (the plugin's own data folder, never the vault, so
anything still in settings is not synced as a note); the newest ten are kept
and older ones pruned. Restoring backs up the current settings first, then
reloads through the normal settings load so every normalization runs again,
and refuses a corrupt file before writing anything. With one backup the
command restores it directly after confirmation; with several it offers a
picker, newest first.

`tests/verification-matrix.test.js` proves, for each of the match / mismatch /
error / review verdicts, that the import finalizer, Quick add, the transcript
question writer and the Quick-add creation path all stamp `verification`,
`verified`, `verified_by`, `verified_on`, `verified_answer` and
`verification_method`, mark `needs_review` and show the warning banner for
anything but a match — and that a hand-written Quick add note stays clean.
Cards are the documented exception: a card has no letter key to check, so card
writes carry no blind-check verdict.

The service-export importers (Evernote, Keep, Notion, Airtable, Bear, Roam)
now load only when an import runs instead of at startup: one fewer eager
module (360 → 359) and about 20 KB back under the startup budget.

Tests: **3,119 pass, 0 fail**; `npm run check` clean. No note format, existing
setting key, review schedule or network default changed.
