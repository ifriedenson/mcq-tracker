# 1.307.6 — The task list lines up

## Why
The task list was the one surface the Primary audits had never measured on its
own. Every earlier "task-list" run landed on a neighbouring Obsidian tab, and
the harness reported whatever was last in the DOM. Pinning the view type showed
why: the plugin opens the list in the **right sidebar**, which the audit
stylesheet hides, so the measured leaf was a zero-width tab that belonged to
Obsidian, not the plugin.

## The harness fix (tools/ui-audit)
- `run.mjs` accepts `viewType`: it targets
  `.workspace-leaf-content[data-type="…"]` (not the tab header, which shares the
  attribute), focuses that leaf, and refuses to report when the measured surface
  is foreign or narrower than 200px.
- `placement: "main"` moves the leaf into the existing main tab group at full
  pane width, so a 1280 measurement really is 1271px of plugin view.
- `expectClass` verifies plugin DOM (`.qt-task-list`) on every state.
- `states` run in order, each with its own screenshot and JSON, and may set
  `focus`, `type` and `press` so a task is added with genuine typed input plus
  Enter, and completed with a real Space on the focused checkbox.
- `checks` records row heights, right-edge alignment, checkbox/title centring,
  meta heights, truncation styles and the live filter — evidence beyond a
  screenshot.
- The touch metric measures a control's wrapping `label` as its hit area.

## What the pass found and fixed
1. **Rows broke into three lines.** `.qt-task-list-star` and
   `.qt-task-list-repeat` had no styles at all, so the row's
   `grid-template-columns: auto minmax(0,1fr) auto` pushed star, repeat and
   delete into implicit rows; repeat and delete stretched into full-width bars.
   The three controls now live in one `.qt-task-list-actions` column, 32px each
   with hover and focus states. Rows fell from 153/189px to 101/119px.
2. **The Add button stretched under the date field** as a fourth child of a
   three-column form; it now spans the form (`grid-column: 1 / -1`) and the form
   stacks to one column under 520px.
3. **A 16px checkbox** was the only target for completing a task. The box stays
   18px inside a 32px `.qt-task-check-wrap` label, so the hit area is 32px and
   the label carries the hover.
4. **Completed rows dimmed to 62% opacity**, taking the title to 4.21:1. The
   strikethrough (in faint ink) and normal title ink carry the state instead.
5. **Primary dark** measured 4.06:1 for the badge, count, tip, empty copy and
   every row pill, and **1.72:1** for the overdue pill. Those classes now borrow
   `--text-normal` in dark, and the overdue pill mixes its red with that ink.

## Evidence — Obsidian 1.15.1, 1.307.6 bundle, Primary, 1280×900
Eight states per theme, each confirmed as plugin DOM at 1271px wide:

| state | light | dark |
| --- | --- | --- |
| empty | 0 overflow / 0 contrast / 0 small targets | same |
| keyboard add (typed + Enter) | same | same |
| long text (190 chars, 2 tags) | same, title wraps | same |
| checked (real click) | same, 1 done row | same |
| filtered (#bio) | same, 1 of 2 rows | same |
| filter cleared | same, 2 rows | same |
| keyboard complete (Space) | same, 2 done rows | same |
| mixed (overdue/today/high/dated/repeat) | same, 5 rows, equal heights | same |

- Row heights consistent within a state (101px one-line, 119px two-line), all
  right edges aligned, 16 focus stops per state with a visible 2px ring on every
  plugin control, and the vertical 129px in the mixed state is the list's own
  scroll region, not clipping.
