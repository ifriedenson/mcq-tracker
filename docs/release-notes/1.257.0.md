# 1.257.0 — The whole repo is inventoried against its own claims

Released Nov 5, 2026.

The previous pass proved the PDF editor against its record. This one covers the rest of the
codebase: every plan item, README claim, settings heading, command, ribbon action and docs page
was traced to the function that implements it and the test that proves it, and a repo-wide
security inventory was recorded and enforced.

## What the audit found

- **No missing implementation.** Every capability `plan.md`, `README.md` and the docs claim is
  present in the bundle. The rows `plan.md` marks as gated stay gated (providers, OAuth, OCR,
  real-device checks, Code Runner, community-directory relisting) and none was invented here.
- **One stale user-facing count, fixed.** `README.md` said the Study Workspace holds **twenty**
  independent modules; the view registers **twenty-one** tabs (`feynman`, `recall`, `planner`,
  `flow`, `subjects`, `courses`, `tasks`, `timeBlocks`, `annotations`, `deepNotes`, `retention`,
  `vocabulary`, `readingLibrary`, `citations`, `quizIndex`, `health`, `lectures`, `readAloud`,
  `bookmarks`, `feynmanAi`, `pdfAnnotations`). The heading and the intro sentence now say
  twenty-one.
- **A blind spot in the existing lint, recorded.** `check-no-dynamic-code.js` masks comments and
  strings before matching, and its tokenizer loses part of `plugin.js` (its `requestUrl` lines are
  blanked as though they were string text). The lint therefore cannot see those lines. The new
  inventory test counts network, write and Node-built-in sinks on comment-stripped raw source
  instead, so the sink list does not depend on the masker. The lint's blind spot is named in
  `docs/security-inventory.md` rather than claimed away.

## Security review (repo-wide)

**No high-confidence vulnerability.** The inventory records, and the test now enforces:

- **Network:** exactly four files call a transport — `api-client.js`, `opencode-client.js`,
  `opencode-manager.js`, `plugin.js`. Provider and local-server bases go through `safeApiBase`
  (HTTPS, or HTTP only on loopback, no URL userinfo); both `plugin.js` requests are calendar feeds
  sanitised by `safeCalendarFeedUrl`; the installer only asks GitHub for its own repository.
  `couchdb-sync.js` takes an injected transport and sends only scheduling fields.
- **Credentials:** API keys and the CouchDB password live in Secret Storage when available, are
  sent only in headers, and are never logged or interpolated into a message. OpenCode starts with a
  fresh 16-byte random password and binds to `127.0.0.1`.
- **Dynamic code:** 0 violations across 297 files; the expression evaluators are hand-written
  parsers, not `eval`.
- **HTML:** exactly six `.innerHTML` assignments. Two pass through `safeSvg`, which drops
  `<script`, `<foreignObject`, `<iframe`, `<object`, `<embed`, `on*=` handlers, `javascript:` and
  `data:text/html`; four take `src/stem-diagrams.js` output, every value of which passes
  `escapeHtml`. The test renders hostile input through all three diagram renderers and asserts no
  markup survives.
- **Filesystem:** thirteen files write to the vault. PDF saves go through `editedPathFor` +
  `vault.createBinary`, which sanitises the base name and never overwrites; note writes go through
  Obsidian's serialised `process`/`processFrontMatter`. Node's `fs` and `child_process` are
  reachable only from the desktop OpenCode installer, through lazy `nodeReq(...)` lookups.
- **Residual risk:** pdf-lib, the zip reader and the SQLite `.apkg` reader parse untrusted files
  in-process; an AI provider receives the content the user sends it by design; the OpenCode child
  process runs with the vault as its working directory; the optional Web browser frames third-party
  pages without filtering them.

  and docs for credential shapes, and pin the write and Node-built-in allow-lists.
