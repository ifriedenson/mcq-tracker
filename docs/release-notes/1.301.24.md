# 1.301.24 — Every settings error shows the fix

1.301.23 added **Open settings** to the missing-key card by matching the word
"settings" in the error text. That left real configuration failures without the
control: an `http://` remote base URL, a provider 404 for an unknown model, a
400 that rejects the model or limits, and the OpenCode 401/404 paths that do not
always spell out "settings". A live 401 also showed the rejected-key sentence
twice.

This patch makes the error's own kind decide the card, not a wording guess.

## What changed

- `src/api-client.js` now marks settings failures as they are thrown:
  `missing-key`, `missing-base`, `missing-model`, `provider-auth`,
  `provider-model`, and `ai-config` for an unsafe or unparseable base URL. The
  marker is the `aiConfig: true` flag plus the specific `code`.
- Missing values, network failures whose fix is the base URL, 401/403
  rejections, 404 model/endpoint failures, and 400/422 model or limit failures
  all carry that kind. A 404 now says to check the model name and base URL in
  settings instead of showing a bare `HTTP 404`.
- `src/opencode-client.js` marks 401 and 404/405 version-mismatch errors;
  `ChatPanel.checkProvider()` marks the no-provider error. The OpenCode reply
  that says a provider is connected remains covered by the message fallback.
- `ChatPanel` stores the kind with the error (`setError`) and renders from
  `errorConfig` first, with `errorNeedsSettings()` kept only for legacy or
  foreign messages. **Retry** and the header gear are untouched; **Open
  settings** still calls `openSettings("mcq-ai")`.
- `friendlyApiError()` is idempotent, so an already-friendly 401, 429 or
  unreachable-provider sentence is not prefixed a second time.

Code: `src/api-client.js` (`configError`, `providerHttpError`,
`requestFailure`, `cfg`), `src/opencode-client.js` (`req`),
`src/chat-panel.js` (`isConfigError`, `setError`/`clearError`, error card).

## Covered messages

The card now draws both controls for:

- `Add your API key in the plugin settings.`
- `Add a base URL in the plugin settings.`
- `Add a model name in the plugin settings.`
- `OpenCode has no AI provider connected yet. Open Settings > Study agent > AI
  and the assistant, choose a provider and paste an API key.`
- `OpenCode rejected the username or password. Check the plugin settings.`
- the provider 401/403 message: `The provider rejected the API key, or the key
  can't use this model.`
- the provider 404 message: `The provider did not find that model or endpoint.
  Check the model name and base URL in settings.`
- the 400/422 model-or-limit message: `The provider rejected the request. Check
  the model name and request limits in settings.`
- `Enter a valid http:// or https:// address.`
- `Do not put a username or password in the address; use the separate fields.`
- `Remote API and OpenCode addresses must use https://. Plain http:// is allowed
  only for localhost, 127.0.0.1 or ::1.`
- the OpenCode reply: `Check that OpenCode is running and a provider is
  connected, then try again.`

Transient empty replies, timeouts, no-response errors and rate-limit messages
keep **Retry** only. The AI-off panel and the 1.301.22 401/unreachable/cancel
copy are unchanged.

## Verified live

Obsidian 1.15.1 was relaunched headless against the disposable vault with the
CDP port and notice observers on the practice/popout and Settings windows. The
vault reported manifest **1.301.24**, and the copied `main.js` matched the
freshly built file's SHA-256 at verification time.

- Seeded `Questions/Unit A/UNIT-A-Q01.md`, started **Quick Practice**, answered
  a question with **Probably Right**, submitted, opened **Ask AI**, and clicked a
  suggested action.
- The provider at `127.0.0.1:4572/v1` returned HTTP 401 on the first request
  (`Incorrect API key provided: sk-live-test.`), so this was not the empty-key
  path. The card read **That reply did not finish**, showed one rejected-key
  sentence followed by the HTTP reason, and drew **Retry** and **Open
  settings**. No notice or console error fired.
- **Open settings** opened the real Settings window on **AI and the assistant**
  (`STUDY AGENT · AI AND THE ASSISTANT`, **AI backend**, **Enable AI features**).
- The provider returned a normal reply on the next request; **Retry** cleared
  the error and rendered the reply with **Bookmark**, **Copy**, **Add to My
  Notes** and **Regenerate**. No spinner was left and no notice or console error
  was recorded.
- The first live pass showed the 401 sentence twice. That was fixed in
  `friendlyApiError()`, the bundle was rebuilt and recopied, Obsidian was
  relaunched, and the same click sequence showed one sentence and the same
  working controls.

## Tests

`tests/chat-panel-copilot.test.js` pins all twelve covered messages in one
table, asserting **Retry**, **Open settings**, Retry wiring and
`openSettings("mcq-ai")` for each, plus an OpenCode "provider is connected"
fallback and a kind-over-wording case. `tests/api-client.test.js` asserts that
real missing-key/base/model, provider 401, provider 404 and unsafe-base errors
carry `aiConfig` and their specific code, and that friendly copy is not
double-prefixed.

**2,797 pass, 0 fail**; `npm run check` clean across **361 source files**;
`main.js` **7,283,480 bytes** from **364 modules**. No note format, setting
key, review schedule or network default changed.
