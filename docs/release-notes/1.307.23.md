# 1.307.23 — Updates no longer report a disable failure

Released November 19, 2026. Obsidian 1.15.1.

## Why

Every update of MCQ Tracker showed a "failed to disable" notice. That
message is Obsidian reporting that the plugin's unload routine threw while
it was disabling the old version to install the new one.

## Cause

Three spots in the teardown path assumed a window was still present:

- `plugin.onunload()` (`src/plugin.js`) called
  `activeWindow.clearTimeout(...)` with no guard. Every other call site in
  the plugin guards `typeof activeWindow !== 'undefined'` first; the
  unload path did not. When the window helpers are already gone during an
  update, that line throws a `ReferenceError`, and Obsidian surfaces it as
  the disable failure.
- The same routine called `this.manager.stop()` and
  `practiceFullscreen.setPracticeFullscreen(...)` unguarded, and called
  `pdfPlus.stop(this).catch(...)` in a way that still throws if `stop`
  fails before returning a promise.
- The same bare-window pattern existed in `schedulePlainCardRefresh`
  (`src/plugin.js`), `InsightsView.onClose`/`later`
  (`src/insights-view.js`), and the OpenCode command runner
  (`src/opencode-manager.js`).

The test harness stubs `activeWindow`, so the suite never caught it.

## Fix

- `onunload()` is wrapped so it can never throw: each teardown step
  (modal close, import session, plain-card timer, fullscreen class,
  managed-server stop, embedded-PDF stop) is individually guarded, and the
  whole body sits in a `try/catch`.
- Timer access goes through `safeTimerWindow()`/`safeClearTimer()`/
  `safeSetTimer()` helpers that fall back to the global timers when no
  window is present. The Insights view and the OpenCode runner got the
  same fallback.
- New `tests/plugin-unload.test.js` pins it: unloading with no
  `activeWindow` and a throwing `manager.stop()` does not throw, and
  scheduling a plain-card refresh with no window still works.
