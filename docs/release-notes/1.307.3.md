# 1.307.3 — Urgent first, typed dates understood

## Why
Mission items 4 and 3 were the two "cheap, do it when you touch that code"
entries. Both turned out to be mostly built already: priority has been a field
with high-first sorting and a `⏫` mirror marker since 1.305, and quick-add has
parsed `at 3pm` and `in N days` since 1.304/1.307.0. So this release closes the
one real gap — a task could not be *created* high priority — and pins the edges
the parser is sensitive to, instead of adding a second mechanism.

## What was already there (proved, not rebuilt)
- `priorityValue`: `"high"` or normal (`""`); no other values, no new setting
  key. `createStudyTask` defaults to normal.
- `compareStudyTasks`: high before normal, then due date, then oldest — and the
  task list and mirror both order by it.
- The per-row ★ toggle in the task list, and `⏫` in the mirror only for high.
- `parseTaskDate` (`in N days/weeks`, weekday, month-day, ISO, today/tomorrow),
  `parseTaskTime` (`at 3pm`, `3:30pm`, `15:00`, `at 9`, `noon`, `in 2 hours`),
  and `extractTaskWhen` with spans winning over clock words.

## What changed
**`src/task-list-view.js`** — the add row carries a `★ High` button:

```js
const priority = addRow.createEl("button", {
  text: "☆ High",
  cls: "qt-task-list-add-priority",
  attr: { "aria-label": "Make the next task high priority", "aria-pressed": "false", … },
});
```

Press it and the next task goes through the normal add path with
`priority: "high"`; leave it alone and the task is normal. It is off in every
fresh render, so "normal by default" still holds, and the per-row star still
flips the flag afterwards. `styles.css` gets two small rules (pressed state
uses the accent colour). The hint line now mentions it.

No parser rule was added: quick-add already resolved the forms in the mission,
so the work there was proving them at the edges.

## Evidence — Obsidian 1.15.1, real task list, built bundle
Driven over CDP in a real vault (today 2026-11-15), all four tasks added through
the task list's own add row (the new toggle and the real `Add` button):

| Added as | data.json | Rendered row |
| --- | --- | --- |
| `Review Biochem` with ★ High pressed (`aria-pressed="true"`) | `priority: "high"` | first, `★ High` star |
| `drill at 3pm` | `time: "15:00"`, `due: "2026-11-15"` | `drill` · Due today · 3 PM |
| `essay in 16 days` | `due: "2026-12-01"` (month boundary) | `essay` · Due 2026-12-01 |
| `Read chapter` | `priority: ""`, no date | last |

Rendered order was exactly `Review Biochem` → `drill` → `essay` → `Read chapter`:
the high task above all normals, and the normals in due order (today, 1 Dec,
undated) with no reshuffling.

The mirror note read back from disk:

```
- [ ] Review Biochem ⏫
- [ ] drill 📅 2026-11-15 ⏰ 15:00
- [ ] essay 📅 2026-12-01
- [ ] Read chapter
```

One line per item, exactly one `⏫` (the high task), byte-identical after a second
refresh, zero duplicates, footer `4 open · 0 done · 16 due`. `data.json` was
unchanged by the mirror write and only moved through the normal save path when a
task was added.

## Boundary pins added (`tests/task-priority-quickadd.test.js`, 6 tests)
- `in 3 days` from 2026-11-30 → **2026-12-03** (month end)
- `in 2 days` from 2026-12-30 → **2027-01-01** (year end)
- `in 1 day` from 2028-02-28 → **2028-02-29**, from 2028-02-29 → **2028-03-01**
- `in 1 week` from 2028-02-22 → **2028-02-29**
- `in 2 weeks` from 2026-12-21 → **2027-01-04**
- `review in 3 days at 3pm` → due 2026-12-02, 15:00; `3:30pm tomorrow` → 15:30;
  `at 9am tomorrow` → 09:00; `at noon Friday` → 12:00
- unchanged: `essay tomorrow`, `drill Tuesday`, and a normal `studyTaskLine`
  with no `⏫`
- order: two high tasks sort by due date, every high beats every normal, and
  the normals keep their due order (rendered list and `compareStudyTasks`
  agree)

## Still open
- One priority level only (high/normal) — no medium, no sort-by-priority
  setting, no start/scheduled dates or dependencies.
- The add-row toggle is per render: it always starts normal, deliberately, so
  the default cannot leak between tasks.
- "in N days"/"in N hours" are whole-number spans; "in 1.5 hours" and "next
  Thursday at 4" beyond the existing weekday forms are not parsed.
