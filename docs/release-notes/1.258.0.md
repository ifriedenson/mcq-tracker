# 1.258.0 — deep links, FSRS training, LaTeX pipeline, Markmind maps

Four gaps recorded in `docs/installed-plugin-parity.md` and `src/fsrs-fit.js` are closed by
new dependency-free engines. No provider, key, network request or bundled model was added.

## PDF rectangle and selection deep links

`src/pdf-deep-link.js` adds the part of a PDF++-style link that was missing: the area.

- `formatPdfDeepLink(path, page, { annotation, rect })` writes
  `[[file.pdf#page=3&annotation=ann-1&rect=0.12,0.34,0.4,0.08]]`.
- `parsePdfDeepLink(link)` reads a page, annotation and rectangle back, and reports
  `valid: false` for a non-PDF path, a page outside 1–100,000, or a link with no page.
- `unionRect(areas)` turns a multi-line selection into one ring.
- `normalizeRect` refuses a rectangle with a non-positive side or one that leaves the page.

`annotationLink` in `src/pdf-annotations.js` now delegates to `formatPdfDeepLink`, so every
annotation link the index and digest write carries the selection it was made over, and a
link without an area still writes exactly the old `#page=N` form.

## Multi-weight FSRS training

`src/fsrs-train.js` implements the 19-weight FSRS-5 memory model (stability, difficulty,
recall probability) and fits those weights to the vault's own review history:

- `retrievability(stability, elapsed)` — the forgetting curve.
- `initialStability` / `initialDifficulty` / `nextStability` / `nextDifficulty` — one state
  transition per review, with lapse, hard and easy paths.
- `loss(reviews, weights)` — mean binary cross-entropy over every predicted recall, plus a
  light pull toward the shipped defaults so a short history cannot wander.
- `trainWeights(reviews, { iterations })` — central-difference gradient with a bounded step
  that halves when a step does not lower the loss. Deterministic, and it refuses fewer than
  30 reviews instead of fitting noise.
- Every weight is clamped positive, so a bad history cannot produce a negative interval.

This is the training that `src/fsrs-fit.js` records as deliberately absent; the per-deck
retention fit is unchanged.

## Handwriting → LaTeX pipeline

`src/pdf-latex.js` owns the deterministic half of a handwriting conversion, with no OCR
engine bundled:

- `LATEX_SYSTEM` and `latexPrompt(page)` ask for Markdown with `$…$`/`$$…$$` maths, forbid
  solving or correcting the work, and treat the page as data.
- `extractLatexMarkdown(reply)` removes fences and preambles, and returns `""` for an empty
  reply.
- `latexNotePath(pdfPath)` produces `name (LaTeX).md` with characters a note name cannot
  hold removed.
- `buildLatexNote(pages, meta)` writes one note with `latex: true`, the source PDF, model
  and date, and a check-the-equations warning. It throws rather than writing an empty note.

## Markmind-compatible mind maps

`src/mindmap.js` reads and writes Markmind's real file shape — frontmatter
`mindmap-plugin: basic` plus a nested Markdown list — so a board stays editable outside the
plugin:

- `isMarkmind`, `parseMarkmind`, `markmindMarkdown` round-trip a tree through that file.
- `addChild`, `renameNode`, `removeNode`, `moveNode` edit a copy and refuse an empty label,
  an unknown node, a missing parent, removing or moving the central node, and a move into
  the node's own subtree.
- `flattenMindmap` lists depth and text for rendering or export.

## What is not wired yet

The engines are reachable through the bundle and tested, but only the deep-link rectangle is
on a user path today (annotation links and the Markdown digest). Commands and reader
controls for training, conversion and the Markmind editor are the next slice; nothing in
this release pretends otherwise.
