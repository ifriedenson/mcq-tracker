# 1.301.12 — A disagreement is checked again before it is believed

## What changed
- **Escalation on disagreement.** The blind check already solved each
  AI-written multiple-choice question independently and compared the result
  with the stored key. When those two disagreed, the note was flagged at once.
  Now that disagreement earns up to two more independent blind checks, and the
  stored answer is verified only with a real majority (at least two of the
  three agreeing with it).
- **A named answer, not a shrug.** If the panel settles on one other answer,
  the warning says how many checks ran and which answer most passes chose
  (previously "a different answer"). If the checks split with no majority, the
  first verdict stands and the note stays flagged.
- **No extra cost on a clean match.** Extra requests run only for answers that
  already disagree, each under the existing per-check time limit.
- **A switch.** Settings → AI → Session pacing and checks → **Ask two more
  checks when they disagree** (on by default). Turning it off restores the
  immediate flag.

The extra checks use the model chosen for the **Check AI-written answers**
feature. Setting that model to something other than the import/generation model
is what makes the check independent of the model that wrote the answer.

## Why
The owner described this flow and asked for it: one AI writes, a second answers
blindly, a match is verified, and a disagreement is looked over by more AIs
before anything is called wrong. The first two steps already existed; the
escalation did not.

## Verification
- `tests/answer-verification.test.js`: a pure verdict test (2 of 3 for the key
  verifies; 3 of 3 for another answer flags it and names it; a 3-way split keeps
  the first verdict; a failed extra check is not a vote), a plugin run where the
  first check disagrees and both extras side with the key (three requests,
  `status: match`, `method: consensus`), and a run with the panel off (one
  request, still a mismatch).
- `tests/ai-tools.test.js` now expects three verifier calls when the only reply
  disagrees with the stored key.
- No note format, setting key, review schedule or network default changed.
