# 1.307.2 — The whole study loop in one note

## Why
1.305 opened one direction: study tasks mirror into a note as Tasks-compatible
lines. But the study loop has two halves, and only one of them was visible in
notes. Exam-plan tasks are ordinary rows so they appeared on the next refresh —
but today's questions, cards and vocabulary never did, and nothing refreshed the
note when the plan, the list or the queue changed.

## What the mirror writes now

```
# Study tasks

_One-way mirror from MCQ Tracker — edits here are overwritten._

- [ ] Review Biochem 📅 2026-11-20 ⏰ 08:15 ⏫ 🔁 every weekday
- [ ] Study Enzymes (pass 1) 📅 2026-11-16 · Biology
- [ ] Study Membranes (pass 1) 📅 2026-11-24 · Biology
- [ ] Study Enzymes (pass 2) 📅 2026-12-03 · Biology
- [ ] Study Membranes (pass 2) 📅 2026-12-11 · Biology

## Due today
- [ ] [[Questions/Mirror/enzymes-due.md|mirror-enzymes]] 📅 2026-11-10 · Question · Biology
- [ ] [[Cards/Mirror/cell.md|cell]] 📅 2026-11-12 · Flashcard · Biology
- [ ] [[Questions/Mirror/enzymes-new.md|mirror-new]] 📅 2026-11-15 · Question · Biology

_Mirrored 2026-11-15 · 5 open · 0 done · 17 due._
```

- **Task lines are unchanged** from 1.305/1.307: `- [ ]` / `- [x]`, title,
  `📅` when a due date exists, `⏰ HH:MM` when it has a time, `⏫` for high
  priority, `🔁` for a repeat rule, `#tags`, and the course after `·`.
- **Due lines** are `- [ ] [[path|title]] 📅 YYYY-MM-DD · Question · Biology`.
  The wikilink is what buys backlinks, search and the graph; the date is the
  item's own `next_review`, or today for an item that has never been reviewed
  (it is in today's queue either way). Nothing invents an `⏰`, `⏫` or `🔁` the
  item does not carry, and the queue's own meta is de-duplicated, so a flashcard
  in the Biology deck of the Biology course reads once.
- `mirrorMarkdown(tasks, today, { dueItems })` keeps the shipped format when no
  `dueItems` are passed, which is pinned by test.

## One writer, rebuilt every time
`syncStudyTasksToNote()` regenerates the whole note from current data; it never
appends. Three consecutive refreshes of the same data produced a byte-identical
file with **0** duplicate checklist lines in the live run.

Refreshes now happen on every relevant change, all through the existing
`refreshTaskMirror()` (a no-op without a mirror note, so no note is ever created
unasked):

| Change | Path |
| --- | --- |
| task added | `addStudyTask` |
| task edited / completed / reopened | `updateStudyTask` |
| repeat successor | `updateStudyTask` + `repeatFollowUp` |
| task deleted | `removeStudyTask` |
| exam plan generated | `generateStudyTasks` |
| a review recorded (question, card, vocabulary) | `recordAttempt` |

`recordAttempt` writes the note once immediately and once 1.2 s later: Obsidian's
metadata cache settles a moment after `processFrontMatter`, so the immediate pass
can still see the old `next_review`. The live run caught exactly that — the first
version left the reviewed question in the note — and the settle pass fixed it.

## Projection only
The writer never touches `settings.studyTasks`; only the normal save path does.
In the live run, three refreshes left the serialized task data byte-identical, a
hand-ticked due line and a hand-written line disappeared on the next refresh
(restoring `- [ ]`), and no `- [x] [[` line was ever created from data.

## Evidence — Obsidian 1.15.1, built bundle, own handlers
Driven over CDP in a real vault, with the mirror note read back from disk:

1. `generateStudyTasks({ course: "Biology", examDate: "2026-12-20", startDate:
   "2026-11-16", topics: "Enzymes\nMembranes", passes: 2 })` → four
   `Study … (pass N)` lines with `📅` dates and `· Biology`.
2. `addStudyTask({ title: "Review Biochem", due: "2026-11-20", time: "08:15",
   priority: "high", repeat: "weekday" })` → `- [ ] Review Biochem 📅 2026-11-20
   ⏰ 08:15 ⏫ 🔁 every weekday`.
3. Due queue projected: overdue question (`📅 2026-11-10`), due card
   (`📅 2026-11-12`), never-reviewed question (`📅 2026-11-15`), all linked.
4. Footer `_Mirrored 2026-11-15 · 5 open · 0 done · 17 due._`; three refreshes
   identical, `duplicateLines: 0`, `dataUnchanged: true`, `handEditRestored:
   true`.
5. `recordAttempt(question, { correct: true, grade: 3 })` → the question left the
   due section, 17 → 16, footer followed.
6. `updateStudyTask(id, { done: true })` → `- [x] Review Biochem 📅 2026-11-20
   ⏰ 08:15 ⏫ 🔁 every weekday` under `## Done`, and its weekday successor
   `- [ ] Review Biochem 📅 2026-11-23 ⏰ 08:15 ⏫ 🔁 every weekday`.

The date boundary cases the projection is sensitive to are the item's own
`next_review` copied verbatim plus the task due dates already shipped in 1.307.1
(month-end, leap day, year-end), covered by `tests/task-recurrence.test.js` and
`tests/task-times.test.js`; the projection adds no date arithmetic of its own, so
leap-day and month-end strings pass through untouched (asserted for
`2026-11-10`/`2026-11-12` and by the unchanged `studyTaskLine` pins).

## Still open
- One direction only, as decided: ticking a mirrored line changes nothing.
- The due section lists the current queue (respecting the daily cap); there is
  no separate "include due work" switch, and no second mirror note.
- A due line's title links to the note; there is no per-item back-link back into
  the plugin, and finished questions are not kept in a "done" list.
