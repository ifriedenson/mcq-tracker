# 1.307.15 — The sidebar, for all three

Released November 16, 2026. Obsidian 1.15.1.

## Why

The task list and the Study agent opened in the right sidebar, but the calendar still opened the Plan hub
as a main tab. The three things a student keeps beside a note therefore lived in two different places, and
opening the calendar pulled focus away from the note.

## What changed

- **One sidebar path.** `plugin.activateSidebarView(type)` reuses a leaf only when it is already inside
  `.mod-right-split`; otherwise it takes the right sidebar (`getRightLeaf(false)`, then `true`). Phones,
  which have no usable right split, keep a normal tab.
- **Calendar joins it.** `activateCalendar` no longer routes through `activateHubTab("plan", …)`. The
  ribbon's **Open Plan** and the `open-plan-hub` command call `activatePlanHub`, which now opens the
  merged calendar through the same sidebar path.
- **Deep links follow.** Focus day, Review calendar and Local events already routed through
  `openMergedCalendar`; that now targets the sidebar calendar too, so every calendar command lands beside
  the note instead of in the editor area.
- **Existing leaves still work.** The Plan hub view remains registered for leaves a user already has open
  and for embeds. Reopening any of the three views focuses the right-sidebar leaf instead of creating a
  second copy.

## Evidence

- `tests/hub-views.test.js` drives the right-sidebar route for Focus day and **Open Plan**, asserts the
  calendar view type and day mode, and asserts the second open reuses the same leaf.
- `tests/task-list.test.js` keeps the task list's right-sidebar assertion.
- `node --test`: **3,006 pass, 0 fail**. `npm run check`: clean.

No note format, setting key, review schedule or network default changed.
