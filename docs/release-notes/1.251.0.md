# 1.251.0 — Read and retarget a link's file or destination

Released Nov 4, 2026.

## What changed

- **Every link action is readable.** `readLinks` no longer reports an empty address for a link that
  does something other than open a URL. Each row keeps its page, area and style and now carries
  `target` as the kind of action — `url`, `page`, `launch`, `remote`, `named`, `other` or `none` —
  plus `file` and `name`: the file a `/Launch` or `/GoToR` action names and the destination name a
  named destination or `/GoTo /D (name)` points at. A remote go-to also reports the page it names in
  the other file as `to`.
- **And those links can be retargeted in place.** `updateLink` converts a launch, a remote go-to or a
  named destination to an `http(s)` address or an in-file page jump on the same annotation: the old
  `/A` action or `/Dest` entry is deleted and the new one written, while the page, `/Rect`, border,
  flags and annotation identity stay exactly as they were. The result reports `fromKind` so the caller
  can say what the link used to do.
- **The editor row.** **Add content → Links** gains a read-only hint beside **Change link** that names
  what the selected link opens — for example `Link 1 is a launch action for chapter1.pdf; a change
  replaces it with the address or jump you choose.` The summary line describes the same kinds
  (`p1 → launch chapter1.pdf`, `p2 → remote notes.pdf page 3`, `p3 → destination Chapter 3`,
  `p4 → /JavaScript action`), and a successful change words the status as
  `now opens https://… instead of a launch action`. One undo step, and only **Save a copy** writes.
- **Refusals, each with a message and no change:** a link that runs an action this editor does not
  rewrite (`/JavaScript`, `/SubmitForm`, `/Named` and any other action name) is refused for
  retargeting with `This link runs a /JavaScript action this editor does not rewrite; remove it and
  add a new link instead.` and its action, script text, rectangle and destination are left alone —
  moving its box, restyling it or removing it still works. An empty address, every scheme other than
  `http`/`https`, an over-long address, a page outside the file, no links and a link number outside
  the list keep the refusals they already had.

## Verification

- Four new tests were written first and run against 1.250.0. Engine: `# tests 3 / # pass 0 /
  # fail 3`, every row reporting `+ 'page'` and `+ undefined` where `- 'launch'`, `- 'chapter1.pdf'`,
  `- 'notes.pdf'`, `- 'Chapter 3'` were expected. Window: `# tests 1 / # pass 0 / # fail 1`
  (`+ 'page', + 'page'` against `- 'launch', - 'other'`). After the change: engine **76 pass /
  0 fail**, window **1 pass / 0 fail**.
- What they assert: a `/Launch` link reads `launch` + its file (from a string and from a
  `/Filespec` dictionary), a `/GoToR` link reads `remote` + its file + its remote page, a
  `/GoTo /D (name)` and a direct `/Dest (name)` both read `named` + the destination name; converting
  those three to an address or a page jump keeps one annotation each, the same rectangle and style,
  and the saved file reads back as `url`/`page` with the file and name gone; and a `/JavaScript` link
  is refused with `reason: "kind"` for both an address and a page jump, keeps its `/S` and `/JS`, gets
  no `/Dest`, and still accepts a box move.
- The window test drives the real built `main.js`: it opens a PDF carrying a launch link and a script
  link, checks the summary and the new **Change link** hint, presses **Change link** to convert link
  1 to `https://example.com/converted`, checks the status wording, the single annotation and the
  `change a link` undo step, undoes and redoes it, presses **Change link** on the script link and
  gets the refusal with that link unchanged, then saves a copy and reopens it with the converted link
  and the untouched script.
- Full suite **1909 pass**, `npm run check` clean across **297 source files**, `main.js` current
  across **298 modules** at **4,960,953 bytes**, and `git diff --check` clean.

## Limits

- A launch, a remote go-to or a named destination is **converted**, never rewritten in place: the file
  specification or destination name itself is not edited, and a remote go-to is not followed.
- Actions this editor does not model are preserved and refused rather than decoded, so their effect
  is not shown.
- Unknown `/BS` border styles (`/B`, `/I`, `/U`) and a `custom` dash pattern remain as 1.250.0 left
  them: preserved, with only solid and dashed editable.
