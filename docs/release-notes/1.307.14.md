# 1.307.14 — One calendar

Released November 16, 2026. Obsidian 1.15.1.

## Why

The Plan hub had four calendars for one question: what is on today, and what is coming? The Calendar tab
drew `.ics` classes and exams. Focus day drew the current day's plan. Review calendar drew the queue due on
each day. Local events drew the plugin's own events. Checking a Tuesday meant four tabs, and nothing showed
how a study block, a review backlog and a class shared the same afternoon.

## What changed

- **The Calendar tab is the merged calendar.** One grid and one day section now carry every planning store:
  classes and exams from the `.ics` feeds, planned study blocks (Time blocks/Kairos), local events,
  review-due questions and cards, and study tasks with due dates. `src/calendar-merge.js` reads those
  stores once per render and groups rows by day; it skips completed tasks and layers whose module is off.
- **Layers are visible and remembered.** Five chips — Classes, Planned, Events, Review, Tasks — sit above
  the calendar, expose `aria-pressed`, and write `settings.calendar.layers`. `mergeCalendarSettings`
  normalizes the key with every layer on by default, so existing vaults see everything after updating.
- **Month cells and the day section agree.** A month cell keeps its class dots and gains one coloured dot
  per extra layer, with the layer count in the cell's accessible name. Under the selected day (and in
  Upcoming) an “Also today” card lists local events, review workload and dated tasks with time and course.
- **The four tabs became one.** `HUB_SPECS.plan.tabs` is the calendar alone. Focus day, Review calendar and
  Local events left the tab bar; their commands still work through `plugin.openMergedCalendar`, which
  switches on the matching layer and opens the day view for Focus day. The standalone views stay
  registered for embeds and back-compat.
- **One Calendar stays reachable.** The Plan tab is always offered so a disabled Calendar module leaves the
  hub with its merged surface rather than an empty frame; the calendar itself explains how to turn the
  module on.

## Evidence

- `tests/calendar-merge.test.js`: five tests for layer defaults, per-day grouping of all five stores,
  completed-task exclusion, switched-off layers, disabled modules and the month-dot counts.
- `tests/hub-views.test.js`: the Plan hub offers exactly `calendar`, mounts the real calendar view, and
  Focus day opens it in day mode with the planned layer on.
- `node --test`: **3,006 pass, 0 fail**. `npm run check`: clean.

No note format, review schedule, network default or existing setting key changed. `settings.calendar.layers`
is a new optional key that defaults to every layer on.
