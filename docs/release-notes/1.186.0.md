# MCQ Tracker 1.186.0

Export from the Reference **Graph** tab.

## What is new

- **Export PNG** paints the current graph into a new canvas and saves it to `Exports/` in the vault as `graph-YYYYMMDD-HHMMSS.png`.
- **Export CSV** writes the data table to `Exports/graph-data-YYYYMMDD-HHMMSS.csv`, with an `x,y` header and one line per filled table row.
- **Copy expressions** copies every non-blank expression, one per line. Each row also has its own copy button that copies that row's source text exactly as typed.
- All four are ordinary buttons with labels such as `Export graph as PNG`, so they are focusable and work from the keyboard. They sit with the existing block controls, and the canvas keys from 1.183.0 are unchanged.

## What the files contain

- The PNG is the on-screen scene: same window, same row colours, widths, dashes, fills and point sizes, same points of interest and the same polar, minor-grid, axis-label and angle settings. It is painted at the device pixel ratio, clamped to between 1× and 3×, so it is not a blurry copy of a 1× canvas on a retina screen.
- The CSV uses the table's own cell strings rather than re-formatted numbers. A field containing a comma, a double quote or a line break is wrapped in quotes and its quotes are doubled, so `3,5` becomes `"3,5"` and `a"b` becomes `"a""b"`. A row with both cells blank is skipped, and the file ends with one newline.
- Copy keeps the expression text exactly, including spacing and capitalisation, and skips rows that are only whitespace.

## Nothing to export

- With no filled data rows, **Export CSV** shows `Add a data point before exporting a CSV.` and writes nothing.
- With no drawable expression — an empty list, or only definitions — **Export PNG** shows `Add an expression that draws something before exporting an image.` and writes nothing.
- **Copy expressions** with no non-blank row shows `Add an expression before copying.`, and a row's copy button on an empty row says `This expression is empty.` None of these paths throws.

## Platform limits

- Each export path feature-detects what it needs. Without a canvas, the image export reports that the device cannot build an image; without `vault.create`/`createBinary`, the file export reports that it cannot write files; without `navigator.clipboard`, copying reports that the clipboard is unavailable. Nothing is silently lost and nothing crashes.
- Files are written into the vault rather than offered through a browser download dialog, so a read-only vault or an unwritable folder shows a save error instead of a file.
- Export is a pure consumer of the existing state. Samples, points of interest, roots, extrema, intersections, the cursor trace, persisted rows and the 1.185.0 style resolution are identical before and after the PNG, CSV and copy paths, which a test compares directly.

## Still limited

- The cursor trace and hit-testing still cover explicit and fitted rows only; polar, parametric, implicit, point and inequality rows draw but give no readout.
- The PNG has no optional size, theme, background-transparency or filename control, and the CSV has no delivery choice beyond the `Exports` folder.
- None of these buttons has been exercised by hand in a live Obsidian vault, on desktop or phone, and neither has the graph canvas generally.
