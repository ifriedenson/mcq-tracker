# MCQ Tracker 1.223.0

The tutor can now run fully offline on your own computer with a local model such
as Google Gemma 4. The plugin already spoke the OpenAI-compatible protocol, so
this release does not bundle a model or a runtime and adds no dependency,
provider account, key or network request. What it adds is first-class setup for
the common local servers, instructions inside Settings, and documentation that
is honest about hardware, context and licensing.

## Local servers you can use

Direct API now has four local presets beside the hosted ones:

| Provider | Base URL | Notes |
|---|---|---|
| **Ollama** | `http://localhost:11434/v1` | Easiest route to Gemma 4; no API key. |
| **LM Studio** | `http://localhost:1234/v1` | Start its Developer server; load a GGUF or MLX model. |
| **llama.cpp server** | `http://localhost:9931/v1` | Current builds default to 9931; older ones used 8080. |
| **Jan** | `http://127.0.0.1:1337/v1` | Start its Local API Server with a model loaded. |

All four are marked `noKey: true` and `local: true`. Choosing one shows an
**Offline local model** hint in Settings with the address, the commands to run,
the context-length warning and the fact that the server must run on the same
computer as Obsidian. **Fetch models** lists what the server has loaded, and
**Test** sends the same one-word connection check as any other provider. The
existing "Other OpenAI-compatible" preset still covers GPT4All, KoboldCpp or any
other local server by address.

## Gemma and hardware

`src/local-models.js` is pure and holds the setup text: Ollama's
`ollama pull gemma4:12b` / `ollama run gemma4:12b`, LM Studio's
`lms server start`, llama.cpp's
`llama-server -hf ggml-org/gemma-4-E4B-it-GGUF:Q4_0 --port 9931`, and Jan's
Local API Server steps. The README's new **Run a local model (offline tutor)**
section covers the practical details:

- Gemma 4 E4B needs roughly 5-7 GB at Q4; 12B roughly 7-8 GB; 26B A4B roughly
  14-16 GB; 31B roughly 17-20 GB, before the KV cache. CPU-only works but is
  slower.
- Ollama's default context is 4096 tokens, so set `OLLAMA_CONTEXT_LENGTH=32768`
  before starting it if you send long passages.
- Downloads need a connection once; after that generation is local. Set
  `OLLAMA_NO_CLOUD=1` and avoid `-cloud` tags to stay offline.
- A phone cannot reach your computer's `localhost`, so the offline tutor is a
  desktop setup; a phone still needs a reachable HTTPS server or a hosted
  provider.
- Gemma 4 is Apache 2.0. Gemma 2/3/3n use the Gemma Terms of Use, which is why
  the guide points at Gemma 4 for anything you redistribute.

## Tests

`tests/local-models.test.js` asserts every local preset is loopback-only, needs
no key and resolves through `ApiClient.cfg()` without a key; that the Ollama
guide contains the Gemma pull command, the context-length setting and the
same-computer warning; that LM Studio, llama.cpp and Jan expose their addresses;
and that hosted or unknown providers are not treated as local. The existing
model-discovery and Qwen tests still pass unchanged.
