# 1.301.16 — Answer checks wait, and OpenCode recovers after sleep

## What changed
- **Blind answer checks have no time limit.** `verifyQuestionDraft` awaits the
  model reply directly on both the choice and numeric paths. `withinVerificationTimeout`,
  `VERIFICATION_TIMEOUT_MS` and the `verifyTimeoutMs` override are deleted.
  A slow reply now verifies the note instead of marking it a verification error.
- **A running-but-dead OpenCode server is restarted before the next use.**
  `OpenCodeManager.ensure()` used to trust the process handle: if
  `isRunning()` was true it returned at once, so a server left half-dead by
  the computer sleeping (screen off, process handle alive, nothing answering)
  was handed to the next import file, which then stuck. Now `ensure()` pings
  the server twice through `providers` (`answering()`, 10 s each); two misses
  stops it and starts it fresh, saying on screen
  "OpenCode was still running but stopped answering, so restarting it fresh...".
- The ping asks twice with 1.5 s between so one dropped poll does not restart
  a healthy server, and `ensure()` accepts test hooks. All callers share the
  fix: the chat, every import file, **Check that OpenCode is running** and
  Settings → Test.

## Why
The owner reported the 60-second check limit verifying nothing, and a second
PDF sticking on start after the screen had been off — the classic
process-alive/server-dead shape after sleep.

## Verification
- `tests/answer-verification.test.js`: a reply delayed 50 ms verifies the note
  (`checked: 1`, `status: match`) instead of erroring.
- `tests/import-batch-window.test.js`: a check answering after 120 ms writes
  the note with `verified: true` and the batch completes with
  "1 question note imported".
- `tests/opencode-lifecycle.test.js`: with the process handle alive and the
  connection pointed at a dead port, `ensure()` replaces the process, answers
  `providers` on the fresh server, and reports the restart.
- No note format, setting key, review schedule or network default changed.
