# MCQ Tracker 1.179.0

Parametric curves with bounds and optional fill in the Reference **Graph** tab.

## Accepted parametric syntax

- A row written as a parenthesised pair is parametric: `(cos(t), sin(t))`, `(t, t^2)`, `(a cos(t), a sin(t))`, `(t - sin(t), 1 - cos(t))` and `(cos(3 t), sin(2 t))` all work.
- The shared parameter is `t`; `theta` and `θ` are accepted as the same name, so `(cos(theta), sin(theta))` is identical to `(cos(t), sin(t))`.
- Both coordinates use the normal row grammar: `sin`, `cos`, `tan`, `asin`, `acos`, `atan`, `sqrt`, `abs`, `ln`, `log`, `exp`, `floor`, `ceil`, `pi`, `e`, `+ - * / ^`, and `f`/`g`/`h` definitions from earlier rows (`f(x) = x^2` then `(t, f(t))`).
- Parameter sliders are read live in both coordinates: `a = 2` then `(a cos(t), a sin(t))` traces a circle of radius 2.
- Without a condition the parameter sweeps `0` to `2π` inclusive, so a closed pair meets exactly at the seam instead of leaving a gap.
- A condition that is exactly a two-sided range on the parameter sets the sweep: `{0 < t < 2pi}`, `{-pi < t < pi}`, `{0 <= t <= 4 pi}`, and slider bounds such as `{a < t < b}`. The bound expressions are evaluated once, must be finite numbers, and the end must be larger than the start.
- Any other condition filters the default `0..2π` sweep instead, with `t`, `theta`, `x` and `y` in scope: `{t < pi}` draws the first half of a circle, and `{x > 0}` keeps only the right-hand part of the curve.
- A coordinate that is not a real number leaves a gap in the line, and the canvas never joins across that gap or across a wrap, so nothing is drawn as a spurious chord.

## Fill

- The word `fill` after the pair shades the enclosed region at the same 16% opacity as an inequality region, before the outline is stroked: `(cos(t), sin(t)) fill` or `(cos(t), sin(t)) fill {0 < t < 2pi}`. It works before or after the brace group.
- Fill requires a continuous closed curve, so `(t, t^2) fill` reports that it needs a closed curve, and a curve with holes such as `(sqrt(t - 3), t) fill` reports that it needs a continuous curve. Nothing is shaded when the check fails.
- The curve itself still draws whenever its points are finite; the fill message is the only error in that case.

## Errors

- `(cos(x), sin(x))` reports `Unknown name "x". Use t, theta, pi, e and the listed functions.`
- `(cos(t),)` and `(cos(t), sin(t), 1)` report that both x and y need exactly one expression each.
- `(t, t) {0 < t < q}` reports that a parametric bound must be a number, and `(t, t) {2 < t < 1}` reports that the end must be larger than the start.
- A row whose curve has no real values in the window says so instead of leaving a blank canvas.

No new dependency, no `eval`, no `Function` and no network request: parametric rows reuse the existing restricted parser, sampler and canvas transform.
