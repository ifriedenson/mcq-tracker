# 1.284.0 — The knowledge record, proved end to end

This release verifies the opt-in knowledge record added in 1.283.0 through the
real plugin paths and fixes the defects that scenario exposed. There are no new
dependencies, providers or external services.

## What the scenario covers

`tests/knowledge-record-scenario.test.js` loads a source note and two linked
questions into the real `QuestionTrackerPlugin`, enables the record, and checks
that the JSON index is written at `MCQ Tracker/knowledge-record.json`. It then
drives the real `recordAttempt` path: two correct answers make one concept
known; a miss plus the normal error-tag path opens a misconception; a later
correct answer fixes it while retaining the error history. Coverage, known, due
and the Insights card are read back from the populated record.

The same scenario renames a heading and proves the concept id, attempts and
aliases survive; removes the source note and proves the concepts remain as owed
work with a `source missing` row; compares two full rebuilds for stable content;
reloads a fresh plugin instance from the vault; renders Insights → Concepts;
clicks **Rebuild record** and **Copy learner digest**; checks the digest's
~3,000-character bound and linked-only evidence; and proves the Study-agent
context is absent while the `Knowledge record` toggle is off.

## Defects fixed

- `buildNoteEntry` now accepts either a concept array or a previous note entry
  before reconciliation. Passing the whole entry meant every rebuild treated
  every concept as new, losing `firstSeen` and aliases.
- Heading ids now use structural anchors. A renamed heading keeps its id,
  records the old label as an alias, and keeps linked question evidence instead
  of appearing as an orphan.
- A full rebuild retains concepts from a deleted source note with `missingAt`;
  the Insights card and learner digest mark them `source missing` rather than
  silently dropping them.

## Verification

`node --test` → **2,379 tests pass, 0 fail**. `npm run check` is clean: no
dynamic code across 336 source files, the vendor guard passes, `main.js` is up
to date and the plan status is current. The generated bundle comes from 339
modules at **6,740,429 bytes**. The generated capability inventory was
regenerated for the new `markNoteMissing` export and the scenario citation.

This is a harness verification, not a visual Obsidian pass. The DOM harness
covers the Insights card's real numbers and both actions; a human should still
open the panel in Obsidian to check its visual spacing and interaction.
