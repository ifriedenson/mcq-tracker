# 1.256.0 — The PDF editor record is checked against the code

Released Nov 4, 2026.

This release is a review, not a feature: the editor record
(`docs/pdf-editor-mission.md`), `plan.md`, `AGENTS.md` and the release notes
1.242.0–1.255.0 were read against `src/pdf-editor.js`,
`src/pdf-editor-modal.js`, `src/pdf-editor-history.js` and the tests, the
editor was security-reviewed, and the record was made self-checking.

## What the review found

- **No missing feature.** Every capability the record claims is present: open
  refusals (empty, oversized, encrypted, damaged, over 2,000 pages), page
  rotate/move/delete/duplicate/blank-insert/add/extract/split, content
  (text, image, page numbers, crop, watermark, shapes, page size), form fill,
  flatten, author, rename and delete, links (add, read, retarget url/page/
  launch/named/remote, area, page move, style, border, dash, phase, removal),
  bookmarks (read, write, clear, zooms/positions), and the bounded undo
  history. The only link-editor gap that had been open — remote `/GoToR` —
  closed in 1.255.0.
- **One record defect, fixed.** The `tests/pdf-editor.test.js` bullet in the
  mission record had become garbled by successive edits: it said “launch”
  twice, ran a sentence across unbroken lines, and never mentioned the remote
  retarget as a separate capability. It now reads once, cleanly, and names the
  remote retargets beside launch and named.
- **Documentation drift, guarded.** The record’s numbers (80 MB, 2,000 pages,
  500 links, 200 bookmarks, 120-character titles, three levels, 60-character
  field names, 100,000 remote pages, 1,000-point phases, 20 undo steps and a
  96 MB history) had no test tying them to code, so a later edit could have
  changed a constant and left the record lying. `tests/pdf-editor-record.test.js`
  now reads the record and the engine together.
- **Security review: no high-confidence findings.** The editor files make no
  network request, hold no credential, use no `eval`/`new Function`, never set
  `innerHTML`/`insertAdjacentHTML`, and render only through Obsidian's
  `createEl`/`setText`. Their only write path is `vault.createBinary` on
  `editedPathFor`, which strips leading slashes and every `\ / : * ? " < > |`
  from the base name, keeps the original folder, and never overwrites an
  existing path; the source PDF and its sidecar are never opened for writing.
  A guard test now fails if a future edit adds `requestUrl`, `fetch`, `eval`,
  `new Function`, `innerHTML` or `insertAdjacentHTML` to either editor file.
  Reported as a refused-gate limit rather than a vulnerability: a PDF is
  untrusted input, and pdf-lib parses it in-process, so a parser memory bug is
  the editor’s residual risk (the same risk the reader already carries).

## What changed

- `tests/pdf-editor-record.test.js` — five tests: every named capability is
  exported, every stated limit equals the engine’s constant plus the history’s
  20 steps/96 MB, the empty and damaged refusals behave and the XFA/encrypted
  claims are present, both editor files stay free of network, dynamic code and
  `innerHTML`, and every release 1.242.0–1.256.0 has notes and is named in the
  record with the record’s notes range ending at 1.256.0.
- `docs/pdf-editor-mission.md` — the garbled link-test bullet is rewritten,
  the history bounds are stated in Verification, the record-style test is
  listed, the notes range ends at 1.256.0, an “At 1.256.0” line records the
  full suite, and a **Review (Nov 4, 2026)** section records both axes and the
  security result.
- `plan.md` and `AGENTS.md` — the audit release is recorded.

## Verification

- `node --test tests/pdf-editor-record.test.js` → **5 pass / 0 fail**.
- Full suite **1932 pass**, engine **90**, window **25**, history tests green;
  `npm run check` clean across **297 source files**; `node scripts/build.js --check`
  reports `main.js` up to date across **298 modules** at **4,976,540 bytes**
  (unchanged, because this release touches no engine code); `git diff --check`
  clean.

## Limits

- This release adds no behaviour. The five remaining gates are unchanged: XFA,
  encrypted files, rewording existing text, unverified link targets and the
  editor-owned dash-phase encoding, plus hierarchical field names and
  bookmark-view guessing.
