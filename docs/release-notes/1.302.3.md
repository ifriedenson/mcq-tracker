# 1.302.3 — A slow model is no longer mistaken for an empty one

## What the owner saw
A single-PDF import stopped with **OpenCode's model sent no reply at all: the
provider accepted the request and returned an empty answer.** The same sentence
could appear while the model was still working: OpenCode creates the assistant
message before the first token, so a message with no parts is not proof that
the provider refused anything.

## What changed
- `src/opencode-client.js` `emptyAssistant()` now requires
  `info.time.completed` before an empty message can end a blocking send. An
  unfinished message is a model reading a long prompt, and the normal silence
  allowance stays in charge.
- `src/import-modal.js` `pollAgent()` applies the same rule, so an import no
  longer stops after two minutes on a message the provider has not finished.
- A provider that really refuses the request completes the empty message within
  seconds (measured at ~15 s on the free tier's `Free usage limit reached`), so
  the fast, actionable message is unchanged.
- No timeout, restart rule, Stop behavior, note format or setting changed.

## Evidence
- Live three-PDF import through the real import window on this build's parent:
  **6 notes**, `MULTI-1-Q01/Q02`, `MULTI-2-Q01/Q02`, `MULTI-3-Q01/Q02`, every one
  with `verified: true` and `verification: match`, ending on **Import complete:
  6 question notes imported from 3 files.**
- The fix was exposed by a second provider (a local llama.cpp model): its
  9,800-token prompt took longer than the old two-minute empty window, and the
  import declared it empty before it could answer. With the fix the request is
  allowed to finish. A 1.5B model still ignores the note-writing tool protocol
  and a 4B model is slower than this CPU can sustain, so the local provider is
  configured and reachable but is not a working import backend on this machine.
- New test: an unfinished assistant message with no parts is treated as a slow
  model (the send falls to its silence allowance), while a completed empty
  message still fails fast with the provider's words.
- Full suite: **2,878 pass, 0 fail**; `npm run check` clean.
