# MCQ Tracker 1.229.0

This release closes the two remaining page operations that were not covered by
the form-safe copy preparation: duplicating a page and moving a page in a
fillable PDF.

## What changed

- `duplicatePage` now prepares a serialised, flattened copy when the document
  has an AcroForm, then copies the selected page from that copy. Filled values
  stay visible in the duplicate, no orphan widget annotation is carried over,
  and the document being edited keeps its original live, fillable form.
- The duplicate result reports `flattened: true`; the editor status says the
  duplicate was baked and the original form stays fillable.
- `movePage` is now explicit about its form contract: it moves the page object
  rather than copying it, so the widget, value and field page reference move
  together. The result reports `flattened: false` and `liveForm`, and the
  editor status names the live form.
- Duplicate and move share `formFieldCount`, so both paths agree on whether a
  document has a readable AcroForm.
- If a form cannot be flattened, duplication refuses with a form-specific
  message and leaves the page count and live values unchanged.

## Why reorder is different

A move does not copy page content. Replacing that with a page copy would create
the same orphan-widget problem the duplicate path had, and flattening the whole
document would destroy the live form. The reorder test therefore proves the
correct contract: one live widget, the value still present after save, the
widget on the moved page, and no baked appearance in the page content.

## Honest limits

- A duplicated page is flattened, so its fields are visible but not fillable.
  The original page and form stay live.
- A move keeps the live form and does not flatten anything. This is deliberate:
  it preserves the field's value and widget instead of copying a page.
- XFA, encrypted PDFs and signature or button fields that cannot be flattened
  still refuse the operations that need a flattened copy.
