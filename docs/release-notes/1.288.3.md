# 1.288.3 — Accessible study surfaces and release integrity

This patch packages the current tree after the 1.288.2 commit. 1.288.2 was
never tagged or released, so 1.288.3 is the next published version. It closes
the gap between the opt-in Web browser implementation and its settings UI,
hardens keyboard and narrow-width behavior across the study surfaces, and makes
the plan, release evidence and verification counts agree.

## Changes

- **Web browser settings are reachable.** The `web-browser` page already
existed, but it was missing from `STUDY_TOOL_SETTINGS_MODULES`, so Settings →
Global, Modules had no entry and the opt-in browser could not be enabled. The
module is registered now; all 36 page implementations are reachable and a test
fails if a page and a navigation entry drift apart.
- **Accessible custom controls.** A shared `makeKeyboardClickable` helper adds
  role, focusability, optional accessible naming and Enter/Space activation to
  non-button controls. Audited views, modals, panels and settings fields now
  expose names for their visible controls, and the swept views use the helper
  for their custom click targets.
- **Narrow-width hardening.** PDF reader and editor rows, Settings tabs, Study
  Stats tables, cards, assignments and time-block grids wrap, stack or scroll
  before the pane clips; the hidden conversation-tab close control no longer
  takes a click.
- **Evidence and records.** The current 20-image Study agent set (18 chat plus
  the settings pair) is committed with its measurements. The plan records 36
  study-tool settings pages and 98 checked / 3 partial / 0 unchecked roadmap
  rows, where the three partials are the unperformed owner manual passes,
  and the capability inventory records 2,941 exports.
