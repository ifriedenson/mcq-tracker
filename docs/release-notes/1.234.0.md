# MCQ Tracker 1.234.0

This release adds the first approved **Advanced Tables** slice: rendered Markdown
table cells can be edited in place and reached with the keyboard, while the source
note stays a valid, aligned Markdown table. The module is off by default and is
available from the Global module index and its own settings page.

## In-place cell editing

`src/table-editor.js` is pure and has no Obsidian dependency:

- `splitTableRow` reads a GFM row without mistaking escaped `\|` or a pipe inside
  a code span for a column separator. `parseTables` skips YAML frontmatter and
  fenced code, keeps each table's line range and preserves optional indentation.
- `renderTable` pads every column to a common width, keeps left/right/center
  alignment, emits a valid delimiter row and adds no blank or ragged rows.
- `escapeCell` turns a typed pipe into `\|`, replaces line breaks with spaces and
  bounds a cell to 4,000 characters.
- `updateTableText` returns the whole updated note with the note's original line
  endings (including CRLF), the block replacement and its line range. A header and
  shape check finds the intended table if earlier edits shifted its line number.
- `navigateCell` defines Tab/Shift+Tab, Enter/Shift+Enter and Alt+Arrow movement.
  It reports a boundary rather than wrapping, so a table cannot steal focus from
  unrelated content by accident.

The plugin registers a second Markdown postprocessor only when the switch is on.
It decorates cells only inside a real reading-view note (`.markdown-preview-view`
or `.markdown-reading-view`), skips embedded notes and custom Markdown renders,
and leaves the table untouched when the switch is off. No parallel editor is
created: a commit goes back through `updateTableCell`, which prefers the live
Markdown editor's `replaceRange` and falls back to `vault.modify`. Writes are
serialized by a queue so two cell edits cannot race a read-modify-write.

## Controls

| Key | Action |
|---|---|
| **Tab** / **Shift+Tab** | Next or previous cell; at the outer edge, leave the table through the browser's normal tab order. |
| **Enter** / **Shift+Enter** | Cell below or above; at the bottom or top, stay put instead of inserting a newline. |
| **Alt+Arrow** | Move one cell in that direction. |
| **Esc** | Cancel the current cell edit and restore its text. |
| Click or blur | Commit the current cell. |

The settings page is **Settings → Global → Advanced Tables**, or the tool's page
in the module sidebar. The default is off. Turning it off again rerenders open
previews and restores the normal read-only table presentation.

## Honest limits

This is editing and navigation only. Formatting commands, row/column insertion
or deletion, move, sorting, formulas, merged cells and CSV export are deliberately
not part of this release.

The editor is wired to reading view. Live Preview is left to Obsidian's own table
editor; no second source-mode widget was added. Editing a cell replaces its inline
formatting (for example bold or a link) with the plain text taken from the rendered
cell, so use source mode when rich cell contents must be preserved. A table must
have a standard GFM delimiter row; blockquote-prefixed tables are not parsed. The
in-memory parser is bounded to 500 rows, 40 columns and 4,000 characters per cell.
Reading-view writes may cause Obsidian to rerender the note and move focus after a
commit; the Markdown itself is still written in one block.

No plugin source, styles or data were copied for this release. No provider,
account, telemetry, dependency or network request was added.
