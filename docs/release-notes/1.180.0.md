# MCQ Tracker 1.180.0

Points, labels, open and closed markers, and point lists in the Reference **Graph** tab.

## Which rows are points

- A parenthesised pair whose coordinates do not use the parameter is a point: `(1, 2)`, `(-3, 0.5)`, `(0, 0)` and `(a, b)` when `a` and `b` are sliders.
- A pair that uses `t` or `theta` is still a parametric curve: `(cos(t), sin(t))` and `(theta, 2)` draw curves, not points.
- A single parenthesised expression is still an explicit expression row: `(sin(t))` is `y = sin(t)`.
- Coordinates take the normal row grammar, so `(2, f(2))` works after `f(x) = x + 1`, and `(pi, e)` is a point.

## Markers, labels and styles

- A point is drawn as a 4.5 px marker at its coordinate through the same canvas transform as every other row, so zoom, pan and the cartesian and polar grids behave identically. Points are never sampled as a polyline, so separate points never get a chord between them.
- `closed` is the default: a filled disc in the row's colour. `open` draws a hollow ring with the same radius and a 2 px outline, so the two styles are distinguishable from each other and from the 2 px curve stroke.
- The label defaults to the coordinate text, formatted to six decimals with trailing noise removed, so `(1, 2)` is labelled `(1, 2)` and `(a, b)` relabels when a slider moves.
- A quoted string replaces the label: `(1, 2) "A"` shows `A`, and `(0, 0) "origin" open` shows `origin` with a hollow marker. Modifiers can be written in either order.
- Labels sit above and to the right of the marker. Near the right edge the label flips to the left of the marker, near the top edge it drops below it, and it is clamped inside the canvas at any zoom level.
- On a list, a quoted label names the row while each marker keeps its own coordinate label.

## Point lists

- Square brackets hold a list: `[(1, 2), (3, 4)]`, `[(-1, 0), (1, 0), (0, 1)]`, and `[(0, 0), (2, 2)] open` for hollow markers. Every entry must be a pair.
- One row draws every marker in its own colour, with no connecting line.
- A restriction filters the markers: `[(1, 2), (-1, 2)] {x > 0}` draws only the first point, and `(-1, 2) {x > 0}` reports that no point matches instead of drawing nothing silently.

## Errors

- `(x, 2)` reports `Unknown name "x". Use t, theta, x, y, pi, e and the listed functions.` A point's coordinates must be numbers.
- `[]` reports that a point list needs at least one point, and `[(1, 2), 3]` reports that each entry needs a pair.
- `(1, 2) fill` reports that fill needs a curve, and `[(1, 2)] fill` reports that fill needs a single closed curve rather than a list.
- `open`, `closed` or a quoted label with no point after it reports that the row still needs a point.

No new dependency, no `eval`, no `Function` and no network request: points reuse the existing restricted parser, definitions and canvas transform.
