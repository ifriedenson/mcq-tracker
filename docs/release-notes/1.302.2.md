# 1.302.2 — A spent free model no longer stops an import

## What the owner saw
A multi-PDF import over OpenCode was only reliable while the chosen free model
still had quota. When that model hit its limit, the file ended with
`Free usage limit reached` even though the provider offered other free models
that day, so the batch could not finish without editing Settings between files.

## What changed
- **Quota-aware fallback.** When a file fails with a quota-shaped message
  (`Free usage limit reached`, `429`, rate limit, capacity, overloaded, or an
  empty reply), `PdfImportModal.quotaFallback()` asks OpenCode for the current
  provider's model list, picks the next **free** model not yet tried, aborts the
  dead session, opens a fresh one and re-sends the identical file prompt. It
  stops after three switches and then reports the original failure.
- **Only free models rotate.** The candidate must match `free` in its model id,
  and the current model must be free too, so a paid or credentialed model is
  never charged to dodge a limit. A disk, PDF or permission error never rotates.
- **No duplicates.** A file with any note already on disk is never started
  again; the fallback is only used while nothing has been written.
- **Checks follow the model that replied.** `verifyDraftQuestions` accepts
  `{ model }`, and the import passes the working model into its blind checks and
  writes that model on the note, instead of sending every check to the exhausted
  model.
- **Faster failure before the fallback can help.** `OpenCodeClient` now reads a
  provider `info.error` and fails the send immediately; an assistant message
  with no content fails after a 90 s grace; an import agent that replies with
  nothing stops after 2 minutes instead of the 6-minute silence allowance.
- **Less wandering per file.** The import prompt reads only the extracted text,
  writes the notes immediately and runs one folder check last, and the system
  prompt no longer invites vault exploration. On the same three PDFs the first
  action was the text read at 18:35:14 and the first shell command was the
  final folder check at 18:39:18.
- **Summary button fix.** The import-complete modal's button is a plain DOM
  element; it now uses `.disabled` instead of the view API's `setDisabled`, so
  the completion summary no longer throws.

## Evidence
- New tests:
  - the same file is asked of `flint-40b-free` and then
    `nemotron-3.5-lightning-free`, the note is written by the second model, and
    the status line says the free model ran out of quota and the file is being
    started again with the next one;
  - a non-quota error, a paid model and a failed model list never rotate;
  - a file that already has notes is never started again;
  - the note and its checks carry the fallback model.
- Measured in headless Obsidian 1.15.1 with managed OpenCode on the same three
  PDFs: 6 notes, each file 4:32, 3:45 and 4:28, last note at 12:45 (down from
  13:31), all checks matching; a dead provider was reported in 93 s instead of
  20 minutes, and an empty reply stopped at 2:09 instead of 6 minutes.
- The fallback itself could not be driven live to a successful import: at the
  time of this release every free OpenCode model on the test machine returned
  `Free usage limit reached` or no content. It is covered by the tests above
  against the provider's real model-list shape and error text.
- Full suite: **2,877 pass, 0 fail**; `npm run check` clean across
  **365 source files**; `main.js` **7,384,813 bytes** from **368 modules**.
