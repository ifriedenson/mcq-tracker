# 1.301.18 — A Stop is answered at once, checked in a real Obsidian window

## What changed
- **Stop ends the check immediately.** `ensure()`'s two pings and the pause
  between them now run behind a stop signal: `stop()` resolves the waiting
  check (`stopWaiters`) so the press is answered at once instead of after the
  current ten-second ping gives up. `stopMark` still guards the start itself,
  so nothing starts after a Stop.
- **Nothing is announced for a server the user just stopped.** The
  "restarting it fresh" line is no longer written when a Stop already ended
  the check.

## Why
The 1.301.17 build was driven in a real Obsidian 1.15.1 window (see below).
Every path behaved as designed except one: a Stop pressed 2.5 s into the check
took 8 s to answer and announced a restart first. This release fixes what the
live window found.

## Live window audit (Nov 13, 2026)
Obsidian 1.15.1 (auto-updated from 1.15.0) ran headless through Ozone with CDP
on port 9222, a disposable vault holding the built plugin
(`main.js`, `manifest.json`, `styles.css`), the real Settings window and the
real import popout. A stand-in `opencode` executable served
`/config/providers`, `/global/health` and sessions, and could freeze its
answers on demand to imitate a server whose process outlived its port after
sleep.

- The plugin loaded and enabled itself in the vault; the Settings page read
  **MCQ Tracker 1.301.17** and no error notice appeared.
- Settings → Study agent → AI showed the real controls; **Start** produced
  `Status Running on http://127.0.0.1:39061.` and **Stop** returned it to
  `Start`.
- One healthy AI request recorded **zero** progress messages, so the lazy
  notice added in 1.301.17 never appeared for an already-running server.
- A frozen server produced exactly `OpenCode is running but didn't answer a
  quick check. Asking once more...`, then `OpenCode was still running but
  stopped answering, so restarting it fresh...`, then restarted and answered.
- Stop 2.5 s into the check: with 1.301.17 it answered after 8 s and said it
  was restarting; with this release it answers at 2.5 s, says
  `OpenCode was stopped before it finished starting. Start it again from
  Settings > Study agent > AI when you are ready.`, announces nothing and
  leaves no server running. Pinned by `tests/opencode-lifecycle.test.js`.
- The import popout opened with its real form (file chooser, vault file,
  folder, writer, figure options), and `verifyDraftQuestions` reported its
  position (`1/2`, `2/2`) through the new progress hook.
- Limits of this pass: Obsidian notices are not inserted into the headless
  renderer's DOM, so the message text was read from the manager's progress
  callback rather than from a rendered notice; and without a provider reply
  that parses as an answer, the import's own "Checking answer N of M" line was
  not driven end to end.

## Verification
- `node --test` passes; `npm run check` is clean.
- `tests/opencode-lifecycle.test.js`: the Stop test now also asserts the
  answer arrives within 1.2 s and that no progress line is written.
- No note format, setting key, review schedule or network default changed.
