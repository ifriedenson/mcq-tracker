# 1.301.14 — The extra checks can use other AIs

## What changed
- **New setting: Models for the extra checks** (Settings → AI → Session pacing
  and checks). One model per line, up to three. The extra checks after a
  disagreement take them in order and repeat the list when there are more
  checks than models, so two listed models cover three extra passes.
- **The first check still uses the configured verification model**, so listing
  two models means the four passes come from three different AIs.
- **`verified_by` names every model that voted.** A consensus-checked note
  records `first model + extra model(s)` instead of only the first model.
- Leaving the list empty changes nothing: every pass uses the model chosen for
  **Check AI-written answers**, exactly as in 1.301.13.

## Why
The owner asked for the extra checks to use two different models so the votes
are not three copies of one AI's judgment.

## Notes
- The models are used as typed; there is no model list fetch here, so a typo
  fails that one extra check and it simply does not vote, which never turns a
  disagreement into a verified answer.
- The list is cleaned on save: trimmed, blank lines dropped, duplicates removed,
  at most three entries, 200 characters each.

## Verification
- `tests/answer-verification.test.js`: `normalizePanelModels` handles newlines,
  commas, repeats and the three-model cap; `panelModelFor` repeats the list and
  returns `""` for an empty one; with `["m-one", "m-two"]` and three extra
  checks the requests carry `["", "m-one", "m-two", "m-one"]` and
  `verified_by` names both extra models.
- The first check always carries no model override.
- No note format, other setting key, review schedule or network default changed.
