# 1.301.23 — The error card has the fix

1.301.22 gave the AI-off panel an **Open settings** button but left the
missing-key error card in the same chat panel with only **Retry** and a sentence
telling the user to find the setting themselves. This patch closes that
asymmetry at the error renderer.

## What changed

`ChatPanel.draw()` now detects provider errors whose fix is a configuration
value rather than another identical request:

- `Add your API key in the plugin settings.`
- `Add a base URL in the plugin settings.`
- `Add a model name in the plugin settings.`
- `OpenCode rejected the username or password. Check the plugin settings.`
- `OpenCode has no AI provider connected yet. Open Settings > Study agent > AI
  and the assistant, choose a provider and paste an API key.`
- `The provider rejected the API key, or the key can't use this model.`
- the unreachable-provider message that points at the base URL in settings

For those errors the card now draws both **Retry** and **Open settings**. The
settings button calls `openSettings("mcq-ai")`, the same route as the AI-off
panel, so it lands on **AI and the assistant** (`AI backend`,
`Enable AI features`) rather than the first settings page. **Retry** and the
header gear are unchanged; a transient network or empty-reply error keeps its
usual card.

Code: `src/chat-panel.js` (`errorNeedsSettings`, error actions row);
`styles.css` (`.qt-agent-error-actions`).

## Verified live

Obsidian 1.15.1 was relaunched headless against the disposable vault with the
CDP port, with notice observers on the main, floating and Settings windows. The
executed bundle reported **1.301.23** from the vault copy, not just the source
tree.

- Seeded `UNIT-A-Q01.md`, started Quick Practice, answered B with confidence and
  submitted.
- Opened **Ask AI**, chose a suggested-action card, and sent it with the provider
  configured (`127.0.0.1:4571/v1`) but the key and secret stores empty.
- The card read *That reply did not finish — Add your API key in the plugin
  settings.* and drew **Retry** and **Open settings**.
- Clicking **Open settings** opened the Settings window on the AI page: the page
  title **AI and the assistant** and the **AI backend** / **Enable AI features**
  sections were present. The main chat stayed on the same error with its
  controls.
- Restoring `openai` key `sk-standin-live` and clicking **Retry** cleared the
  error card and rendered the reply with **Bookmark**, **Copy**, **Add to My
  Notes** and **Regenerate**.
- No notice fired and no console error was recorded in either window.
