# 1.271.0 — Markmind files and any note's outline are a real mind map

Markmind was recorded as Partial: `study-map` drew a read-only outline and key-term
map, there was no outline editor, and there was no Markmind file compatibility.
The `src/mindmap.js` reader/editor existed but no command reached it.

## What changed

- **`mindmapFromMarkdown`** builds a map from any note: headings nest by level,
  list lines nest under the heading they follow, and a note with no heading still
  gets its list as branches. That makes an ordinary outline editable.
- **`plugin.mindMapTree(path)`** reads a note as a map — a Markmind board
  (`mindmap-plugin: basic` plus a nested list) or a plain note's headings.
- **`plugin.mindMapEdit(path, action, args)`** applies add, rename, remove or move
  and writes the Markmind shape back, so the map stays a normal Markdown file that
  Markmind can open and the plugin can read again. A plain note is upgraded on its
  first edit; an unknown action, a node that is not in the map or a missing note is
  refused without a write.
- **Commands:** **Mind map: add a child**, **rename a node**, **remove a node**,
  **move a node** (two prompts each) and **Mind map: make a Markmind map from this
  note**, which writes `<note> (mind map).md` and refuses to overwrite.
- `study-map` keeps its read-only outline and key-term map; this release adds the
  editing and file side beside it.

No Mindmap source, styles or data were copied — the module is original and writes
only the frontmatter key the format documents.

## Verification

- `tests/mindmap-edit.test.js` (5 tests): heading and list nesting, reading and
  editing a Markmind note through add/rename/move/remove with a re-read tree,
  upgrading a plain note on first edit, the refusals, and the sibling map note
  being written once and not overwritten.

## Honest limits

- The tree is edited through prompts, not a drag-and-drop canvas. The map's visual
  layout is still Markmind's or the `study-map` block's; this release does not add a
  canvas renderer.
- Node text is matched exactly, so two nodes with the same text are ambiguous; the
  first match is edited.
