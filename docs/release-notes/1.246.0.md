# 1.246.0 — Bookmark views

Released Nov 4, 2026.

## What changed

- **A bookmark can name a view.** `setOutline` takes an optional third argument — `{ zoom, top }` — and
  writes a real `/XYZ` destination for every bookmark instead of `/Fit`: the page, its left edge, the
  position in points from the top of the page and the zoom fraction. Naming only a position writes a
  null zoom, so the viewer keeps the zoom it already has and still jumps to the right place.
- **It reads back.** `readOutline` returns `zoom` and `top` beside the title, page and level, so the
  rows show what each bookmark actually does. A whole-page bookmark still carries neither key, which
  keeps the existing rows and every earlier file unchanged.
- **The editor row.** **Add content → Bookmarks** gains **Zoom %** and **Position %** next to the
  `Title | page` list and **Save bookmarks**. Leaving both empty keeps the whole-page behaviour; the
  status line names the view it wrote. Each save is one undo step and only **Save a copy** writes.
- **Refusals, each with a message and no change:** a zoom outside 10–400% or one that is not a number,
  and a position outside 0–100% down the page.

## Verification

- Two new real-byte tests. A bookmark written at 150% zoom and 25% down a 500-point page is read back
  from the saved file as `zoom: 150, top: 25`, its raw destination is `/XYZ 0 375 1.5`, and a
  whole-page bookmark carries no zoom key at all. Every refusal leaves the file with no outline, and
  a position on its own reads back as `zoom: 0, top: 40`.
- 61 focused PDF-editor tests pass. Full suite **1891 pass**, `npm run check` clean across
  **297 source files**, `main.js` current across **298 modules** at **4,935,887 bytes**, and
  `git diff --check` clean.

## Limits

- One view applies to the whole list, not one bookmark: the row's two fields are document-wide, so a
  file that needs two different zooms is written in two passes.
- The position is measured on the page's media box, so a page with a non-zero crop offset starts from
  the media box edge rather than the crop edge.
- A destination of another kind (a fit-width or fit-rectangle bookmark in someone else's file) is read
  as a whole-page bookmark and rewritten as `/Fit`; it is never guessed at.
