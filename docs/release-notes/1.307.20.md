# 1.307.20 — A free local model's notes arrive whole

Released November 18, 2026. Obsidian 1.15.1.

## Why

Document import has always needed a model, and the documented options were a provider key or
OpenCode. To find out whether a free model running on the same computer is good enough, a real exam
PDF was imported through the real import window with **Ollama** on a CPU-only machine (8 cores,
15 GiB RAM, no GPU), no API key and no network beyond `127.0.0.1`.

The model (`qwen2.5:7b`, 4.7 GB, `Q4_K_M`, 32768-token context) answered, and the plugin got in its
way. Four defects came out of the run, all fixed here.

## What changed

- **A broken note separator no longer loses the notes.** The model wrote `=====` and then
  `NOTE=====` on two lines. `splitNotes` (`src/importer.js`) now accepts a marker broken across
  lines (`NOTE_MARKER`), where splitting on the exact marker alone read the reply as zero notes.
- **A repeated question is not a passage.** For the two questions that have no passage, the model
  filled `## Stimulus` with the stem followed by all four choices. `stimulusEchoesQuestion(sec)`
  recognizes that shape — the question, then each choice in order, then nothing, with punctuation
  and spacing ignored — and `finalizeNote` then writes no `stimulus_id` and `withoutStimulusSection`
  drops the duplicate section from the note body. `carryPassages` also skips such a section instead
  of handing it to the next batch as a "passage carried over". A genuine passage is untouched, and
  so is a passage that merely *begins* with the stem but carries on with real text.
- **A local model gets 15 minutes, not 2.** A 7B model on a CPU answered one batch after 3m30s,
  which the hosted 120-second deadline cut off. `LOCAL_REQUEST_TIMEOUT_MS` (`15 * 60 * 1000`)
  applies to the local presets — Ollama, LM Studio, llama.cpp, Jan — in `ApiClient.cfg()`.
- **The import window reads the provider from the right place.** `localProvider(ai)` tested
  `ai.provider`, but the setting lives at `ai.api.provider`, so the import window fell back to its
  own 3-minute deadline even for a local server. It now accepts both shapes.

The README gains the recipe that was actually run, under **Import and export → A free local model,
with Ollama**: `ollama pull qwen2.5:7b`, then Direct API, provider Ollama,
`http://127.0.0.1:11434/v1`, model `qwen2.5:7b`, with the measured speed (about 4–11 tokens per
second on 8 cores; 3½ minutes for the first batch because the 4.7 GB model has to load, under a
minute once it is warm), and what a smaller and a larger model did here (3B merged questions and lost answers; 14B answers at about 2 tokens/s, over ten
minutes for the same pages, and was never driven to completion on this machine).

## Evidence

**The live run.** `small-exam.pdf` (3 pages, 3 questions, a printed answer key on page 3, host
furniture on every page) was imported through the real import window with the rebuilt bundle. The
review appeared after the model finished and the notes were created. On disk:

| | Q01 | Q02 | Q03 |
| --- | --- | --- | --- |
| stem matches the PDF | yes | yes | yes |
| four choices match | yes | yes | yes |
| `answer` | B | B | C |
| printed key | B | B | C |
| `## Stimulus` section | none | none | the Source passage |
| `stimulus_id` | none | none | `SMALL-EXAM-S03` |
| page furniture | none | none | none |

Neither passage-less note carries a duplicated stem section, and the two notes that used to get a
`stimulus_id` for a passage that does not exist now carry none. No note contains `lOMoARcPSD`,
`Downloaded by`, `Studocu`, `Scan to open` or `Page N of`.

The same saved reply, replayed through the shipping `finalizeNote`, gives the same three notes
(`artifacts/pdf-import/verify-echo.js`, local; the repo keeps `artifacts/` out of git).

**What the model is and is not.** A second live run with the same settings sampled a different reply
and repeated question 2's stem as question 1 while keeping all three answers right. That is model
quality, not the plugin: the import window shows every draft before it writes a note, which is how
the repeated stem was caught, and nothing is written unread. On this machine the 7B model is good
enough to draft a short exam and not good enough to trust blind.

## Tests

`tests/import-note-split.test.js` pins the broken separator. `tests/import.test.js` gains three
cases: an echoing Stimulus section dropped (no section, no `stimulus_id`), a real passage kept
alongside a passage that only opens with the stem, and `carryPassages` skipping an echo.
`tests/api-client.test.js` pins the local deadline and `localProvider()` against the real settings
shape (`{ api: { provider: "ollama" } }`), which is the shape that was wrong. Two `every Tuesday`
cases in `tests/study-tasks-plus.test.js` expected the date they were written on; they now read a
fixed reference date (and, for the plugin path, the next Tuesday from today).

**3,036 tests pass, 0 fail. `npm run check` clean** (duplicate members, dynamic code, vendor hash,
startup budget, `main.js` up to date, plan status current).

No note format, setting key, review schedule or network default changed.
