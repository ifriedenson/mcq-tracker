# 1.301.17 — A stopped OpenCode stays stopped, and long checks keep counting

## What changed
- **Stop wins over an in-flight check.** `OpenCodeManager.stop()` now counts the
  stop (`stopMark`) and the kill itself moved to `terminate()`, so `ensure()`'s
  own restart is not mistaken for a user stop. A Stop press in Settings, or the
  plugin unloading, during the "is it still answering?" ping ends the check
  with "OpenCode was stopped before it finished starting. Start it again from
  Settings > Study agent > AI when you are ready." instead of starting a server
  behind the user's back (a late start could outlive the unloaded plugin).
- **The second ping is announced.** When a running server misses the first
  10-second check, the window says "OpenCode is running but didn't answer a
  quick check. Asking once more..." before the 1.5-second retry, so the bad
  case is no longer ten silent seconds.
- **No setup notice on every AI request.** `plugin.ensureOpenCode()` created a
  zero-duration "Setting up OpenCode..." notice on every call, and `aiChat()`
  calls it for every request, so each blind check in a batch flashed it. The
  notice is now created only when the server is not running; a real start,
  repair or restart still reports itself, including a restart that begins
  while the server looked healthy.
- **Long checks keep counting, and stopping ends them.**
  `verifyDraftQuestions(items, { onProgress, shouldStop })` reports its position
  and stops between notes. The import window uses it to name each AI-written
  answer being checked ("Checking answer 2 of 5 without showing the key...")
  and to stop paying for checks after it was stopped or closed. Notes the run
  never reached are left with no verification fields at all, not marked.

## Why
1.301.16 removed the 60-second cap on blind answer checks and made `ensure()`
ping a running server. Both are right, but their edges were rough: a Stop press
during the new ping was ignored, the bad case froze for ten seconds with no
text, every AI request flashed a setup notice, and a long batch showed one
frozen sentence while its checks kept running after the window was closed.

## Verification
- `tests/opencode-lifecycle.test.js`: a Stop pressed while `ensure()` checks a
  dead connection rejects with the stop message and leaves no process; the
  restart test also pins the "didn't answer a quick check" line; an already
  answering server shows no notice, a real start still does and is hidden.
- `tests/answer-verification.test.js`: a three-note batch reports 1/3 and 2/3,
  never sends the third check after the stop, and leaves that note unverified.
- Full suite and `npm run check` are re-run for this release.
- No note format, setting key, review schedule or network default changed.
