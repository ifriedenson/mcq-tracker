# 1.301.22 — AI failures say what to do next

The previous live passes left one surface undriven: what the assistant shows when
the provider cannot answer, or when AI is not set up at all. This pass drove it
in a real Obsidian 1.15.1 window against the same disposable vault, with a
stand-in provider that could refuse, reject a key, hang, or answer.

## What was driven

Quick Practice was started from a seeded question, answered, and **Ask AI** was
opened on the result. From there the same suggested action was sent under each
failure, and Retry was pressed from the error card:

- **Unreachable provider** (base URL pointed at a dead port): within 1.5 s the
  panel showed *That reply did not finish — Couldn't reach the provider. Check
  your internet connection and the base URL in settings.* with a **Retry**
  button. No notice, no console error, no spinner left behind.
- **Invalid API key** (provider answered HTTP 401): *The provider rejected the
  API key, or the key can't use this model. HTTP 401: Incorrect API key
  provided: …* with **Retry**. This is a different sentence from the network
  failure, so the two causes are not conflated.
- **Cancelled reply** (provider accepted the request and held it open): the
  **Stop** control was present while streaming; pressing it cleared the spinner
  and read *Stopped waiting for the reply.* with **Retry**.
- **No API key**: *Add your API key in the plugin settings.* with **Retry**;
  the panel's Settings gear is present.
- **AI turned off**: opening **Ask AI** now shows *AI is turned off. Turn it on
  in Settings → Study agent → AI and the assistant.* with an **Open settings**
  button, instead of only naming OpenCode.
- **Provider restored**: with the stand-in running again, Retry sent the same
  question and the reply rendered with Bookmark, Copy, Add to My Notes and
  Regenerate; the error card disappeared.

## The import preflight and a file that cannot be read

With AI turned off, **Import questions** still opens its preflight with its real
controls (Choose files, vault picker, Check this file, Cancel, Paste questions).
Choosing `Papers/broken.pdf` and pressing **Check this file** produced *This file
can't be read. I couldn't open that PDF. It may be damaged or password-protected.
Remove its password or export a new PDF with selectable text, then try again.
Nothing was added to your vault.* with **Choose another file**, **Cancel** and
**Paste questions instead (works offline)**.

`Papers/Unit A.pdf` produced *This file is readable. Read 1 page (105
characters). About 2 question starts spotted.* and **Continue to AI setup**
opened the **Connect AI to import a file** dialog in the main window with the
provider picker, key field, Fetch models, Test connection, Continue to import,
Paste questions instead and Close. That dialog turns AI on only when the user
continues, which is the existing import onboarding path.

## The fix

The AI-off panel was a dead end: a paragraph naming a settings path, with no
control and no way to open it, and it said *OpenCode* even for a Direct API
setup. It now says *AI is turned off* and draws **Open settings**, which opens Settings directly on the AI page. Code: `src/chat-panel.js`.

All other failure text was already specific and actionable; no change was
needed there. The 401-vs-network distinction is now pinned so it cannot regress
into one generic sentence.

## Tests added

- `tests/due-queue.test.js`: starting from a row or the bulk button calls
  `startQuickPractice` with `mode: "smart"`, so never-attempted questions in the
  listed queue are not filtered out, and cards still route to `reviewCard`.
- `tests/chat-panel-copilot.test.js`: the AI-off panel names the setting and its
  **Open settings** button calls the plugin opener with the AI page id.
- `tests/api-client.test.js`: an HTTP 401 is reported as a rejected key, keeps
  the provider's reason, and does not say the provider was unreachable.

The five-minute warning and the Recent files `openRow()` pins from 1.301.21
remain in `tests/practice-tools.test.js` and `tests/recent-files.test.js`.

## Verified live

  provider, 401, hanging provider + Stop, missing key, and AI off.
- Retry after restoring the stand-in rendered a reply and removed the error.
- Import preflight: unreadable PDF and readable PDF, both read as text with

- Tests: **2,792 pass, 0 fail**; `npm run check` clean across

## Limits

The native file picker is still not driven in the headless renderer; the vault
picker is the path used above, and the device picker was already covered in
previous passes. The 401 and hanging providers are local stand-ins with CORS
headers, since the renderer's streaming `fetch` requires them; Obsidian's
`requestUrl` paths (import, tests) do not.
