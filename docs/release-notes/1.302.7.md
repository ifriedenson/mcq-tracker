# 1.302.7 — Notes land in the vault no matter where OpenCode runs

## What the owner asked
Run the 100-PDF overnight queue end to end on the current build and report
per-file notes, failures and the morning log.

## What the run did
One hundred distinct one-page PDFs (`Bulk2/batch-001.pdf` …
`Bulk2/batch-100.pdf`, each with its own arithmetic and general-knowledge
questions) were queued with `startOvernightImport` against the 1.302.6 bundle
in headless Obsidian 1.15.1, with every free model exhausted. The queue
processed file 1, then parked with 99 files pending — the 1.302.5 design
working as intended instead of failing a hundred files.

Two defects surfaced, both fixed here:

1. **File 1 recorded done with 0 notes and no error, while two finished
   notes existed — outside the vault.** The agent's session shows completed
   `read`/`bash`/`write`/`edit` tool calls and a closing summary naming both
   notes (`BATCH-001-Q01.md`, `BATCH-001-Q02.md`) in `Questions/batch-001/`,
   but the vault folder is empty: the user-run server works in `$HOME`, and
   the prompt's vault-relative paths resolved against that directory. The
   files were found at `$HOME/Questions/batch-001/` with matching content.
   Earlier sessions of the same run wrote into the vault because their agents
   happened to discover absolute paths via shell commands first — per-session
   luck, not a guarantee.
2. **The write-side park recorded no reason.** Only the checks side stored
   `run.pauseReason`, so the morning log read a bare `status: paused` with
   `Files: 100 (1 done) · Notes: 0` and no explanation.

## What changed
- `runAgent()` passes absolute vault paths for the text file, the source
  copy, the images folder and the note folder (`absoluteVaultPath()` in
  `src/importer.js`, rooted at `plugin.vaultPath()`), and the prompt now says
  to use the paths exactly as written instead of claiming they are relative.
  Absolute paths resolve the same from any server working directory; the
  vault-side reads, note baseline and cleanup keep using vault-relative
  paths. Backslashes are normalized and already-absolute paths pass through.
- `pauseUnattendedForCap()` stores the provider's sentence as the run's
  pause reason, so the log prints it under the header on a write-side park
  too. Verifying the fix live caught the journal round-trip dropping the
  reason (`normalizeOvernightRun()` whitelisted it out): the reason is now
  part of the stored run, with a round-trip test, so a parked run still says
  why after a reload.

## Evidence
- Session inspection (message parts, tool states, completion times, closing
  summaries) plus files on disk outside the vault with matching content and
  an empty target folder inside it.
- `tests/importer-prompt.test.js` gains two tests: the path helper's join /
  passthrough / empty-root / separator behavior, and a prompt built with
  absolute paths containing them verbatim with no "relative" sentence.
- The re-run (below) resumes the parked queue on the fixed build.

## Checks
`node --test`: 2,895 pass, 0 fail. `npm run check`: clean. `main.js` rebuilt
from source. No note format, setting key, review schedule or network default
changed.
