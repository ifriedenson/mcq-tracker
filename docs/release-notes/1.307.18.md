# 1.307.18 — The stamp stops reaching your questions

Released November 17, 2026. Obsidian 1.15.1.

## Why

A downloaded exam PDF carries its host's furniture on every page. The 21-page Unit 4 exam used to
verify this release prints, on each of its 21 pages: `Downloaded by Bobby Joe
(hummingbirdrhino@gmail.com)`, the watermark id `lOMoARcPSD|64937195`, the running header `AP World
History: Modern Test Booklet`, the running title `AP World Unit 4 Exam`, a three-line College Board
copyright footer, and `Page N of 21`. All of it reached the model as if it were part of the exam, so
a note could pick up a stamp as a source line or a "Page 7 of 21" as text.

1.307.17 removed the QR code and its caption. This release removes the rest of that furniture.

## What changed

- **`repeatedFurniture(pages)` (`src/pdf.js`) names it from repetition alone.** A line is furniture
  when a whitespace-and-case-insensitive copy of it appears in the same top (≤10% of the page) or
  bottom (≥88%) strip on at least `max(3, 60% of pages)` pages. Nothing is keyed to a publisher's
  wording, so any site's download stamp is handled the same way; a document of one or two pages has
  no furniture to find and is untouched.
- **Only the margin copy is dropped.** `withoutRepeatedFurniture` removes a named line only where it
  sits in a band, so the same words in the body of a page stay. A heading shared by five pages of a
  long document, or a passage quoted twice, is below the threshold and stays wherever it is.
- **`isPageNumberLine(text, pageNumber)`** handles `Page 12 of 21`, `12 / 21`, `- 7 -` and `page 3`,
  and only when the number is the page's own — a printed page number never repeats, so repetition
  cannot find it.
- **Both copies of the text are cleaned.** The reading-order lines feed `page.text` (and therefore the
  AI prompt and the note bodies) and the gap lines feed the Quizlet/table reader; both are filtered
  with the same furniture set, and the whole document is read before any page text is built.

## Evidence

The attached PDF was not in this workspace, only its extracted text, so
`artifacts/pdf-import/unit4-pages.txt` transcribes its page-by-page content and
`artifacts/pdf-import/build-pdf.js` writes a real 21-page PDF from it with that furniture in the same
bands. `artifacts/pdf-import/run.js` reads those bytes through the shipping `readPdfPages`, using the
production chunking (`chunkPages(pages, 9000, 5)`), into `before/` and `after/`; `verify.js` compares
both against the transcription and writes `artifacts/pdf-import/report.md` (local evidence: the repo
keeps `artifacts/` out of git).

| | before | after |
| --- | --- | --- |
| characters on the 21 pages | 36,685 | 29,155 |
| download stamps | 21 | 0 |
| watermark ids | 21 | 0 |
| running headers | 21 | 0 |
| running titles | 21 | 0 |
| copyright footers | 21 | 0 |
| printed page numbers | 21 | 0 |
| QR captions (fixed in 1.307.17) | 0 | 0 |
| question stems | 31 | 31 |
| answer choices | 120 | 120 |

Every one of the document's own lines survives verbatim and every removed line is one of the five
furniture lines above: the per-page diff in `report.md` lists exactly those five on all 21 pages and
nothing else.

The startup gate's byte budget moved from 5,500,000 to 5,600,000 with the measurement recorded in
`scripts/check-startup-budget.js`: the pass added about 2.6 KB of pure logic to the already-eager
`src/pdf.js` and no module or dependency, so the measured eager load is 5,502,920 source bytes from
359 of 375 modules, with 1.8% of headroom left.

`tests/pdf-furniture.test.js` covers the stripper: a repeated stamp dropped from a three-page
document, a one-page line kept, a legitimate repeated line kept (in the body, and a heading shared by
five of twenty-one pages), one- and two-page documents untouched, a shared line kept where it appears
in the body, the printed page number dropped only on its own page, the table lines cleaned with the
same set, and `readPdfPages` end to end returning only the questions.

No note format, setting key, review schedule or network default changed.
