# 1.273.0 — Importer: service exports

Importer was Partial because it could read documents and card decks but not the note
services students actually export from. This release adds a dependency-free parser
for each documented text export and one note per record, so an export becomes a
folder of Markdown notes instead of a manual copy-and-paste job.

## What is new

- **`src/service-import.js`** (pure; no vault access) parses and converts:
  - **Evernote `.enex`** — `<note>` entries with their title, CDATA XHTML body, every
    `<tag>`, the `created` timestamp (`20260201T101500Z` → `2026-02-01T10:15:00Z`) and
    the source URL. Scripts, styles and tags are dropped; block elements become
    paragraphs and list items become bullets.
  - **Google Keep Takeout** — the JSON notes array (text plus `listContent` rendered as
    `- [x]`/`- [ ]`, labels, `createdTimestampUsec`, trashed notes skipped) and the
    single-note Takeout HTML page.
  - **Airtable** — `{ records: [{ fields }] }` JSON and CSV exports; the title, tags and
    created date are lifted out and the remaining columns become `## Column` sections.
  - **Notion** — database CSV exports and Markdown pages (`# Title`, a `Tags:` line,
    the page body).
  - **Bear Markdown** — the `# Title #tag` line, with inline `#tag` tokens moved into
    frontmatter and out of the body.
  - **Roam JSON** — pages as nested bullets, `#tag`/`#[[tag]]` tags and `create-time`.
- **Detection is content-first**: `detectServiceExport(text, filename)` recognises each
  format even when the file is renamed, and returns a reason instead of guessing.
  `.textbundle`/`.textpack` bundles are refused by name (they carry attachments this
  importer does not copy).
- **`recordMarkdown(record)`** writes `title`, `created`, `source_url`, `imported_from`
  and a `tags` list as frontmatter, then `# Title` and the exported body.
  `noteFileName`/`uniqueNotePath` produce vault-safe, collision-free names.
- **`src/plugin.js`** adds `serviceExportText`, `importServiceExport` (accepts
  `{ path }` or `{ text, filename }`, defaults the folder to `Imports/<Service>`,
  creates it, skips notes that already exist so a rerun never duplicates or
  overwrites, and reports what it wrote), `importActiveServiceExport`,
  `importServiceClipboard`, and the commands **Import notes from an export** and
  **Import notes from a pasted export**. Writes stay in `plugin.js`, the same
  documented vault-write path as every other importer.

## Tests

`tests/service-import.test.js` (15 tests) uses real-format fixtures: a two-note ENEX
export (entities, CDATA, list, tags, date, URL), Keep JSON with a checklist and a
trashed note, the Takeout HTML page, Airtable JSON and a CRLF CSV with quoted commas
and newlines, a Notion Markdown page and CSV, Bear Markdown with inline tags, and a
Roam JSON page with nested blocks. One test per format proves titles, bodies, tag
mapping and dates; refusals prove an empty file, invalid JSON, a header-only CSV, a
non-Bear Markdown file and an unknown format return a reason with no records; the
vault tests prove `importServiceExport` writes one note per record, creates the
folder, skips a repeated import, re-reads the unchanged notes, and writes nothing for
a missing file, an unsupported export or a bundle.

## Limits

Apple Notes (proprietary, undocumented database with attachments) and OneNote (binary
`.one` sections) have no documented text export this parser can read, so they remain
unsupported. Bear `.textbundle`/`.textpack` attachments and the Notion HTML/Markdown
ZIP bundle are not unpacked. PDFs and Office documents still go through the question
importer. No dependency, provider, account or network request was added.
