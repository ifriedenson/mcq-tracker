# 1.306.0 — A shorter ribbon: Today, Plan and Study

## What was asked
The ribbon had grown to 19 buttons (16 module views plus PDF++'s three
toggles). Merge related views into real tabbed hubs — buttons, not menus —
collapse the PDF++ toggles, and give every existing install the new layout
once. No feature may be lost.

## The layout

| Hub (one ribbon button) | Tabs |
| --- | --- |
| **Today** (sun) | Today · Study statistics · Pomodoro |
| **Plan** (calendar-days) | Calendar · Focus day · Review calendar · Local events |
| **Study** (workflow) | Study Workspace · Study Tools |

Standing alone: Practice, Cards, Reference, Assignments, Task list, next due
note, Review sidebar, Study agent, and one **PDF++ toggles** button. That is
**12 buttons instead of 19**.

## How it works
- `src/hub-view.js` — a `QtHubView` ItemView that renders a tab bar and one
  pane per enabled tab. Each tab mounts the **real view class** into its pane
  (`view.contentEl = pane`, then `onOpen()`), so nothing is reimplemented and
  child state survives switching: hiding a tab toggles `display`, it never
  destroys the child. `onClose()` closes the children; `render()` refreshes
  the mounted panes instead of rebuilding the frame.
- `src/hubs.js` — the three specs and their tabs, each tab carrying the same
  module getter the ribbon used, so a hub never offers a section whose module
  is off. An empty hub says exactly which settings turn it on, and
  `refreshHubLeaves()` closes a hub whose sections are all off.
- Commands keep their names and route to the right tab: `activateHubTab()`
  backs `activateToday`, `activateStudyStats`, `activatePomodoro`,
  `activateCalendar`, `activateFocusDay`, `activateReviewCalendar`,
  `activateLocalEvents`, `activateStudyTools` and `activateStudyWorkspace`
  (which still forwards its own sub-tab). A new **Open Plan** command opens
  the Plan hub.
- **PDF++**: the vendor's `addRibbonIcon` calls are captured by the host
  instead of drawing three buttons; one button opens a `Menu` with the three
  toggles, a separator and **PDF++ settings**.
- **Migration**: `ribbonLayout` defaults to `"grouped"` for every install.
  Settings → Global → **Ribbon layout** offers *One button per view*, which
  restores the exact long ribbon (commands still work in both layouts).

## Evidence
- `tests/hub-views.test.js` (7 tests): tab lists follow module switches, the
  grouped ribbon is short and classic restores every button, a hub mounts and
  switches real views without rebuilding them, an empty hub explains itself,
  module commands land on the right tab, an empty Study hub closes, and
  PDF++'s three toggles run from one menu.
- `tests/focus-day.test.js` now pins Focus day to the Plan hub (and to the
  classic layout when chosen); `tests/plugin.test.js` lists the three hub
  views and the new command; a `Menu` shim was added to the test harness.
- Capability inventory regenerated: 458 groups, 3,187 exports, 242 commands.

## Checks
`node --test`: 2,942 pass, 0 fail. `npm run check`: clean (startup budget
358 of 360 eager modules, 5,419,781 of 5,500,000 bytes). No note format,
existing setting key, review schedule or network default changed.

## Not verified
The hub frame was not looked at in a running Obsidian window in this
