# 1.257.1 — the lint sees every line, and the untested commands are tested

## The dynamic-code lint was blind to most of `plugin.js`

`scripts/check-no-dynamic-code.js` masked comments and string literals before matching, but it
treated every `/` as division. A regex literal containing a quote, a backtick or `//` therefore
opened a string or comment frame that swallowed the code after it: `src/plugin.js` measured
**17.1% code**, and both `requestUrl` calls sat inside a phantom string, so an `eval`, a
`new Function` or a string timer later in the file would not have been reported.

The masker now tokenizes regex literals. It decides from the previous significant token whether a
`/` opens a regex or divides (so `total / 2` stays division and `/^##\s+/` after `[`, `(`, `,` or
`return` opens a regex), skips escapes and character classes, and keeps regex bodies counted as
code so a sink spelled inside one is still reported. Whitespace no longer overwrites that
previous token, which is what made `/x` after `[\n  ` look like division.

`src/plugin.js` now measures **84.3% code**, and both `requestUrl` call sites are inside the
scanned surface. This is a fix to the checker, not to shipped behaviour: no `src/` file changed.

`tests/dynamic-code-lint.test.js` (7 tests) fails against the old masker. It places a dynamic-code
sink after a regex holding a backtick and after one holding a quote (both invisible before),
checks that division is not read as a regex, proves regex bodies stay scanned, asserts a coverage
floor of 60% for `plugin.js`, asserts that every `requestUrl` line is code, and asserts that the
tree scan covers every source file. `docs/security-inventory.md` now describes what the scanner
does instead of the limit it worked around.

## The commands the inventory listed as untested are now exercised

`docs/capability-inventory.md` listed 30 command-palette commands with no test that named them.
`tests/command-effects.test.js` (30 tests) runs each registered callback and asserts its observable
effect: the method it delegates to and the arguments it passes (`open-time-blocks` →
`activateStudyWorkspace("timeBlocks")`, `sync-cards-anki` → `openAnkiConnectPush({ sync: true })`,
`add-fields-all` → `addMissingFields` with every question file). The five commands that only exist
on a note — `toggle-flag`, `add-fields-this-note`, `calendar-class-attended`,
`calendar-class-absent`, `lecture-practice` — are also asserted at their guard: unavailable with
nothing open, no write while the palette is only checking availability, and the open file handed to
the tested function when run.

`tests/uncited-groups.test.js` (9 tests) drives 14 previously uncited pure groups with real input:
the quick-practice option lists, `fmtDateTime`, the 1–10 exam-ready clamp, `cloneFilters` and
`hasFilters`, `matchFilters` (OR within a field, AND across fields, honoured skip),
`weightOf` (missed, unseen and flagged), `statVals` (one folder per note, list values kept), the
quick-session pack/unpack refusal paths, and a timed session counting down, pausing, resuming and
expiring.

The inventory now records **150 commands, all cited, and 43 groups with no citing test**, each
listed with the reason it is not separately tested (modal and dock shells whose callers are covered
by the command tests, and internal helpers reached only through a tested path).

`tests/capability-inventory.test.js` now also requires every command to be cited, checks that each
cited test file exists and really mentions that command or its callback, pins the 43 remaining
groups, and asserts two claims that were previously checked only by reading code: the README's
twenty-one Study Workspace tabs against the tabs the view registers, and the settings headings the
README describes against the headings the settings code draws.
