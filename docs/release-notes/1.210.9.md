# MCQ Tracker 1.210.9

Two local candidates from the academic-plugin backlog, both read-only or
contained: renaming a task tag, and a glossary built from notes you already
write.

## Rename a task tag

The Study Workspace **Tasks** tab gains a **Rename a task tag** card.

- It lists the tags in use with their counts, then takes a **Tag to rename**
  and a **New tag name**.
- The rename applies to the local study tasks only. Matching is
  case-insensitive, so `#Math` and `#math` are the same tag.
- A task that already carries the new name keeps one copy instead of gaining a
  duplicate, and the existing four-tag limit still applies.
- An empty tag, an unchanged tag or a tag no task uses is refused with a
  message instead of writing anything.
- Notes, frontmatter and other plugins' tags are never read or rewritten. This
  is deliberately not a vault-wide tag merge.
- The add-task form also takes optional tags, so a task can be tagged here
  rather than only in the sidebar list.

## Glossary from your notes

The **Vocabulary** tab gains a **Glossary from your notes (read-only)**
disclosure.

- **Build glossary** reads the vault's Markdown for `Term: definition` lines
  (including bullets and blockquotes) and for two-column tables such as
  `| Term | Meaning |`.
- Frontmatter, fenced code, headings, checkbox lines, a table's own header row
  and URL-shaped pairs are skipped, so examples and links are not turned into
  definitions.
- The first definition of a repeated term wins; later copies are counted as
  duplicates rather than merged.
- The lookup ranks an exact term first, then a prefix, then a match inside a
  term, then a match inside a definition.
- Every row shows its note path and line number with **Open note**.

## Boundaries

- No note is edited, rewritten or reopened, and no word leaves the vault: this
  replaces an external dictionary request rather than making one.
- No new dependency, setting, network request or background index was added.
  Both surfaces live inside modules that are already opt-in.
