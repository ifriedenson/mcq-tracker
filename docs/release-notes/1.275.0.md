# 1.275.0 — Plan sweep: every remaining row is a recorded gate

The plan is the product source of truth, so this release reads it top to bottom and
makes it honest at the current version. It found no unimplemented local work: the
plan holds **0 unchecked items and ten `[~]` partials**, and each partial is blocked
by a named gate rather than by missing code. No plugin behaviour changed.

## What the sweep verified

- **0 unchecked `[ ]` items** and **10 `[~]` partials**, matching §3.9.6 and §11:
  the real-Obsidian visual/math check, the real iOS/Android audit, README
  screenshots, TTS/audio and pronunciation, the bundled OCR engine (and the
  course-note summary and paper-scanner remainder that depend on it), the AP FRQ
  human-scored calibration, and Code Runner (resolved as no in-plugin execution).
- **Nothing claimed as unreleased is missing from the bundle:** the Qwen preset is
  in `src/api-client.js`, the local `chem`/`biology`/`biosequence`/`circuit`
  blocks are in `src/stem-diagrams.js`, and all fourteen `canvas-*` commands and
  their `src/canvas-*.js` modules are in the shipped 1.274.0 build.
- **D5 (Hold Course / uni-calendar read-only interop) was re-checked and stays
  gated.** Hold Course stores its semesters, classes, lectures, assignments and
  exams in its plugin `data.json` and only writes a generated syllabus note;
  uni-calendar fills lecture notes from a user-defined template. Neither publishes
  a stable note schema, so a parser would be a guess. The row now records that and
  asks for the owner's own note or export.
