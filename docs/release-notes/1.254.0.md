# 1.254.0 — A launch link and a named link keep their kind

Released Nov 4, 2026.

## What changed

- **A launch link is retargeted in place.** `updateLink({ target: "launch", file })` writes
  `/A << /S /Launch /F << /Type /Filespec /F (path) /UF (path) >> >>` onto the same annotation and
  deletes any old `/A` or `/Dest`, so the link still launches a file instead of becoming an address
  or a page jump. The path is carried as a file specification's `/F` and `/UF` strings (hex strings,
  so a non-Latin-1 path survives), which is the form `linkFileSpec` already reads. The result reports
  `target: "launch"`, `file` and `fromKind`, and `readLinks` reads the same path back.
- **A named destination is renamed in place.** `updateLink({ target: "named", name })` writes
  `/A << /S /GoTo /D <name> >>` — a PDF name when the destination is a token, the destination's text
  otherwise — replacing a direct `/Dest` entry on the same annotation. `readLinks` reports
  `target: "named"` and the name, so a re-read returns exactly what was set. `/S /Named` is PDF's
  named *action* (`NextPage`, `Print` …), not a destination, and it stays refused as an action this
  editor does not rewrite; a named destination is a go-to with a name, which is what 1.251.0 already
  read as `named`.
- **A target alone picks the kind.** `{ file }` means `launch` and `{ name }` means `named` when no
  `target` is given, so the engine cannot silently fall back to a URL. Addresses and page jumps
  retarget exactly as before (`target: "url"` / `"page"`, or `{ url }` / `{ to }`).
- **The kind survives every other edit.** A move, a resize, a width change, a border style, a custom
  dash with its phase, a highlight change and any other style edit never touch the action, so a
  launch link stays `/Launch` with its file and a named link stays `/GoTo` with its name. One undo
  step; only **Save a copy** writes.
- **The editor row.** **Change link** gains a **Change to** select (Address, Page, Launch, Named) with
  **File path** and **Destination** fields; the status reads `now opens chapter2.pdf` or `now opens
  the destination Chapter 4` (and still `now opens https://…` / `now jumps to page 3`), and the
  change hint says a launch or named link keeps its kind instead of being replaced.
- **Remote go-tos are still converted,** deliberately: a `/GoToR` names a destination in *another*
  file this editor never opens, so it cannot verify the page or name it would write. Retargeting one
  still converts it to an address or a page jump, and the notes and mission record say so.
- **Refusals, each with a message and no byte change:** a launch path that is empty, not a single
  string, over 2,000 characters or containing a NUL/control character; a destination name that is
  empty, not a string, over 200 characters, containing a control character or a slash; a payload
  supplied for the wrong kind (a file path or a name on an address or page link, an address, a page
  or a name on a launch link, a file path, address or page on a named link), and an unknown `target`
  kind. Every 1.253.0/1.252.0 refusal still stands — the border, dash and phase rules, `custom`
  without a pattern, a pattern without the custom dash — as do the five deliberate refusals and the
  `/JavaScript`-style action refusal.

## Verification

- Four new tests were written first and run against 1.253.0: engine `# tests 3 / # pass 0 / # fail 3`
  and window `# tests 1 / # pass 0 / # fail 1`. The engine returned `ok: false` for every launch and
  named retarget (`[false, undefined, undefined, undefined]`), and the window printed the real
  status `A link opens an http or https address only.` because `target: "launch"` was coerced to a
  URL. After the change: engine **87 pass / 0 fail**, window **24 pass / 0 fail**.
- What they assert: a launch retarget emits `/S /Launch` with a file specification whose `/F` reads
  `chapter2.pdf`, and the link re-reads as `launch` with that file; a named retarget of an action
  destination emits `/GoTo /D /Chapter4`, a retarget of a direct `/Dest` replaces it on the same
  annotation, and both re-read with their new names; a launch link keeps its file and its `/Launch`
  through a custom dash with phase 3, an outline highlight, a new area and a move to page 3, and
  every bad path, bad name and wrong-kind payload is refused while the document's bytes stay
  identical; the window test drives **Change to Launch** and **Change to Named** on a real built
  `main.js`, styles the launch link, refuses a slashed name with a message, saves a copy and re-reads
  both kinds, both targets, the width, the dash pattern and its phase.
- Full suite **1923 pass**, `npm run check` clean across **297 source files**, `main.js` current
  across **298 modules** at **4,972,820 bytes**, and `git diff --check` clean.

## Limits

- A launch path is whatever the PDF names; the editor does not check that the file exists, is a PDF
  or is reachable from the reader — the viewer resolves it.
- A remote go-to is still converted rather than rewritten (see above), and a link whose action is
  `/JavaScript`, `/SubmitForm`, `/Named` or another unmodelled kind is still preserved and refused
  for retargeting.
- The five deliberate refusals (XFA, encrypted files, rewording text, hierarchical field names,
  guessing bookmark views) are unchanged.
