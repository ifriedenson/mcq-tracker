# 1.276.0 — Plan decision sheet, and three rows closed on recorded decisions

The plan had no implementable work left, but ten `[~]` rows all looked like open
questions. Re-deriving each row against §11 showed that three of them were not
open at all: they were waiting on a licence review the owner had already decided,
in §11 **E3** ("keep the opt-in BYOK vision path and state that no bundled OCR
engine exists", Nov 1, 2026). The same blocked table row also carried PDF form
filling, which §11 **E4** reversed on Nov 4, 2026 and 1.218.0 shipped.

So this release closes those three rows with the decision that already resolved
them, and turns the remaining seven into something answerable in one sitting.

## Closed: the OCR trio

| Plan row | Why it closes |
|---|---|
| 2702 — AI summary and key terms for course notes | Shipped in 1.44.0; the only stated gap was the bundled engine, declined by E3 |
| 2703 — Paper scanner: photos to one PDF | Shipped in 1.46.0; same gap, same decision |
| 2704 — OCR for image-only scans | The BYOK vision path, editable per-page text and the Markdown OCR note shipped; E3 makes "no bundled engine" the answer rather than a pending gap |

No code changed for these. §3.9.6's combined "PDF form filling, bundled OCR
engine, and the OCR-dependent course-note summary and paper-scanner remainder"
row is struck as resolved with both decision citations, §3.9.10's gate cell is
corrected, and the **Current focus** bullet that still said "licensed review" is
gone.

## New: `docs/plan-decisions.md`

One section per still-gated row — math/chemistry visual audit (§5.16.1), real
iOS/Android audit (§5.19), README screenshots (§10b), TTS and the audio-only
commute (§5.22.4), pronunciation feedback (§5.22.4), the AP FRQ accuracy claim
(§5.20) and the pilot go/no-go thresholds (§7 Phase 2b) — each with the plan row it comes from,
the single decision, its options with a recommended default and why, and what
closes once answered. Option A in every section is the "do nothing new" default,
so answering "all A" closes the plan without a dependency, provider or account.

It also carries a table of the adjacent §11 owner questions that gate future work
(O1, O2, O4, O5, O9, O10, O11, O12, D5, E11) with their already-written defaults,
so the whole set can be answered together.

The sheet is linked from `AGENTS.md` **Current state**, from **Current focus**,
from the §3.9.6 blocked-row introduction, from §3.9.10 and from §11, so a fresh
chat finds it without reading the plan end to end.

## Limits

Closing the OCR rows is a correction of the plan's wording against a recorded
decision, not a capability claim: there is still no bundled OCR engine, and
offline image-only scans remain unsupported. Nothing here moves any visual,
device, accuracy or calibration gate — those stay open until the owner answers
the sheet.
