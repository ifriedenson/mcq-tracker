# 1.252.0 — Every link border style is editable

Released Nov 4, 2026.

## What changed

- **A link's border style is readable.** `readLinks` reports `style.border` — `solid`, `dashed`,
  `beveled` (`/B`), `inset` (`/I`), `underline` (`/U`) or `other` for a `/BS /S` name outside those
  five — and `style.pattern`, the `/D` dash lengths (`[]`, `[6 4]`, `[2 3]` or a custom pattern)
  beside the width, dash and highlight it already reported.
- **And editable in every one of them.** `updateLink({ style })` takes an optional `border`
  (solid/dashed/beveled/inset/underline) and an optional `pattern` (1 to 8 lengths, each above 0 and
  at most 100, as numbers or a `"7 3"` string), and accepts a `dash` of `custom` for the first time.
  A width change on a `/B`, `/I` or `/U` link no longer refuses: it writes `/W` and keeps the style
  name. A `custom` dash writes `/BS /D` plus the same lengths in `/Border`, and keeps the style the
  link already had.
- **The returned style is what a re-read gives.** `updateLink` reports `border`, `dash` and `pattern`
  after normalising, so choosing `dashed` returns `border: "dashed"` and `pattern: [6, 4]`, and a
  custom pattern on a beveled link returns `border: "beveled"`, `dash: "custom"`, `pattern: [7, 3]`.
  Moving the box, moving to another page, retargeting the action and removing the link all keep the
  border, width and pattern untouched.
- **The editor row.** **Add content → Links** gains a **Border style** select (keep, solid, dashed,
  beveled, inset, underline), **Dash** gains `custom`, and a **Dash lengths** field takes the pattern
  for it; the hint names the selected link's border, dash and pattern. The status reads
  `now has a 3-point beveled border` or `a 3-point dashed border with a custom dash (7 3)`. One undo
  step, and only **Save a copy** writes.
- **Refusals, each with a message and no byte change:** a border word outside the five, a dash word
  outside solid/dashed/dotted/custom, `custom` with no pattern, a pattern entry that is not a number,
  not above 0 or over 100, a pattern longer than 8 lengths, and a pattern given without the custom
  dash. An unknown `/BS /S` style (`/X` and the like) is not refused: it is read as `other`, a width
  change keeps it exactly, and choosing a style replaces it.

- Six new tests were written first and run against 1.251.0. Engine:
  `# tests 5 / # pass 0 / # fail 5` — `link 1 accepts a width` reported `false !== true` (the old
  `/B` refusal), and every row read back without `border` (`+ actual` began at the width, where
  `- 'beveled'` was expected). Window: `# tests 1 / # pass 0 / # fail 1` with
  `both border styles are readable` failing the same way. After the change: engine **81 pass /
  0 fail**, window **22 pass / 0 fail**.
- What they assert: `/B`, `/I`, `/U` and a `[5 2]` custom dash read as `beveled`, `inset`,
  `underline` and `dashed`/`custom` with their patterns; a width change on each writes `/W 4`, leaves
  `/BS /S` as `/B`, `/I` and `/U`, and re-reads the same styles with the box and target untouched; a
  beveled link takes a new rectangle and a page-jump retarget and still saves `/B` with width 2, and
  the links left behind keep their own borders after a removal; a chosen `custom` dash `[7 3]` writes
  `/BS /D [7 3]` and `/Border [0 0 3 7 3]`, survives a width change and returns to `solid` with an

  `/BS /S /X` link keeps `/X` through a width change while reading as `other`.

## Limits

- A custom dash is a list of lengths only; the `/D` phase offset is not editable.
- A `/BS` style outside the five named ones stays `other` and is preserved until a style is chosen;
  it is not interpreted.
- Launch, remote go-to and named destinations are still converted rather than rewritten (1.251.0),
  and actions this editor does not model are still preserved and refused for retargeting.
