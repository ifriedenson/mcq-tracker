# 1.307.13 — One pane, one row

Released November 16, 2026. Obsidian 1.15.1, Primary theme, fresh private Xvfb session at 1280×900 and 390×844.

## Why

Every capture in `artifacts/ui-quality/runs/` showed the Plan, Study and Today hubs sitting above three
empty-looking rows. The hub itself was only ~150px tall, its calendar was cut off, and the audit's JSON
described the last visible leaf (`rootBox` y=711, h=178, empty text) rather than the hub it claimed to test.
The task list's `task-list-1280-light.png` was a New tab, not the task list.

## What changed

- **A hub mounts into its own pane.** Obsidian's `View` constructor gives every new view its own
  `.workspace-leaf-content` inside the leaf it is handed. The hub handed every tab the hub's own leaf, so
  Plan drew four 149px wrappers under its tab bar and took what was left. `mountPane` now records the leaf's
  children before the mount and removes only the wrappers that mount added; the child still renders into the
  hub's pane. The hub leaf measures 744px again and there is exactly one `.workspace-leaf-content` in it.
- **Muted ink clears AA.** `--text-muted` measured 4.21:1 light / 4.06:1 dark across weekday labels, mode
  tabs, planner hints and Today's small print (14–22 labels per hub). One computed token,
  `--qt-read-text-muted` (the same 55/45 mix the chat hint already used), now feeds `--text-muted` inside
  `.qt-root`, so every plugin surface uses one readable mix rather than another per-class colour.
- **The 390px calendar header keeps one row.** Six 44px controls plus the month title cannot share 273px, so
  the settings gear hung past the card edge. Under 520px the controls now share one flex row, tighten their
  padding and keep a 32px+ target; the gear sits inside the card.
- **The evidence measures the surface it names.** `tools/ui-audit/run.mjs` collapses a leaf-stacked layout
  before a run, targets the active leaf for command jobs, measures `.workspace-leaf.mod-active .view-content`
  by default and accepts a `script` step; `tools/ui-audit/jobs-hubs.json` gives each hub its `viewType`.

## Evidence

Regenerated on the shipped build: `today-hub`, `plan-hub`, `plan-hub-dark`, `study-hub`,
`plan-hub-narrow` and `today-hub-narrow`. Every run reports the hub's own `view-content` at full height
(1266×806, or 381×750 at 390px), 0 clipped controls, 0 sub-32px controls and 0 contrast failures in both
themes. `plan-hub-narrow-390-light.png` shows all six header controls on one row inside the card.

The empty `task-list-1280-light.png` was removed; its 38 state screenshots are unaffected.

## Checks

`node --test`: 3,001 pass, 0 fail. `npm run check`: clean. No setting key, note format, review schedule or
network default changed.
