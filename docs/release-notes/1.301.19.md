# 1.301.19 — the whole plugin, driven in a real Obsidian window

The build was driven in an actual Obsidian 1.15.1 window (Ozone headless, CDP,
a disposable vault, a stand-in OpenAI-compatible provider) across every surface
it registers. Three defects turned up that no test had caught, and each is fixed
here at its cause.

## What was driven

- **All 233 command-palette entries** executed in the live app, one at a time,
  with the open modal recorded and closed between commands. 36 opened a dialog;
  every one rendered content and closed.
- **All 21 plugin view types** opened in a tab, read, reopened and closed
  (the 22nd view in the registry is Obsidian's own PDF view, not this plugin's).
- **All 53 Settings pages** walked through their four category tabs, with the
  text of each page checked for empty panels and raw runtime strings.
- **The import flow** through its real popout: a vault PDF was read locally, a
  stand-in provider wrote two answers the AI had to stand behind, and the blind
  check was watched to its end — `Checking answer 1 of 2 without showing the
  key...` then `Checking answer 2 of 2 without showing the key...`, both notes
  then reading `answer checked`, and **Create 2 notes** writing them.
- **Settings persistence**: a toggle changed through the Settings window was
  found in `data.json`, survived a full app restart, and came back on in the UI.

## Fixed

- **Adding a note to whole-note review threw a ReferenceError.** `addNoteToReview`
  called `noteReview.isNoteCandidate(...)` on a name that was never imported
  (`isNoteCandidate` lives in `src/note-review.js`). Every entry point into that
  command — the palette entry, the file menu, the review sidebar's plus button
  and Settings → Review → **Add this note** — failed with
  `ReferenceError: noteReview is not defined` and changed nothing. It now imports
  and calls `isNoteCandidate`, and the live window added a note to review with
  `note_review: true` and a first `next_review` date.
- **The assignment dialog crashed on open.** `AssignmentModal` set its four
  numeric fields through `points.inputEl.type` / `score.inputEl.type` /
  `weight.inputEl.type` / `estimate.inputEl.type`, but those helpers already
  return the `<input>` itself, so `.inputEl` was `undefined` and opening
  **Assignments: add an assignment** threw
  `TypeError: Cannot set properties of undefined (setting 'type')` before the
  dialog could draw. The four fields now set `type` on the element, and all four
  render as number inputs in the live dialog.
- **A vault file handed to the importer failed with a raw runtime string.** The
  importer's `file` option assumed a device `File` with `arrayBuffer()`; passing
  an Obsidian `TFile` reached the reader and failed with
  `Couldn't import opts.file.arrayBuffer is not a function`. A file with a path
  and no `arrayBuffer()` is now routed through the vault reader, and a
  file-like object with no bytes says "That file has to be chosen from this
  device again" instead of naming an internal property.

## Pinned

- `tests/feature-surfaces.test.js` now opens the assignment dialog and asserts
  its four numeric fields are number inputs, and adds a real note to whole-note
  review and asserts the frontmatter it writes.
- `tests/import-source-routing.test.js` covers the vault-file route, the device
  file route and the no-bytes message.

## Known limits of this pass

- Obsidian notices are not present in the headless renderer's DOM, so notice
  text was not read from the screen; surfaces were judged by their dialogs,
  views, settings pages and written notes.
- The 233 commands ran with the native file chooser patched to cancel, so each
  picker's cancelled path was exercised rather than a real OS dialog.
- Five dialogs open with no buttons of their own on an empty vault
  (`pdf-annotate`, `pdf-draw`, `practice-folder`, `open-due-queue`,
  `find-question`); each explains the empty state in its body, and the file
  pickers among them were reached only as far as their cancelled path.
- A single `renderMarkdown` component warning was seen once during the sweep and
  did not reproduce across four markdown-rendering surfaces afterwards.

No note format, setting key, review schedule or network default changed.
Tests: **2,786 pass, 0 fail**; `npm run check` clean across **361 source files**; `main.js` **7,270,591 bytes** from **364 modules**.
