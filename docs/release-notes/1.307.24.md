# 1.307.24 — The week timetable, semester rollover, and Undo on every task edit

Released November 19, 2026. Obsidian 1.15.1 (headless harness; no app window was
available, see Limits).

## Why

An audit of the repository against `plan.md` was run because the plan claims
**0 unchecked rows and 0 partial rows**. Re-reading every non-✅ row, every
captured idea set and every gate produced the real remainder:

- **Adapted (◐) rows**: per-message rollback of every editor change, and an
  inline diff drawn in the editor. Both are deliberate presentation limits of
  the review-modal design and are unchanged here.
- **Captured, not approved idea sets**: §5.22 Class Timetable 2.0 (4 ideas)
  and §5.22 Doable (4 ideas).
- **13 gated rows**: each needs a provider, credential, device or owner decision
  (`plan.md` §3.9.6).

Three of the captured ideas were locally implementable, use stores the plugin
already has, and the plan ranked them as the cheapest and most visible gaps, so
they ship here. The rest stay captured and are listed under "Still open".

## What shipped

### 1. A real week timetable for the one merged calendar

`src/calendar-week.js` is pure layout: `weekStartKey` (Monday, or Sunday when
that is the calendar's first day), `weekDayKeys`, `weekLabel`,
`clockMinutes`/`rowMinutes`, `layoutDay` and `buildWeek`. `CalendarView` gains a
**Week** mode beside Month, Day and Upcoming.

- The grid is a real clock: one column per weekday, one row per hour, and each
  class, planned block, local event, review-due row and dated task sits at its
  own time. A row with no time waits in the all-day strip at the top of its
  column.
- Overlapping rows are split into lanes, so a 09:00 lecture and a 09:30 seminar
  each take half the column instead of hiding one another.
- The axis starts at 07:00 and ends at 22:00, and widens only when something
  actually sits outside it (an 06:30 lab, a 23:30 event), never squeezing a real
  block out of view.
- A now-line marks the current time in today's column and is repositioned every
  30 seconds without rebuilding the view; a date change rebuilds it.
- Each day header is a button that opens that day, and so is every block, so the
  week is a way into the day view rather than a dead picture.
- `Calendar: open the week timetable` (`open-calendar-week`) opens it through
  `openMergedCalendar({ mode: "week" })`, the same route the other calendar
  entry points use. No second schedule store, no new property and no settings
  key: the grid reads the same enabled layers as the month view.

### 2. Start the next semester in one command

`rolloverCourses(value, label)` (`src/calendar-model.js`) stamps `semester` on
the courses that never had one and leaves labelled courses alone.
`plugin.rolloverSemester({ label, start, end })` then points the term window at
the new dates, and `Courses: start the next semester` opens a three-field dialog
(semester label, start, optional end) through `SemesterRolloverModal`.

- Only the blank labels are filled; a course already marked `Fall 2025` keeps
  its term, and the count of stamped and skipped courses is reported.
- The start date is required and validated; an end date before the start is
  dropped rather than stored backwards.
- Notes, lecture history and imported `.ics` events are not moved, rewritten or
  deleted. Old classes simply fall outside the new term window, which is what
  makes the calendar start the term empty.

### 3. Undo on every task edit, not only on delete

The sidebar task list could complete, reopen, star and change a repeat in one
click with no way back; only delete had an Undo. `deleteWithUndo` now accepts
the notice text instead of always saying "Deleted", and a new
`plugin.updateStudyTaskWithUndo(id, patch, onChange, text)` routes an edit
through the same helper.

- Completing a task shows `Completed “<task>”.` with the usual eight-second
  Undo. For a repeating task the successor it just scheduled is removed with it.
- Reopening, starring/unstarring and cycling the repeat each show their own
  notice and restore the whole task store.
- Undo refuses if anything else has touched the tasks since the edit, so a later
  change is never silently overwritten, and the Undo disables itself after use.

## Tests

The suite is **3,068 tests, 0 fail**, and `npm run check` is clean.

New and extended coverage:

- `tests/calendar-week.test.js` — Monday/Sunday week starts, week labels across a
  month and a year, clock parsing, lane splitting for overlaps and sequential
  rows, the all-day strip, axis widening, the now-line position, the default
  07:00–22:00 axis, and a row that ends before it starts.
- `tests/calendar.test.js` — a view-level pass: the Week tab renders seven day
  columns, the class becomes a positioned button block, opening it selects that
  day, and `open-calendar-week` is registered.
- `tests/semester-rollover.test.js` — only unlabelled courses are stamped, the
  term window moves, an unusable start changes nothing, and an end before the
  start is dropped.
- `tests/task-list.test.js` — completion Undo restores the task and removes the
  repeat's successor; star and repeat Undo each put their field back.
- `docs/capability-inventory.md` is regenerated from the bundle (463 groups,
  3,228 exports, 244 commands), so the new module, exports and two commands are
  recorded rather than assumed.

## Still open

- ◐ **Inline diff in the editor** — the diff stays in the transcript card and

- **Class Timetable #2** class-held dots on the course hub and **#4** week image

## Limits

No Obsidian window was available in this environment. The week grid was driven
through the real `CalendarView` and the headless DOM harness, which proves the
mode, the seven columns, the positioned block, the day hand-off and the command;
it was **not viewed in Obsidian**, and no screenshot is claimed. The semester
dialog's own fields were not clicked through in an app window either; the
behaviour behind it is covered by `tests/semester-rollover.test.js`.

No note format, existing setting key, review schedule or network default
changed. The calendar's term dates and course labels were already stored.
