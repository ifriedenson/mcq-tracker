# MCQ Tracker 1.204.0

Explicit 3D surfaces in the Reference panel.

## What changed

- A new **3D** tab renders an explicit surface `z = f(x, y)` with a local
  software ray-marcher. It has a finite x/y/z bounding box, a camera with yaw,
  pitch and distance, orbit/tilt/zoom buttons and a one-click reset.
- Points are entered as `x, y, z`, separated by semicolons or new lines. Each
  visible point is projected into the image and labelled `P1`, `P2`, and so on.
- The renderer is deliberately bounded: a 320 by 200 image by default, at most
  80,000 pixels and at most 160 ray steps, so a difficult surface cannot lock
  the editor. It uses no WebGL, mesh library, network request or `eval`.
- The surface, box, camera and points are saved in
  `settings.reference.threeD`. Invalid expressions, bounds or points are
  reported in the polite status region and do not replace the last valid view.
  Older saved settings open the default `z = x^2 + y^2` bowl.
- The pure ray-marcher and camera math live in `src/graph-3d.js`; the tab
  markup and canvas adapter live in `src/graph-3d-panel.js`.

## Verification

- `npm test` passes: **1,493 tests, 0 failures**.
- `npm run check` passes: no dynamic code and `main.js` matches `src/` across
  **250 modules**.
- Focused coverage: deterministic explicit-surface rasterization, the pixel cap,
  bounds and camera normalization, point parsing and projection, the 3D tab
  render path, point/camera persistence, and invalid surface handling without
  replacing the previous surface.

## Licence

No dependency was added and no third-party code was copied. The ray-marcher,
camera and shading are written locally; expression compilation reuses the
existing restricted parser.

Known limitations: this release exposes explicit surfaces only; implicit
`F(x,y,z) = 0` surfaces are queued for 1.205.0. The image is intentionally
low-resolution, and export, print and a live Obsidian visual pass are not part
of this release.
