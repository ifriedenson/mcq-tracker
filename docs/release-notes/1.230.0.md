# MCQ Tracker 1.230.0

This release makes **Duplicate page** produce a live, fillable copy of a form
page instead of a flattened picture of its values. It closes the limit named in
the 1.229.0 report: a duplicated fillable page can now be filled independently
of the source, and button, signature, XFA and unsupported constructs are refused
as a whole rather than producing blank or orphaned fields.

## What changed

- Duplicating a page copies its widget annotations with the page, then clones the
  terminal field behind each widget. Each clone is registered in the document's
  AcroForm `/Fields`, its `/T` is a deterministic unique name (`student_2`,
  `student_3` …), its `/V` keeps the source value, and the copied widget's
  `/Parent` and `/P` point at the clone and the duplicate page. The copied
  widget's `/AP` appearance is preserved, so the duplicate renders with the same
  value before any editing.
- The source page, source field dict and source widget are never modified. The
  duplicate can be filled without changing the source, and both values survive
  save and reload.
- Repeated duplicates and collisions with existing top-level field names resolve
  deterministically and case-insensitively. Every duplicate gets a distinct
  field; a duplicate of a page with two fields gets two new names.
- Non-widget annotations on the page (links, highlights and comments) are copied
  with the page and are not mistaken for widgets.
- The result keeps the caller-compatible shape: a live duplicate reports
  `flattened: false`, `liveForm` and the number of cloned `fields`; refusals keep
  `reason: "form"`.
- The Duplicate status says the live fields were copied with unique names and the
  source form stays untouched. Move still reports its live-page behavior.

## Unsupported-field policy

The policy is **refuse the whole duplicate**, not a partially flattened page:

- An XFA form refuses with a message naming **Duplicate-page**.
- A page whose widget belongs to a button, signature, or any field kind this
  editor cannot safely clone refuses with `reason: "form"` and a message naming
  **Duplicate-page**.
- A widget annotation that is not registered in the AcroForm, or a copied widget
  that cannot be paired with its source field, also refuses.
- Refusal happens before the page is inserted or any field is registered, so the
  page count, source values and live form are unchanged. There are no blank or
  orphaned fields.

This is deliberate: a partial flatten would leave the page with a mix of live and
dead fields and a status that could not be trusted. Extraction, split and merge
keep their separate flatten-on-copy policy, and Move keeps its live-page object
move; neither path changed in this release.

## Honest limits

- Button, signature and XFA fields cannot be duplicated live; this release
  refuses the whole duplicate for those pages rather than flattening them.
- A field with several widgets is cloned per widget on the copied page: each
  copied widget becomes its own uniquely named field with the source value. The
  source field and its other widgets stay untouched.
- Encrypted PDFs remain unsupported, as before.
- Saving still writes a new `name (edited).pdf`; the source PDF and its sidecar
  are never changed.
