# 1.301.29 — An import cannot sit on a silent agent forever

## What the owner saw
The second PDF of a batch: the folder and the copied PDF appeared, **no notes were
written, and nothing happened for ten minutes**. The answer-check recovery from
1.301.27/28 never ran, because the file was still in the agent phase.

## Why
`PdfImportModal.waitForAgent()` had no time limit of any kind — deliberately, so a
100-page illustrated PDF could not be cut off. It only ended on lost contact with
the server (five failed status reads) or Stop/Undo/Discard. A model request that
OpenCode silently retries — which is what a frozen provider looks like — produces
no notes, and its retries changed nothing the old check watched, so the file could
wait indefinitely with `The agent is working... 0 notes written so far.` on screen.

## What changed
- **A measured silence allowance.** `waitForAgent()` tracks *progress*: a note
  written, or a tool call started or finished (`pollAgent()` now returns a
  `progress` signature built from the note count and the tool parts' states).
  `agentSilenceMs` (six minutes, the same allowance a blocking send gets) throws
  `agentStalledError()` when nothing at all happens for that long. Every real
  action resets it, so a slow document is untouched. A silent model retry inside
  OpenCode changes neither notes nor tool calls, so it cannot look like work.
- **One restart, then the file is started again.** A stall with **zero notes** is
  recoverable: `runAgent()` says *"The agent stopped answering, so OpenCode is
  being restarted, and this file is being started again..."*, calls
  `plugin.recoverAiConnection()` (managed: stop + `ensureOpenCode()`), creates a
  fresh session and re-sends the same prompt. Nothing was written, so no note can
  be duplicated. One restart per file.
- **A plain reason when it cannot recover.** After that restart, a second silence
  ends the file with *"OpenCode stopped answering while it was writing this file:
  nothing was written for N minutes. It was last seen: …"*, and the batch moves on.
  A stall **with** notes already written is never re-prompted (that would duplicate
  notes); it ends with the note count and the last activity named.
- Stop, Undo, Discard and closing the window behave exactly as before.

## Verification
- `tests/import-batch-window.test.js`:
  - "a silent agent is restarted once and the file is written on the retry" — a
    two-file batch whose first session of each file returns no messages: each file
    is restarted once (2 restarts, 4 sessions), the window says why, and the
    retried agent's note is written.
  - "an agent that stays silent twice ends with a plain reason" — both files stall
    again after the restart: exactly one restart per file, no `## Question` note
    left behind, and the batch finishes.
- Suite: **2,806 pass, 0 fail**; `npm run check` clean; `main.js` 7,298,862 bytes
  from 364 modules.
- Not driven against a live frozen agent in Obsidian; the real-OpenCode runs in
  1.301.28 covered the answer-check guard, not this one.
