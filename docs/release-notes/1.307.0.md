# 1.307.0 — Tasks learn the clock (and the hubs open again)

## The 1.306.0 bug this fixes
Every hub tab in 1.306.0 showed **"Plugin no longer active — the plugin that
created this tab has gone away"**, with the raw view type as its title.

Cause: Obsidian's `View` constructor calls `getViewType()` **while `super()`
runs**, i.e. before our constructor body had assigned `this.spec`. The base
class read `this.spec.type`, threw `TypeError: Cannot read properties of
undefined (reading 'type')` inside the registered creator, and Obsidian fell
back to its "plugin has gone away" placeholder for that leaf.

Fix: `hubViewClass(spec)` in `src/hub-view.js` returns a class per hub whose
`getViewType()`, `getDisplayText()` and `getIcon()` answer from the closure,
so they are correct before any instance field exists. The base `QtHubView`
also stopped dereferencing `this.spec` unguarded. `plugin.js` now registers
`new (hubViewClass(spec))(leaf, this, spec)`.

Verified in a real Obsidian 1.15.1 window (Xvfb, CDP, the built bundle in a
vault): `activateHubTab("plan", "focus")` yields a view with type
`question-tracker-hub-plan`, title **Plan**, tabs `Focus day · Review calendar ·
Local events`, and the rendered pane holds the real Focus day view (mini
calendar, Pomodoro card); `activateToday()` and `activateStudyWorkspace()`
open the Today and Study hubs on their first tabs. `tests/hub-views.test.js`
pins the constructor-time contract by calling the prototype methods on an
empty object.

## Why the clock
The quick-add boxes read days (`today`, `tomorrow`, `Tuesday`, `in 3 days`) but
not hours, so "review Biochem at 3pm" became a task titled that, due whenever.
Mission item 3: a few more patterns cover what people actually type, without
chrono and without leaving the dependency-free bundle.

## What a task can now say
| You type | Due date | Due time |
| --- | --- | --- |
| `Review Biochem at 3pm` | today, or tomorrow if 3pm has passed | 15:00 |
| `call at 9am` | tomorrow after 9am | 09:00 |
| `standup 15:30` | today / tomorrow by the clock | 15:30 |
| `drill 3p` · `drill 9a` | as above | 15:00 · 09:00 |
| `essay at 9` | as above (a bare hour counts only after "at") | 09:00 |
| `quiz tonight` | today, always (the one anchored word) | 20:00 |
| `draft noon` · `midnight` | today / tomorrow by the clock | 12:00 · 00:00 |
| `read this morning` · `this evening` | as above | 09:00 · 18:00 |
| `water plants in 2 hours` | real clock math, may roll past midnight | 01:30 at 11:30pm |
| `stretch in 30 minutes` / `in an hour` | same day unless it rolls | 16:30 / 17:00 |

Everything the parser already understood still works unchanged: `today`,
`tomorrow`, `tonight` (date), weekdays, `next Tuesday`, `weekend`, `next week`,
`next month`, `in N days|weeks|months`, `November 20` and ISO dates.

## Where the time goes
- **Model** — `studyTasks` rows gain `time: "HH:MM"` (normalized in
  `normalizeStudyTask`; focus-day scratch tasks validate the same way). A row
  saved before this release simply has no time.
- **Task list** — the chip reads `Due today · 3 PM`; a task with a time but no
  day shows just the hour instead of "No due date".
- **Focus day** — the scratchpad chip names the time, and its hint mentions it.
- **Mirror note** — the line becomes
  `- [ ] Review Biochem 📅 2026-11-16 ⏰ 15:00 ⏫ #bio`, the Tasks-compatible
  time field, and same-day rows sort by clock before unscheduled work.

## The rules that keep it honest
- A date or time picked in the form **always** beats the words: the parser is
  asked only for the half that is empty (`{ takeDate, takeTime }`), so
  "Practice tomorrow" with a chosen date keeps its words in the title.
- A bare hour never counts outside `at 9` — "read chapter 9" stays a chapter.
- `extractTaskDue()` is untouched for existing callers and tests; the new
  `extractTaskWhen()` is what the add paths use.

## Evidence
`tests/task-times.test.js` (13 tests): every clock shape, the named hours, the
words nobody means as a time, hour-already-passed rolling, stated-day wins,
"tonight" never rolling, `in N hours` rolling past midnight, plain titles left
alone, model normalization dropping `9:5` and `25:00`, the plugin add path
(picked day and picked time each winning), the Task list chip text, the Focus
day scratchpad, and the mirror line plus same-day ordering.
`tests/hub-views.test.js` (8 tests) adds the constructor-time view-type contract.
