# 1.307.10 — The last four deletes, driven live

## Why
1.307.9 moved every destructive control onto one `deleteWithUndo` helper, but
four of them could not be reached in the harness: the agent panel opens with AI
off and no saved conversation existed, the cards view was empty, and the
practice and calendar surfaces were never opened. They were wired and unproven.
This release drives all four in the running app, and the exercise found two real
gaps rather than confirming the wiring.

## What changed
- **Saved conversations gain a row Delete.** `deleteActive()` only ever acted on
  the open conversation, so an archived or saved conversation had no Delete at
  all, and the notice fell back to "this conversation". Each chat-library row now
  carries `Delete conversation <title>` (`src/chat-panel.js`), routed through the
  existing `onDeleteChat` and therefore through `deleteChatWithUndo`.
- **The notice names the record.** `deleteChatWithUndo` now falls back from the
  saved session title to the open tab's title before "this conversation"
  (`src/agent-view.js`), so the notice always names what left.
- **Pending grades name their card.** The pending panel and the in-review
  Discard used "the pending grade" whenever the stored entry had no `title`.
  A small `pendingGradeName` helper in `src/cards-view.js` uses the card's front
  text, then its file name, for both the button's accessible name and the notice.

## Driven live (Obsidian 1.15.1, Primary)
Each control was clicked where a reader would click it, with the record seeded in
the app's own stored state:

| Control | Notice | Undo |
| --- | --- | --- |
| Chat library → `Delete conversation Saved conversation probe` | `Deleted “Saved conversation probe”.` | session back, settings byte-identical, button disabled |
| Chat library → `Remove project` | `Deleted “Live project probe”.` | project and assignment back, byte-identical, disabled |
| Practice → `Delete the saved filter preset` | `Deleted “Live preset probe”.` | preset back, byte-identical, disabled |
| Cards → `Discard the pending grade for What is a cell?` | `Deleted “the pending grade for What is a cell?”.` | device-storage snapshot exactly restored, panel repainted, disabled |
| Calendar day plan → `Remove planned block <title>` | `Deleted “<title>”.` | block back byte-identical, shared `removeTimeBlock` path |

Every notice came from the shared `.qt-notice-undo` (58×32), and every Undo
refused a second click.

## Tests
`tests/undo-everywhere.test.js` gains five cases: the saved conversation, the
chat project, the practice preset, a pending-grade undo refusing to overwrite a
newer queued answer, and the pending grade itself restored from device storage.
**2,998 tests pass, 0 fail**; `npm run check` clean. No setting key, note format, review schedule or network default changed.
