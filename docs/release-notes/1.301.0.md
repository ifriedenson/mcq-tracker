# 1.301.0 — Import a batch, keep the progress, practice the result

The document importer accepts several files at once, follows the queue from the
main window, and opens in a real desktop popout that survives clicking back into
Obsidian. A finished batch offers Practice on the folder it just filled. This
release also carries the UI design-token and accessibility pass.

## What changed

### Several files in one import

- **Multi-select.** The source picker accepts several PDF, PowerPoint or
  Word/OpenDocument files in one action. The setup names the count and starts
  the batch with **Import N files**.
- **One review at a time.** Each file shows its position (`File 1 of 2`), its
  own preflight result and its own question preview. **Create N notes** writes
  that file, then the next file begins. Existing-folder confirmation still
  applies to each target folder.
- **A folder per file.** Under the chosen parent (the default is `Questions`),
  each file gets a subfolder named from the file. Duplicate names get ` (2)`,
  ` (3)` and so on instead of sharing a folder by accident.
- **Failure isolation.** A failed file is recorded in the batch result and the
  remaining files continue. The existing file-first text check, AI readiness,
  cleanup of stopped attempts and ordinary review/write path are unchanged.

### Progress that outlives the popout

- **Main-window progress.** The live progress is a zero-duration notice moved
  into the main window's `.notice-container`, with a fill bar and text for the
  current file, queue position and stage. It stays visible if the import window
  is closed or the main window is focused.
- **Honest stages.** The notice switches to `Waiting for your review.` while a
  file is waiting for confirmation and `Skipped: ...` when a file cannot be
  imported. At completion the live notice is replaced by a summary notice that
  remains for 12 seconds; **Cancel** dismisses the live notice immediately.
- **No orphaned work.** Batch timers run in the main host window, so closing
  the popout cannot leave a queued import without a driver. Closing while an AI
  request is in flight still lets that request finish, so the review appears
  when the window is reopened.

### A real import window

- **Desktop popout.** On desktop the importer opens a registered
  `question-tracker-import-window` item view in a 780×900 Obsidian popout, like
  Settings. Clicking back into the main window does not close it. Mobile keeps
  the existing modal, and a popout failure falls back to it.
- **Close is not cancel.** Closing the popout detaches only the view; the plugin
  keeps the session and the import continues. Running the import command again
  reattaches the same panel, queue, review choices and progress. It also focuses
  an existing import window rather than opening a second one.
- **Explicit cancel.** **Cancel** ends the batch, dismisses the live notice and
  detaches the window. A cancelled batch does not open a completion summary.

### Completion and Practice

- **One per-file summary.** The larger summary reports imported notes, files
  with no questions, and files that failed, with totals and an overall result.
- **Practice the imported folder.** When any notes were made, **Practice these
  questions** calls `practiceFolder(parent, made)`. Practice opens on the
  imported parent folder, including after a partial failure. The button is
  absent when no notes were made.
- **Late completions are guarded.** A cancelled session cannot reopen a summary
  after its work finishes.

### UI quality and accessibility

- **One design-token layer.** `styles.css` now defines type, spacing, radius,
  elevation, semantic colour, focus and motion tokens. Components consume those
  tokens instead of inventing local values. Light and dark accent fills are
  mixed so white text reaches 4.5:1, and `prefers-reduced-motion` collapses the
  duration and loop tokens.
- **Shared focus and target rules.** `.qt-ui` is added to plugin dialogs and the
  Settings root. Focus-visible uses a 2 px accent outline and 4 px ring; controls
  are at least 44 px at phone/coarse-pointer widths; Settings navigation and form
  controls stay 44 px; chip rows wrap at narrow widths.
- **Heatmap semantics.** The Study statistics heatmap is a keyboard-operable
  `role="grid"` with `row` and `gridcell` roles. Its 12 px visual cells are
  deliberately data cells rather than hundreds of buttons.
- **Rendered evidence.** `docs/ui-design-system.md` records the Obsidian 1.15.0
  Xvfb audit at 320, 768 and 1280 px in light and 1280 px in dark, plus six
  Settings categories at 675 px. `tools/ui-audit/` is the repeatable CDP
  harness. The PDF/EPUB reader modals were not rendered because the audit vault
  had no fixture; vendor PDF++ controls are not restyled; core Obsidian controls
  are outside the plugin's scope.

## Verification

- **Batch lifecycle with real PDF bytes.** `tests/import-batch-window.test.js`
  (9 tests) generates two real PDFs and covers multi-file selection and
  queueing, per-file review and completion, the desktop popout request and
  existing-window focus, close/reopen reattachment with the live notice,
  closing while AI is answering, a failed file not stopping the next, a full
  failure with one summary, cancel dismissing the notice and leaf, notice
  placement in the main container, and the mounted popout controls.
- **Practice wiring.** The same tests replace `practiceFolder` and assert that
  the completion button calls it with the imported parent folder and expected
  note count. They also assert there is no Practice button after zero notes.
- **UI contract.** `tests/ui-tokens.test.js` checks the token families,
  body-scoped focus and colour tokens, reduced motion, the 44 px rules and the
  heatmap roles.
- **Full gate.** `node --test` passes **2,641 tests, 0 fail**; `npm run check`
  is clean across **360 source files**; `main.js` is **7,161,028 bytes** from
  **363 modules**; `git diff --check` is clean.
- **Not hand-verified.** No real Obsidian desktop pass was run while preparing
  this release. The automated tests prove the popout/session/notice/Practice
  wiring, not the rendered popout or the real Practice view. The on-device
  check below remains with the owner.

## On-device check

1. Install this build in a test vault, enable the plugin, and make AI ready with
   Direct AI or a running OpenCode server.
2. Run **Import questions from a file (PDF, PowerPoint, Word)** and select at
   least two PDFs. Confirm a separate 780×900 import window opens and the main
   window is still usable.
3. Click back into the main Obsidian window, then return to the import window.
   Confirm the import is still open.
4. Start the import. While it runs, close the import popout. Confirm the live
   notice remains in the main window's notice area and continues updating.
5. Run the import command again. Confirm the same panel, queue and review
   return, and that no second popout is created.
6. Review and create notes for each file. Confirm the next file starts and the
   completion summary lists both.
7. Click **Practice these questions**. Confirm Practice opens limited to the
   imported parent folder and the imported questions are available.
8. Repeat with one deliberately failing file and with **Cancel**. Confirm the
   queue continues after a failure, the summary reports it, and Cancel leaves no
   completion summary behind.

No note format, review schedule, setting key, dependency, provider or default
network path changed. The popout is desktop-only; mobile keeps the modal.
