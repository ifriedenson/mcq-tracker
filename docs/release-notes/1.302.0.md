# 1.302.0 — Overnight imports

## What the owner saw
A 70-question PDF import takes about four hours, almost all of it in the
blind answer checks, and there was no way to queue more than a handful of
files: each check risked a six-minute silence, OpenCode was restarted roughly
every six minutes during checking because the client's idle guard was
classified as a connection failure, and the check was then asked again from
scratch. A reload, a spent AI budget or a rate limit failed the work instead
of pausing it.

## What changed
- A quiet check no longer restarts the server on suspicion. The OpenCode send
  takes a ~20-minute verification idle allowance with its own `deleteSession()`;
  on a silence timeout the plugin probes the server first — answers mean the
  provider is slow and the same question is simply re-asked, a failed probe
  restarts exactly once. A slow provider can never trigger a restart.
- The import agent writes all notes first, then runs one validation command
  over the folder instead of one script per note; the plugin's own parse and
  report stays the independent check.
- **Import files overnight…** queues 100+ picked or vault files with no setup
  screen, no per-file review and no dialogs. Encrypted or damaged files are
  recorded per file and the queue continues; Stop stays live.
- `src/overnight-run.js` journals every file (source path + hash, notes,
  copies, pictures, checks, timings) in the plugin folder, so reload, crash
  and sleep resume by skipping finished work — one notice, no duplicates —
  and **Undo this run** removes exactly what the run wrote.
- A spent daily or per-run AI budget parks the run as **paused** with the
  queue intact on both the write and the check sides; a 429 waits on
  Retry-After with jitter and retries, never failing a check. Notes are
  created in small batches so the indexer keeps up, each check's OpenCode
  session is deleted after use, and a wall-clock jump re-probes the server
  before anything is judged frozen.
- The verification pass checks notes with `verified: false` two at a time
  (configurable 1–4) and patches only check frontmatter. **Show flagged
  answers** lists every disagreement with the question, both answers, votes,
  model and date, plus Open note, Re-check, Accept stored answer, Drop and
  Re-check all — reusing the existing frontmatter, no schema change.
- The morning evidence is **Overnight import log.md**: a per-file table with
  notes, matched, flagged, errors, write and check times, plus the flagged
  list. The window shows the phase: Writing notes, then Checking answers.
- Three defects the headless drive exposed are fixed: one file's failure no
  longer poisons the journal, fully-checked entries read as done when a run
  finishes, a run stranded mid-checks resumes instead of being forgotten, and
  the flagged surface waits for the vault index before refreshing.

## Verification
- Suite in four shards: **2,862 pass, 0 fail** (680 + 651 + 759 + 772);
  `npm run check` clean across **365 source files**; `main.js` **7,370,491
  bytes** from **368 modules**.
- Headless Obsidian 1.15.1 against a stand-in provider, current bundle:
  a 3-file batch (good, broken, encrypted) with zero dialogs; a 40-file bulk
  run reloaded mid-flight finishing 40/40 matched with no duplicates; 4
  injected 429s ridden through to a finished run; a spent budget pausing with
  the queue kept and resuming to finished; the auto-resume notice read in the
  window after reload; the flagged surface driven through open, re-check,
  accept and re-check-all.
- Not verified live: a real provider key (model-turn counts for the batched
  self-check), a real laptop sleep, and killing `opencode serve` mid-run —
  the kill path is covered by unit tests (dead server restarts once, slow
  server never restarts, no double-spend) and resume-without-duplicates by
  the reload runs above.
