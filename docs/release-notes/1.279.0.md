# 1.279.0 — Type or dictate card answers

## Answer a card by speaking, then edit before grading

The Cards review surface now supports dictation in its existing typed-answer box. Choose **Speak** as the answer mode, select **Dictate**, and the browser/device SpeechRecognition API writes the transcript into the same textarea. Interim words update as you speak, and the final transcript stays editable, so a misheard word can be corrected before **Check answer** runs. Grading is never triggered automatically by speech.

### The existing grader does the work

Dictation is only an input method. **Check answer** still runs the deterministic first pass and then the optional AI second opinion through the existing `gradeTypedAnswer` and `gradeCardWithAi` paths. The AI grader receives the card front, the stored answer, the edited transcript and the strictness setting, and returns the same verdict, reasoning and stored answer shown for a typed response. No second grader, provider, model allow-list entry, note schema or dependency was added.

### Honest fallbacks

- **No speech support.** If the WebView does not expose `SpeechRecognition` or `webkitSpeechRecognition`, the **Dictate** button is disabled with a visible explanation and typing continues to work.
- **Microphone denied.** A permission or recognition error is shown in the answer box; **Try again** appears, and the typed answer remains usable.
- **No AI configured.** The local verdict and stored answer still appear, the AI hint explains that no provider is configured, and no AI request or queued grade-later request is created. Nothing is presented as an AI verdict when no AI ran.
- **No automatic rating.** The learner still chooses the rating after seeing the result, as with a typed answer.

### Limits

- Speech recognition depends on the Obsidian WebView and the platform's speech service. The plugin does not record or upload audio, but the browser/OS speech service may process it.
- Dictation is an answer-entry aid, not pronunciation assessment.
- The headless suite injects a fake recognition object at the `speechFactory` boundary; a real microphone, a real Obsidian window and a real provider request should still be checked by hand.
- The three owner-run visual, device and screenshot passes remain open.
