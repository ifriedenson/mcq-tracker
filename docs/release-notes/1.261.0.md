# 1.261.0 — Advanced Tables: upstream formulas and source-editor keys

This release closes the two behaviours that 1.260.0 still listed as differences
from [Advanced Tables](https://github.com/tgrosinger/advanced-tables-obsidian):
formula results and keyboard navigation now behave the way upstream documents.

## Formulas produce upstream's results

`src/table-formulas.js` keeps the note's `<!-- TBLFM: … -->` comment as the
canonical form, so every existing document and test is unchanged, and adds the
parts of upstream's documented language that were missing:

- **Time values.** A cell holding `YYYY-MM-DD HH:mm` is a datetime in
  milliseconds (read in local time); a cell holding `hh:mm` (for example
  `02:10` or `09:00`) is a duration in milliseconds. Both take part in
  arithmetic, comparisons and `sum`/`mean`/`count`/`min`/`max`.
- **`;dt` and `;hm`.** `;dt` prints `YYYY-MM-DD HH:mm`; `;hm` prints a signed
  `hh:mm` duration, so a column of durations can be summed into a total like
  `07:40`.
- **`#+TBLFM:`** is accepted as an alias of the comment line, which is the form
  upstream's own guide uses in one example.
- **Invalid ranges.** A range from a row to a column (`@2..$4`) is refused with
  `A range cannot go from a row to a column.`, matching the guide's rule.

`tests/table-formulas-upstream.test.js` runs every example in upstream's
formula guide and compares the resulting table rows: the overview total
(`@>$2=sum(@I..@-1)` → `1607`), the Fibonacci destination range, the row
subtraction, the `#+TBLFM:` conditional, the nested `if`, the two-by-two range
sum, `;%.2f` division, `;dt` datetime addition, datetime subtraction with
`;hm`, the full task-duration table with its `07:40` total, chaining with `::`
against separate formula lines, the refused row-to-column range, and a write-back
through `updateTableFormulas` that keeps the delimiter row, alignment and padded
cells.

## Tab and Enter navigate tables in the source editor

`onTableEditorKeydown` is a capture-phase `keydown` listener registered with
Obsidian's `registerDomEvent`, so no CodeMirror dependency is added. While the
cursor is inside a table in the normal Markdown editor:

- **Tab** / **Shift+Tab** move to the next / previous cell, wrapping to the
  next row and appending a body row at the end.
- **Enter** / **Shift+Enter** move to the same column on the next / previous
  row; Shift+Enter in the header row moves the cursor past the table and its
  formula lines.

The keys are ignored — leaving indentation, newline and selection behaviour
untouched — when the module is off, when **Bind Tab to cell navigation** or
**Bind Enter to row navigation** is off, when the cursor is outside a table,
when text is selected, when a modifier is held, or when the event comes from a
rendered reading-view cell (which keeps its existing handler). `previousRowTarget`
joins the engine's cursor helpers for the Shift+Enter direction.
