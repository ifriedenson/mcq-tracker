# 1.300.0 — Questions from more places

Question generation now starts from four sources, and the document importer
checks the text layer before it asks for AI or touches the vault.

## What changed

### Find or generate quiz questions

- **Four sources.** The command keeps its id and opens a source picker:
  **My notes** (the previous folder search), **My prompt** (original questions
  from the model's general knowledge, with no web lookup), **PDFs in my vault**
  (up to three, 40 pages each) and **Text I paste**.
- **A brief that sets the task.** A 1,000-character brief can name the subject,
  level, exam style and difficulty. Prompt mode requires it; notes mode keeps
  `focus` as a compatible alias for saved settings and existing callers.
- **Local reading, explicit sending.** PDFs and pasted text are read locally.
  Only the prepared source is sent, and only after **Send request**. Sources are
  capped at 18,000 characters; a PDF with no readable text is skipped and named
  with its reason, and a selection with no readable PDF is refused rather than
  guessed at. Prompt-only mode sends no source text.
- **The existing write path.** Preview, blind answer verification, distractor
  checks and ordinary question-note writes are unchanged. Nothing is written
  until **Create questions**.

### File-first import

- **Check before setup.** When AI is not ready, the importer now opens on a
  local check: choose a PDF, PowerPoint or Word file, read its text, and see the
  page count, character count and likely numbered question starts before
  **Continue to AI setup**.
- **Scanned files fail early.** An image-only file explains the OCR fix before
  AI setup and before any folder, source copy, figure or note is written. The
  offline **Paste questions instead** route stays beside the error.
- **The check carries forward.** The result appears in the AI wizard and is
  passed back into the reopened importer, so the file is not asked for twice.

### Stopped imports leave nothing behind

- **Every attempt tracks its writes.** The importer records the folders it
  creates and the source copy, captured figures and question notes it writes.
  A failure, a closed preview, **Back** from review or a draft with no usable
  items removes those artifacts without touching notes that existed before.
- **Agent writes are covered too.** An OpenCode import records a baseline of the
  target folder, so Markdown files the agent wrote itself are removed on a
  stopped attempt. A successful import commits the artifacts.
- **Closing during work is safe.** Closing while a request or note write is in
  flight defers cleanup until that work finishes, then removes the attempt.

### OpenCode readiness and compatibility

- **Start before testing.** The shared connection test and Settings → **Test**
  now start the managed server before opening a client, so they never probe the
  unconfigured default `127.0.0.1:4096` endpoint.
- **A bounded readiness signal.** Readiness uses `/config/providers` with a 4 s
  bound instead of `/global/health`, which stalls through Obsidian's request
  layer on OpenCode 1.19.5 even while the server answers over HTTP.
- **One repair, not a loop.** A server that is listening but never answers is
  stopped, its old database is preserved, and a fresh start is retried once. A
  still-stalled start gives actionable wording and leaves no child running.
- **Version-aware errors.** The managed release picker skips OpenCode 2.x, and
  a 405 names the removed 1.x route and points at Direct API. Manual servers
  keep their configured URL.

### Startup and indexes

- **One document reader.** `src/document-source.js` now serves the import,
  course-notes, document-review and OCR modals, so device/vault source handling
  and its error wording cannot drift between them.
- **PDF work stays off the startup path.** The PDF editor, reader and the
  vendored pdf-lib/PDF++ engines are required only when a PDF is opened; the
  test surface uses lazy getters.
- **Path-scoped indexes.** Question and card reads reuse path-keyed indexes
  that are updated per vault event; snapshots are invalidated only when an
  indexed path changed. Saves and bulk writes drop the indexes so a new note is
  visible even if its metadata event is late.
- **Two guards.** `check-duplicates.js` rejects duplicate class members and
  export keys, and `check-startup-budget.js` enforces the eager module budget
  (355 eager modules / 5,158,408 bytes against 360 / 5,500,000) while keeping
  the PDF stack lazy.

## Verification

- **Real PDF bytes.** The import tests generate a text PDF and an image-only PDF
  with pdf-lib, parse them through the shipping `readPdfPages` path, and cover
  the readable check, the scanned refusal, Direct AI extraction, and cleanup
  after copy, capture, note and close failures. The quiz tests use the recorded
  PDF.js text layer and a real provider request for all four source modes.
- **OpenCode.** Tests cover bounded health/providers probes, managed vs manual
  clients, 1.x/2.x selection, database quarantine and one retry, and the
  Settings connection path.
- **Full gate.** `node --test` passes **2,626 tests, 0 fail**; `npm run check` is
  clean across **358 source files**; `main.js` is **7,131,354 bytes** from
  **361 modules**.

No note format, review schedule, setting key, data path or network default
changed. PDF and pasted text leave the device only after **Send request**. The
interface is pinned by the shipping modal code and DOM tests; no fresh Obsidian
window was used for this release.
