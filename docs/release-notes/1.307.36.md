# 1.307.36 (Nov 25, 2026)

Sharing a set of questions meant exporting the whole vault and telling the
recipient which notes to ignore. This release adds the small, visible path: one
folder of question notes, one ZIP, a picker on both ends.

**Share from where you practise.** The practice home's shortcut row gains
**Share a folder (ZIP)** beside Import and Paste, so the action is visible
without the command palette. **Settings → MCQ Tracker → Practice** gains a
*Share question folders* row with **Export a folder…** and **Import a ZIP…**,
and the palette gains **Export a question folder as a shareable ZIP**.

**Pick a folder and see how many notes it holds.** The picker lists *All
questions* first — the configured question folder, labelled "whole vault" when
there is none — then every folder that directly holds a question note, each
with the number of notes it contains, subfolders included. A fuzzy search
filters the list, and a single choice exports without opening a dialog.

**The archive is the existing study bundle.** `src/study-bundle.js` writes the
same stored ZIP as the full backup, with `folder` in `manifest.json`, an
unchanged Markdown copy of every note under `questions/<original path>` and a
README that names the folder it came from. The file is named for the folder and
the day (`mcq-folder-bio-unit-3-2026-11-25.zip`); exporting the same folder on
the same day again writes `… 2.zip` rather than replacing the first share.

**Import is the same restore.** The import command now finds every MCQ Tracker
ZIP in the vault: one imports at once, several open a picker listing their file
names. A shared folder ZIP and a full study bundle follow the existing restore
rules — notes return to their original paths, an existing note is never
overwritten, an identical note is skipped, and cards are ignored when the
flashcard module is off.

**Nothing new to configure.** No setting key, note format, review schedule or
network default changed, and the new module loads on first use, so the startup
budget is unchanged. `src/folder-share.js` holds the folder list, the file-name
test and both modals; `tests/folder-share.test.js` covers the list, the name,
the archive contents, the empty and unsafe refusals, the round trip and the
pickers.

Both buttons were also driven in a real Obsidian 1.15.1 window: the folder and
ZIP pickers rendered with their counts, exports wrote the two folder ZIPs, and
imports restored the notes byte-identically at their original paths.

Tests: **3,196 pass, 0 fail**; `npm run check` clean; `main.js` rebuilt at
4,402,873 bytes from 391 modules; inventory 475 groups, 3,350 exports, 256
commands.
