# 1.277.0 — PDF++ is built in

## PDF++ is built in

MCQ Tracker now embeds the complete, unmodified **PDF++ 0.40.31** production
bundle, so there is no reason to keep both plugins installed. PDF++ adds its own
**PDF++** settings tab and its full native-viewer feature set; the MCQ reader,
annotations and page editor keep working beside it.

### What you get

- **Backlink highlighting.** Every link to a PDF page is highlighted in the PDF
  and listed from the note, for internal links, citations, embeds and outlines.
- **Callouts and colour palette.** Link to a page with a colour and callout
  style; templates make repeated formats quick.
- **Backlink pane.** A focused pane with filtering, sorting and hover sync
  between the note and the page.
- **Annotation editing.** Highlights, underlines, boxes and notes created by the
  native viewer can be edited directly, with a configurable menu.
- **Page composer and embeds.** Create, insert, delete and extract pages, and
  embed a cropped page or a trimmed region of a PDF in a note.
- **Link tools.** Copy a link to a page, a selection or an annotation, with
  context menus and link history.
- **Keyboard commands.** Page navigation, zoom, fit-to-width/height, sidebar
  toggles and rectangular selection from the keyboard.

### How it works

- `vendor/pdf-plus.js` and `vendor/pdf-plus-css.js` are the upstream release
  assets, byte for byte. PDF++ is MIT licensed; its notice is in `NOTICES.md`.
- MCQ Tracker hosts the upstream plugin class as a managed child component with
  a private manifest (`mcq-tracker-pdf-plus`), so it cannot collide with an
  installed PDF++ plugin. Its settings live in MCQ Tracker's own `data.json`
  under `settings.pdfPlus`, not in a second settings file.
- The module is **Settings → Global → Modules → Embedded PDF++ tools**.
- If the standalone PDF++ plugin is enabled, the embedded copy refuses to start
  and says so instead of patching the native viewer twice. Disable the standalone
  plugin; MCQ Tracker then supplies the same feature set.
- A standalone PDF++ `data.json` is not read: the embedded copy starts from
  PDF++'s defaults and saves into MCQ Tracker's settings.

### Link highlights straight from your notes

A `[[Papers/Exam.pdf#page=3&selection=12,0,13,18&color=green]]` wiki link is the
annotation now: the reader scans the note for links to the open PDF, paints the
selected area in the link's own colour and lists the notes that cite the page, so
a highlight can live in any note as ordinary Markdown. Copied page links carry
the rectangle too, and **PDF: open a copied deep link** jumps to that page with
the area ringed. The sidecar annotator is unchanged and stays the durable model
for ink, quotes, notes and tags.

### Two PDF UIs never compete

PDF++ decorates Obsidian's native PDF viewer. MCQ Tracker's reader and page
editor draw their own canvas overlays. While either MCQ PDF surface is open, the
embedded host is stopped — its commands, settings tab, patches, embed creator and
hover sources all go away — and it restarts exactly once, when the last surface
closes. An editor opened over the reader nests the pause, and toggling the module
while a surface is open takes effect when that surface closes.

The trade-off is deliberate: PDF++'s own menus and settings tab are absent while
an MCQ reader or editor is open, and in-host state such as an open PDF++ sidebar
is rebuilt on resume. See `docs/pdf-plus.md` for the full policy and its limits.

### Native-viewer-only extras

Outline, page-label and embed editing, external-app sync and Vim keybindings
remain out of scope for MCQ Tracker's own UI. They are available through the
embedded PDF++ host exactly as in the standalone plugin, so their absence from
MCQ's own interface is not a reason to keep both installed.

### Verification

- **2,212 tests pass**; `npm run check` is clean (no dynamic code across **309 source files**,
  vendor guard, up-to-date bundle).
- `tests/pdf-plus-boot.test.js` boots the **real** vendored bundle through
  MCQ Tracker's host against a headless Obsidian app and proves load, UI
  registration, complete teardown, no Node-only built-in at load, reader
  pause/resume cycles with no duplicate commands or stacked patches, overlapping
  surfaces, enable/disable while open, and real reader/editor modal wiring.
- `main.js` is rebuilt across **312 modules** at **6,374,495 bytes**.
- The headless harness has no PDF leaf, so what PDF++ draws inside the native
  viewer still needs a real desktop/mobile run.

### Upgrading

Update the plugin, then turn on **Embedded PDF++ tools** in Settings → Global →
Modules. If you have the standalone PDF++ plugin installed, disable it (its
features are now here). No new dependency, account or network access is added.
