# 1.307.25 (Nov 19, 2026)

The finish-scope pass: every plan row that was still partially implemented or
unimplemented — and buildable locally without a new dependency, credential,
device or owner decision — now ships. The 13 gated rows in plan.md §3.9.6 stay
gated and are each named there with their reason.

**Class-held dots on the course hub** (Class Timetable idea 2). Each course
card shows one dot per scheduled class meeting this term: filled when that
day's lecture note exists, a ring when attendance was checked without a note,
empty when the class did not meet. Clicking an empty dot creates the note from
the existing course template. `src/class-dots.js` is the pure matcher over the
term's meetings plus the note/lecture/absence sets; `plugin.classDotsData()`
builds those sets from the calendar cache, the class-note index, the lecture
log and absences. No new property, store or setting key. Pinned by
`tests/class-dots.test.js`.

**Week image export** (idea 4). The week header gains an export control and
`Calendar: export the current week as a PNG image` saves
`week-timetable-<startKey>.png` beside the `.ics` export.
`src/week-image.js` builds the SVG deterministically from the same
`plugin.buildWeekLayout()` rows the week card draws (title, day headers, hour
lines, lane-split blocks, all-day chips, now-line); the plugin rasterizes it
with a canvas at 2x. No scheduling data changes. Pinned by
`tests/week-image.test.js`.

**Agenda rail** (Doable idea 1). The task list gains a List|Agenda toggle,
persisted as `studyTasks.agenda` with List the default. Agenda groups open
work into overdue, today, one section per upcoming day, later (capped at 20
with a total), no-date (capped at 20) and done-today; empty sections are
skipped and rows reuse the existing complete/star/repeat/delete paths.
Finishing a task now stamps `doneAt` (an explicit value wins; reopening
clears it), which is what the Done-today section reads. Pinned by
`tests/task-agenda.test.js`.

**Quick-add preview** (idea 2). The add row shows a live line —
`Adds "…" · due … · repeats …` — computed by `previewTaskEntry()` from the
same spoken-date/repeat extraction the Add path uses, with picked dates
winning over spoken ones. Pinned by `tests/task-agenda.test.js`.

**Inline task chips** (idea 3). In reading view, trailing schedule tokens
(`📅`, `⏰`, `⏳`, `🛫`, `🔁`, `⏫`) render as small chips via a
postprocessor gated on the tasks module; clicking the date chip opens a date
picker and clicking priority steps it, each rewriting only that token in the
source line. The vault task index stays read-only — chips are a separate,
scoped decorator. Live Preview's CodeMirror overlay is out (untestable here,
bundle risk); reading view is covered and the limit is recorded. Pinned by
`tests/task-chips.test.js`.

**Per-message agent-edit undo** (adapted Copilot row 1). Every applied
OpenCode review is now journalled device-locally (`src/agent-edit-journal.js`,
capped at 10 records) with its before/after text, and **AI: review and undo
agent edits** lists each review with its own Undo; notes edited since are
skipped, never clobbered. The single-slot in-memory undo stays as the
fast path and falls back to the journal, so it survives reloads. Pinned by
`tests/agent-edit-journal.test.js`.

**In-editor diff navigation** (adapted Copilot row 2). Proposal cards and the
review dialog gain **Show in note**, which opens the note and selects the
changed lines in the open editor (`src/editor-diff-nav.js` derives hunk spans
from the shipped `diffPreview` rows); **Study agent: show the next proposed
change in its note** steps through every pending hunk. No CodeMirror overlay
or new dependency, per the dependency-free rule. Pinned by
`tests/editor-diff-nav.test.js`.
