# 1.307.19 — Every PDF import path, proven in a vault

Released November 18, 2026. Obsidian 1.15.1.

## Why

1.307.18 fixed the row ordering that PDF imports depended on, but the fixes were
proven by tests and a headless harness, not by the plugin running in a real
vault. This release is the proof: every way a PDF reaches the tracker was driven
in Obsidian 1.15.1 against a disposable vault, with the shipped bundle and a
stand-in OpenAI-compatible provider, and each path was read back from disk.

Nothing in the shipped plugin behaviour changed. The vault pass found no defect
in product code, so the only source change in this release is in the end-to-end
harness.

## What was proven

- **Main import.** `exam-mcq.pdf` wrote `Questions/Exam MCQ/EXAM-MCQ-Q02.md` with
  `verified: true` and `verification: match`, kept its PDF copy, and raised no
  error.
- **Free response.** `frq.pdf` detected two items and wrote both, with prompt and
  rubric in the right order.
- **Quizlet cards.** The preview counted 3 and created 3, with 0 errors, and
  `Cards/Spanish/` gained the three cards with their `quizlet-pdf` format keys.
- **Document cards.** `doc-cards.pdf` found three cards locally, the modal showed
  its Cancel control from the start, and `import_format` was written on each card.
- **Overnight batch.** A journaled run finished with 2 done, 2 notes, 2 matched,
  0 flagged and 0 errors.
- **Quiz generation from a PDF.** `exam-mcq.pdf` produced 2 verified items and
  created both tracked questions.
- **Vision OCR.** `scan.pdf` wrote `OCR/OCR 2026-11-18.md` stamped with the
  `ai-vision` model and its source.
- **LaTeX conversion.** The same scan wrote `scan (LaTeX).md` with its LaTeX
  frontmatter, source and model.
- **Refusals.** A damaged PDF was refused with “couldn't read”, a scanned
  document was refused by the main import as “almost no readable text”, and an
  import with AI off offered the offline paste path — each leaving the vault
  untouched.

## What changed

- **The e2e stand-in answers quiz prompts.** `tools/overnight-e2e/standin.mjs`
  now recognises the quiz-generation prompt shape and replies with a valid
  `{"questions": [...]}` payload, so the PDF-to-quiz path can be driven without a
  paid provider. Note and verification replies are unchanged.

## Tests

`node --test` → **3,020 pass, 0 fail**; `npm run check` clean. No note format,
setting key, review schedule or network default changed.
