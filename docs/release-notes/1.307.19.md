# 1.307.19 — The cover page stops reaching your questions

Released November 17, 2026. Obsidian 1.15.1.

## Why

1.307.17 removed the QR code and its caption from imported PDFs; 1.307.18 removed the download stamp,
watermark id, running header/title, copyright footer and printed page numbers. One block survived both
passes: the cover the host site prints at the top of page 1. On the 21-page Unit 4 exam that is

```
682243944-APWorld Unit 4Exam-pdf AP World History (Rock Canyon High School)
Studocu is not sponsored or endorsed by any college or university
682243944-APWorld Unit 4Exam-pdf AP World History (Rock Canyon High School)
Studocu is not sponsored or endorsed by any college or university
```

It repeats an identifier line and a tagline, but it appears only on page 1 — so the repetition rule of
1.307.18 could not see it, and it was still reaching the AI prompt and the note body.

## What changed

- **`withoutCoverPreamble(lines)` (`src/pdf.js`)** reads only the leading lines of the first page, up to
  the first real question, source, document or heading (`isContentAnchorLine`), and never past the
  first twelve lines. From that preamble it drops only three shapes of line:
  - a line the page prints more than once (`furnitureKey` equality, whitespace and case folded);
  - a bare address, a domain on its own, or a "visit example.com" invitation (`isBareUrlLine`);
  - an identifier: a long numeric id, a `WORD|1234` watermark id, a file name, or an id-leading slug
    (`isIdentifierLine`).
- **A single legitimate line stays.** A title, an instruction, a teacher or class heading, a `Name`
  field and the first question can occupy the same position as a cover block; because they appear once
  and are neither an address nor an identifier, they survive.
- **Only page 1 is a cover.** `readPdfPages` applies the rule to the first page of a document with two
  or more pages and to nothing else, so a chapter heading or a file-name-shaped line in the body of a
  later page is untouched.
- **Everything from 1.307.17 and 1.307.18 is unchanged:** the QR symbol detector and caption stripper,
  the repeated-furniture stripper with its `max(3, 60% of pages)` threshold and margin bands, the
  printed-page-number rule, and the cleaning of both the reading-order lines and the table lines.

## Evidence

out of git) was read through the shipping `readPdfPages` with production chunking
(`chunkPages(pages, 9000, 5)`):

| QR captions | 0 | 0 |
| **cover slug lines** | **2** | **0** |
| **cover taglines** | **2** | **0** |

The verifier (`artifacts/pdf-import/verify.js`) computes the line set page 1 must keep by running the
module's own cover rule over the transcription, then fails if any other line is missing, if any
furniture or cover shape survives, or if the `Name` field disappears. Its verdict on this run: *every
document line survives verbatim; no furniture, no QR artefact and no cover block is left.*

`tests/pdf-furniture.test.js` grew five cases: a synthetic non-Studocu cover block stripped; a single
legitimate preamble line kept; anchor detection stopping the preamble at the first question; the URL and
identifier shapes asserted one by one; a file-name-shaped line on page 2 kept; and `readPdfPages`
dropping the first page's cover while page 2 keeps its own lines. The nine 1.307.18 furniture cases still
pass, so the repetition rule, the body-position rule, the short-document refusal and the page-number rule
are unchanged.

No note format, setting key, review schedule or network default changed.
