# 1.301.3 — Keep a stalled answer check from freezing an import

A blind answer check could wait forever when its AI provider accepted the
request and then stopped responding. The import stayed on **Checking the
notes...** with no visible progress, which made a long batch look stuck even
though Obsidian and Node were idle. Each check now has a 60-second limit, and
the import names the answer it is checking.

## What changed

### A stalled check cannot freeze the import

- Every blind answer check is bounded by a 60-second timeout.
- A timeout is recorded as a verification error on that one note. The imported
  question is kept, the current file finishes, and the batch moves to the next
  PDF instead of waiting forever.
- The same bound applies to Direct AI and OpenCode checks, including manual
  **Verify answer with AI** actions.

### See which answer is being checked

- The import window and the main-window progress notice now show
  **Checking answer N of M: note name...** while verification runs.
- The rest of the import flow is unchanged: review, stop choices, the live
  progress notice, the completion summary and **Practice these questions**.

## Why it looked stuck

The Task Manager showed Obsidian and Node using about 0% CPU because the
plugin was waiting on a network request, not doing local work. The importer had
already written several notes and was checking their AI-written answers one at
a time. One request never settled, so the loop never reached the next note.

## Verification

- `node --test`: **2,655 tests, 2,655 pass, 0 fail, 0 skipped**.
- New coverage keeps a never-resolving provider call from freezing both the
  answer-check path and the real agent-driven import; the note is retained and
  the batch summary still opens.
- `npm run check` is clean across **360 source files**; `main.js` is
  **7,187,933 bytes** on disk from **363 modules**.

No note format, review schedule, setting key, dependency, provider or default
network path changed.
