# 1.265.0

## Kairos document model in Time blocks

The owner ranked the remaining Kairos gap, so the opt-in **Time blocks** module
now implements the Obsidian plugin's documented document model and behaviours.
It is still original, dependency-free JavaScript: no Kairos source, styles or
copy text was used.

### What is new

- **Schedule markdown.** `parseScheduleMarkdown` reads a `## Schedule` section
  with timed blocks, tasks (`[ ]`, `[/]`, `[x]`, `[-]`), notes, `[Project]` /
  `[D:Domain]` associations, trailing `(tag)` notes, the `Unscheduled` block and
  the older single-line checkbox forms. `scheduleMarkdown` writes the same
  section and `replaceScheduleSection` edits only that section.
- **Two-way daily-note sync.** `plugin.syncTimeBlockDailyNote(date)` imports the
  day's Schedule section (creating missing projects/domains) and writes it back,
  leaving prose and other sections untouched. The command is
  **Time blocks: sync today's Schedule section with the daily note**.
- **Task statuses.** Tasks keep `open`, `half`, `done` and `cancelled`; `done`
  stays true only for `done`, and toggling a checkbox keeps `status` in step.
- **Carry-over.** **Time blocks: carry unfinished tasks to today** finds the most
  recent earlier day's open and half-done tasks that today does not already
  have, and moves them into today's `Unscheduled` block with the block's
  association written onto each moved task.
- **Routines.** `Routines.md` headings and per-line `🔁` rules accept Daily,
  Weekdays, Weekends, day lists (`Mon, Wed` / `Tue/Thu`) and `Monthly on N`;
  timed routines carry their nested tasks. **Regenerate today's routines**
  removes the day's routine blocks and offers them again.
- **Backlog.md and imports.** Backlog lines read `[Project]` / `[D:Domain]` and
  `📅 YYYY-MM-DD`, and `resurfacedBacklog` reports what is due. Commands import
  `Routines.md` and `Backlog.md` without duplicating existing entries.
- **View commands.** Each planner view now has its own command (day, week, grid,
  backlog, routines, projects, timeline).

### Not reproduced

Drag-and-drop editing, Timeline intensity bars, project/domain status files,
the onboarding tour and touch gestures remain UI differences. They are recorded
in `plan.md` §5.22.12 and `docs/installed-plugin-parity.md`.

Tests: **2,139 pass**, `npm run check` clean. Coverage is in
`tests/time-blocks-kairos.test.js` beside `tests/time-blocks.test.js`.
