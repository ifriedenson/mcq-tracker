# MCQ Tracker 1.218.1

Fixes a form-authoring defect: an explicitly requested field name longer than 60
characters was checked for duplicates before it was shortened, so the shortened
name could match a field that already existed. The result was two fields sharing
one name, which viewers fill as one field twice.

## What changed

`addFormField` in `src/pdf-editor.js` now shortens an explicit `name` to
`MAX_FIELD_NAME` (60) *before* comparing it with the document's fields, so a
truncated name that collides is refused with `duplicate` instead of creating a
second field under the name already in use. Names derived from a label behave as
before: they still gain `_2`, `_3` ….

## Verification

`tests/pdf-editor.test.js` adds "an explicit field name is shortened before the
duplicate check": a 70-character name is accepted once and stored at 60, the same
70-character request is then refused with `duplicate`, and exactly one field
carries that name.

**1,684 tests pass / 0 fail**, `npm run check` is clean, `main.js` is rebuilt and
`git diff --check` is clean.
