# 1.288.0 — Copilot-style Study agent chat surface

The Study agent now uses the transcript-first chat layout of Obsidian Copilot
while keeping the plugin's own Obsidian-variable styling, actions and review
gates.

## Chat surface

- Removed the branded **Study agent** identity header, avatar rows and speaker
  names. The transcript is the first thing in the pane.
- A **ChatControls** strip follows the transcript: mode and role on the left;
  token gauge, **New chat**, **Chats**, **Settings**, **Save chat** and
  **Expand** on the right.
- User turns are full-width bordered cards using
  `background-modifier-hover`. Assistant turns are flat and unboxed. Message
  actions are compact icon buttons with full accessible labels.
- The composer keeps context chips above a borderless draft, with `@`, PDF,
  **Commands** and model selection on the bottom-left and a circular accent
  **Send**/**Stop** on the bottom-right.
- Reasoning parts render as a compact disclosure; vault links are collected in
  a **Sources (N)** block and remain clickable. GFM tables render in assistant
  replies.
- Empty, streaming and provider-error states use the same panel and composer.
  Stop keeps the partial reply; Retry keeps the error card.
- The 1.287.1 closed-picker scroll-track fix is carried forward.
- Behaviour is unchanged: sends, queuing, model resolution, mentions, context,
  budget, review-before-write, tabs, history and Stop all use the existing
  paths.

## Evidence

`docs/render/study-agent-ui/` contains 12 fresh chat captures from the real
`ChatPanel.build()`/`draw()` markup with the real `styles.css` and Obsidian's
default light/dark variables:

- 420 px thread, empty, busy/Stop and error states;
- 560 px thread with the **Sources** disclosure;
- 320 px empty state with the bottom-sheet composer;
- the unchanged grouped Settings → AI pair.

The measured pass found zero horizontal overflow at every width, an 8 px
composer bottom gap, 24 px message-action targets, and the correct Send/Stop
swap. There is no Obsidian app runtime in this environment; the final in-app
light/dark check remains the documented limitation. The settings pair is a
structural fixture because Obsidian's `Setting` renderer is unavailable
outside the app. Method and limitations are in
`docs/render/study-agent-ui/README.md`.
