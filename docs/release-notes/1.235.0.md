# MCQ Tracker 1.235.0

This release adds row and column structure to **Advanced Tables**: insert, delete
and move rows and columns from a compact toolbar attached to each rendered table.
The note remains an ordinary, aligned Markdown table. The module is still opt-in
and reading-view only.

## Controls

When a cell is focused, the toolbar appears below the table. On a pointer device
it also appears on hover; on touch devices it stays visible.

| Control | Action |
|---|---|
| **+ Row** | Insert a blank row below the selected row. |
| **− Row** | Delete the selected body row. |
| **↑ Row** / **↓ Row** | Move the selected body row one position up or down. |
| **+ Col** | Insert a blank column to the right of the selected column. |
| **− Col** | Delete the selected column. |
| **← Col** / **→ Col** | Move the selected column one position left or right. |

The active cell is committed before the structural action runs. The header row
cannot be deleted or moved, the last remaining column cannot be deleted, and a
row or column at its edge refuses to move rather than wrapping to the other side.
A refusal is reported through the plugin's normal notice and changes nothing.

## How the source stays valid

`structureTable` in `src/table-editor.js` is pure and operates on the parsed
table. It keeps the header first, keeps every row the same width, carries column
alignment with the moved column, and creates blank cells for insertions. The
bounded table limits remain 500 rows, 40 columns and 4,000 characters per cell.

`updateTableStructure` applies that change to the full note through
`tableBlockUpdate`, the same block writer used by cell edits. It preserves the
note's original line endings (including CRLF), pads every column, keeps the
delimiter row valid and escapes pipes. The plugin's new `updateTableStructure`
and the existing `updateTableCell` both call one `updateTableBlock` method, so
the live Markdown editor is preferred, `vault.modify` is the fallback, and every
change runs through the existing serialized queue. This prevents a toolbar
action from racing a pending cell edit.

`createTableToolbar` builds the eight accessible buttons after the rendered table.
The toolbar is `contenteditable="false"`, the buttons have labels and titles, and
the click path commits the active cell before applying the action. No parallel
editor, second note store, dependency, provider or network request was added.

## Honest limits

This is still reading-view editing, navigation and row/column structure only.
Formatting commands, sorting, formulas, merged cells and CSV export are not in
this release. Deleting a row or column is immediate and is not preceded by a
confirmation; use Obsidian's file history to recover an accidental deletion.
Editing a cell replaces its inline formatting (for example bold or a link) with
plain text, so use source mode when rich cell contents must be preserved. The
parser still requires a standard GFM table with a delimiter row. Interactive
Obsidian desktop and touch behavior was not manually exercised in this
environment; the toolbar and write behavior are covered by simulated DOM and
plugin tests.
