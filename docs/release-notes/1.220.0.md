# MCQ Tracker 1.220.0

Page management is now a complete, checked part of the PDF editor: every
reorganisation is a real edit on the document, one undo step, and nothing is
written until a copy is saved.

## What the page controls do

Each page card keeps its **⟲** / **⟳** rotation buttons, **↑** / **↓** move
buttons, **Duplicate** and **Delete**. The page bar keeps **Add blank page** for
the end of the document and now adds **Insert at** with an **Insert blank page**
button, so a blank page can go between any two pages, not only after the last.

The engine behind them was tightened:

- `rotatePage` refuses any angle that is not a multiple of 90 degrees, with
  `A page rotation has to be a multiple of 90 degrees.`
- `movePage` refuses a destination outside the file instead of silently clamping
  it, with `Position N is not in this PDF (1 to M).`
- `addBlankPage` accepts a position from 0 to the page count, refuses anything
  else with `A blank page cannot go at position N in a M-page PDF.`, and still
  appends when no position is given.
- `deletePage` still refuses to remove the last page, and every operation still
  refuses a page that is not in the file.

## Per-page state

A reorder, delete, duplicate, insert or merge changes which page a form field
sits on, so the window now rebuilds the field labels from the live document
(`syncFields`) after those edits. The page map (`originOrder`), the extraction
selection and the thumbnail map follow the change; the selection is cleared
whenever indexes shift, so no stored index can quietly point at a neighbouring
page. Rotated pages stay rotated, and the existing rules that refuse content
placement on rotated pages are unchanged.

## Checks

`node --test` passes, including new tests that rotate through 90/180/270 and
refuse 45, reorder and then reload the saved order, insert blank pages at the
start, middle and end with their own sizes, and exercise every refusal path.
`npm run check` is clean and `main.js` is rebuilt from the sources.
