# 1.307.8 — One undoable delete, on every surface

## Why
1.307.7 made the sidebar task list's × undoable and proved it live. The plugin
owns the same local `studyTasks` rows on a second surface — the Study Workspace
Tasks tab — and that pass never drove it. Driving it found the same data-loss
defect still in place.

## What was wrong
The Study Workspace queue drew its own row **Delete** button that called
`plugin.removeStudyTask(task.id)` and repainted. The row disappeared on one
click with no notice, no undo and nothing to recover it, while the identical
task deleted from the sidebar left an eight-second Undo. Two surfaces, two
different answers to the same click, and one of them cost the task.

## What changed
- `src/plugin.js`: new `deleteStudyTaskWithUndo(id, onChange)` — delete, repaint
  the caller, show `Deleted “<task>”.` for 8 seconds with an **Undo** that
  restores every field, repaints again and disables itself.
- `src/task-list-view.js`: the row's × calls the helper instead of carrying its
  own copy of the notice.
- `src/study-workspace-view.js`: the queue's **Delete** calls the same helper and
  carries the task title as its accessible name.
- `tests/task-list.test.js`: a second test drives the workspace Delete, asserts
  the task is gone, finds the same `qt-notice-undo`, clicks it, and checks the
  restored tags and due date.

## Evidence — live, Primary, Obsidian 1.15.1
- Queue Delete button: 243×40, accessible name `Delete Workspace delete probe`.
- Click: stored tasks 6 → 5, the row leaves the rendered list, and the notice
  reads `Deleted “Workspace delete probe”.` with Undo at 58×32.
- Undo label contrast 8.37:1 against its own fill; Undo font 13px.
- Undo: the task returns with `tags: ["chem"]`, `priority: "high"`,
  `due: "2026-11-20"`, the queue lists it again, the button is disabled and the
  notice is gone; stored tasks back to 6.

## Checks

- `tests/task-list.test.js` alone: 11 pass.
