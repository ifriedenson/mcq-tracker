# MCQ Tracker 1.228.0

This release applies the form-safe page preparation to merging: adding pages
from another PDF that has a form no longer leaves orphan widgets or drops the
filled values.

## What changed

- `insertPdfPages` now prepares the incoming PDF through
  `prepareForPageCopy`. If it has AcroForm fields, a serialised copy is
  flattened before its pages are copied, so filled values become visible page
  content.
- The target document keeps its own live form. Only the incoming pages are
  prepared, and the source file is read, never changed.
- The result reports `flattened: true`, and the editor status says that form
  values were baked into the added pages.
- Extract, split and merge now share one form-preparation path. An unsupported
  form that cannot be flattened refuses the merge with a clear message.

| Reader page merges | **Pass** | The reader page-operation merge test still asserts order, labels and shifted form overlays. |

## Honest limits

- Added pages are flattened, so their fields are visible but no longer
  fillable. The target document's own form is untouched.
- XFA, encrypted PDFs and signatures or button fields that cannot be flattened
  are still refused.
