# MCQ Tracker 1.231.0

This release closes the flatten-on-merge limit: adding pages from another
fillable PDF now keeps the incoming form fields live instead of baking their
values into the inserted pages.

## What changed

- `insertPdfPages` validates the source form, copies its pages, maps every
  copied widget to its source terminal field, and clones the field object that
  `copyPages` already placed in the target context. Each clone gets a
  deterministic unique `/T` (`name`, then `_2`, `_3` …), `/Kids` points at the
  copied widget, and the widget's `/Parent` and `/P` point at the clone and its
  inserted page. The field is registered in the target AcroForm and the copied
  widget keeps its appearance stream.
- `/V`, `/AP` and non-widget annotations survive, so an added page keeps its
  values and can be filled independently. The target document's existing fields
  and the source file are untouched.
- Existing target field names and repeated merges resolve collisions
  deterministically and case-insensitively. A page with two fields contributes
  two distinct clones.
- The result keeps its caller-compatible shape: a live merge reports
  `flattened: false`, `liveForm` and the number of cloned `fields`; the
  Add-pages status names the live fields that were copied.
- Extraction and splitting still use `prepareForPageCopy` and flatten their
  serialised copy, because they produce a separate PDF rather than adding pages
  to a live form. Move still keeps its existing live-page semantics.

## Unsupported-field policy

The policy is **refuse the whole merge**, not a partially flattened page:

- An XFA source or XFA target refuses with a message naming **Add-pages**.
- A source page whose widget belongs to a button, signature, or any field kind
  this editor cannot safely clone refuses with `reason: "form"` and a message
  naming **Add-pages**.
- A widget annotation that is not registered in the source AcroForm, a copied
  widget that cannot be paired with its source field, or a copied widget whose
  field was not carried into the target context also refuses.
- Refusal happens before any page is inserted or any field is registered, so the
  target's page count, existing values and live form are unchanged. There are no
  blank or orphaned fields.

This is deliberate: a partial flatten would leave an added page with a mix of
live and dead fields and a status that could not be trusted. The merge path now
matches the live duplicate-page contract; extract and split remain intentionally
different because they create a new standalone file.

## Honest limits

- Button, signature and XFA fields cannot be merged live; this release refuses
  the whole merge for those sources rather than flattening them.
- A field with several widgets is cloned per widget on the added pages: each
  copied widget becomes its own uniquely named field with the source value. The
  source field and its other widgets stay untouched.
- Encrypted PDFs remain unsupported, as before.
- Saving still writes a new `name (edited).pdf`; the source PDF and its sidecar
  are never changed.
