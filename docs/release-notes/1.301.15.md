# 1.301.15 — Pick the extra check models from a list

## What changed
- **The typed list is gone.** Settings → AI → Session pacing and checks now has
  **Extra check model 1**, **2** and **3** as dropdowns instead of one text box.
  Each starts at **Same as the first check**, which is the verification model
  chosen for **Check AI-written answers**.
- **The options are only models this device already knows**: the provider's
  fetched list (`ai.api.models`), the model saved for each AI feature, and the
  models already chosen for the extra checks. A mistyped name cannot be picked,
  so an extra check cannot silently fail and stop voting.
- **Other model...** switches one slot to a text field plus **Use the list**, for
  a provider whose model list was never fetched (OpenCode names such as
  `provider/model`). A saved name outside the list opens in that field by itself,
  so nothing saved by 1.301.14 is lost or hidden.
- The order and repeat rule are unchanged: the chosen models are used in slot
  order and the list repeats when the panel is longer than the list.

## Why
The owner asked for a dropdown of available models instead of a typed list, so a
typo cannot cost a vote.

## Verification
- `tests/settings-navigation.test.js` renders the real AI settings page and
  finds all three pickers, confirms the old typed field is gone, and re-renders
  with a saved model that is not in the fetched list.
- `tests/answer-verification.test.js` covers `panelModelChoices`: fetched models
  first, blanks dropped, repeats collapsed, feature and saved models included,
  and an empty result when nothing is known.
- `tests/helpers/load.js` gains `setDisabled` on the fake text and textarea
  controls, which the AI page's feature-model fields already used.
- No note format, other setting key, review schedule or network default changed.
