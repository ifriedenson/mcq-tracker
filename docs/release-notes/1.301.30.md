# 1.301.30 — A provider error is reported when it happens

## What the owner saw
A multi-PDF import failed every file with *"OpenCode stopped answering while it
was writing this file: nothing was written for 6 minutes..."*, twice per file,
while the same PDF imported alone worked (that one stalled later, during the
answer checks, and recovered).

## What was really happening
OpenCode reports a provider failure as an **assistant message with an `error`
and no parts**:

```json
{ "info": { "role": "assistant", "error": { "name": "APIError",
  "data": { "message": "Incorrect API key provided" } } }, "parts": [] }
```

1.301.29 measured progress as "a note written, or a tool call started or finished".
That message changes none of those, so a rejected key, a rate limit or an overloaded
model looked exactly like a frozen server: six minutes of silence, a restart that
could not help, six more minutes, then a misleading "stopped answering" reason.

## What changed
- `pollAgent()` extracts the error with `assistantErrorText()` (from
  `info.error.data.message`, `info.error.message`, `data.error` or the error name)
  and returns it with the poll result.
- `waitForAgent()` throws `agentFailureText()` immediately on that error, with the
  provider's own words and the next step:
  - a rate/usage/quota/429/overloaded message says to wait a few minutes and import
    the file again;
  - anything else points at **Settings → Study agent → AI** (backend, model, key).
  Either way it says the files already imported are kept.
- A provider error never restarts OpenCode (a restart cannot fix it) and never
  waits out the silence allowance.
- `runAgent()` no longer turns a missing `client.base()` into
  *"client.base is not a function"*; the message is preserved.

## Verification
- `tests/import-batch-window.test.js`: "a provider error inside OpenCode is
  reported at once, not waited out" drives a two-file batch whose session returns
  `{ error: { name: "APIError", data: { message: "429 rate limit exceeded" } } }`
  with no parts, and asserts zero restarts and each file's result carrying
  *"could not write this file: 429 rate limit exceeded"* plus the wait advice.
- Suite: **2,807 pass, 0 fail**; `npm run check` clean; `main.js` 7,302,034 bytes
  from 364 modules.

## Still open
The owner's provider was refusing requests; which error it returned is not known
yet. This release makes that visible on the next run instead of guessing, and the
message says whether to wait or to check the AI settings.
