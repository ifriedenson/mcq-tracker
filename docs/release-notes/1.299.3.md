# 1.299.3 — Accessible names across the plugin

A whole-plugin quality pass: shared form helpers and the primary inputs now
carry accessible names, and the documentation stops naming older builds.

## What changed

- **Shared helpers name their controls.** The Study Workspace
  `renderField`/`renderTextarea` helpers pass the visible label to the input,
  textarea and select they create, and the study tools field helper does the
  same. One change covers every form built through them.
- **Workspace filters are announced.** The annotation, vocabulary, subject,
  time-block tag and PDF-annotation filters, the per-block task input, and the
  Feynman and Deep Notes answer boxes each have their own name instead of
  relying on placeholder text.
- **Primary inputs have names.** Quick Ask, the Study agent search and
  composer, reading pages, Auto Anki, chat memory, course templates, exams,
  Cards typed answers, FRQ, card archive, spaced-everything, transcript and
  quiz/card generators, document cards and OCR text carry accessible names.
- **The documentation names the current build.** The README comparison and the
  decision-sheet header refer to this release, and
  `tests/release-hygiene.test.js` fails if the README stops naming the version
  in `manifest.json`.
- **No behaviour change.** Labels are additive. No note format, review
  schedule, setting, data path, command or network request changed.

## Verification

`tests/a11y-labels.test.js` pins the shared helpers, the workspace filters and
the primary inputs, and `tests/release-hygiene.test.js` adds the README build
check. The full suite passes **2,579 tests**, `npm run check` is clean across
**355 source files**, and `main.js` is current at **7,085,198 bytes** from
**358 modules**.
