# 1.262.0 — Advanced Tables: building a table from a bare pipe

Upstream's guide starts with the way you make a table: type a single `|`, then
the first heading, then Tab, and keep typing headings and pressing Tab. That was
the one flow still missing here. The engine only recognised a table once its
delimiter row existed, so Tab on `| Item` fell through to the editor's own
indentation and a heading could never grow into a table.

## What changed

`src/table-editor.js` now treats a run of lines that start with `|` as a table
even when the delimiter row is absent, and provides three helpers:

- `tableDraftAtLine` returns that unfinished table, or `null` for a finished
  table, a delimiter row, plain text, or a block past the row/column limits.
- `startTable` writes the header and delimiter rows and, when a heading was
  already typed, adds the next empty header cell and puts the cursor in it. A
  bare `|` completes to a one-column table.
- `addTableColumn` adds an empty column at the right edge of every row and puts
  the cursor in the new header cell.

`nextCellTarget` now returns `addColumn` instead of walking into the body when
Tab runs past the last header cell, which is upstream's next-cell behaviour.
`src/plugin.js` wires that into the source-editor listener, into the
**Tables: go to the next cell** command (the mobile path, where there is no Tab
key) and into the palette's **format** action for a draft, all through the
existing `writeTableResult`/`updateTableBlock` path.

Unchanged: Enter moves from the header to the first body row, Shift+Enter still
leaves the table from the header, Tab in the body still walks cells, wraps rows
and appends a row at the end, and nothing outside a pipe row is touched.
Padding, alignment, escaped pipes, CRLF and `TBLFM` comments are preserved
because every write goes through the same renderer and queue.

## Tests

`tests/table-commands.test.js` adds nine tests: a draft completes with the next
heading, a bare pipe completes to one column, a finished table and plain text
are not drafts, a column is added to every row, Tab on `| Term` writes the table
through the editor, Tab at the last header cell adds a column through the
editor, the next-cell command starts a draft, the **format** command completes
a draft to one column, and formatting an already canonical table changes
nothing. The one existing expectation
that header-Tab wrapped into the body now asserts the column instead.

Full suite green; `npm run check` clean; `main.js` rebuilt.
