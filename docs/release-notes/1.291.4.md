# 1.291.4 — Study agent chrome stays readable at full width

The 1.291.3 real-window coverage run, repeated in an uncollapsed 1132 px
main-area leaf and a 296 px sidebar, found two chrome defects outside the
suggestion deck itself:

- The token gauge label was capped at 72 px at every width, so even a 1132 px
  leaf showed `0% · ~16 …` instead of the full `0% · ~16 / 12,000 tokens`. The
  label now releases its cap when the panel container is at least 640 px;
  below that it keeps the compact 72 px label, and the existing ≤470 px rule
  still hides it. At 1132 px the label needs 153 px, and the resulting 291 px
  actions row fits inside the 812 px controls row.
- The **How replies work** disclosure used a text `ⓘ` marker, which the
  Obsidian UI font rendered as an empty square in the Xvfb capture. It now
  uses the same `›` chevron as **Usage and context**, rotating when the details
  is open; reduced-motion still disables the transition.

The suggestion deck, chips, dots, composer, prompts and three-line detail
clamp are unchanged. No schema, dependency, provider, network or storage
behaviour changed.

Verification: `node --test` → **2,459 pass, 0 fail**; `npm run check` clean
across **344 source files**; `main.js` is **6,899,848 bytes** from **347
modules**. The published 1.291.4 assets are re-captured at 1132 px and 296 px
in light and dark in `docs/render/study-agent-ui/`.
