# 1.278.0 — PDF→FRQ import

## Turn a vault PDF into gradable FRQ notes

Free-response questions can now come straight from a PDF you already have. Run **AP: import free-response questions from a PDF**, choose the file, review the prompts and rubrics the text layer produced, then create ordinary AP FRQ notes. Nothing is written until you confirm.

### Review before anything is saved

- **One PDF or a picker.** One matching vault PDF opens directly; several open a picker.
- **Editable split.** Each candidate has a title, prompt, rubric, page number and warnings. Edit the text, choose the course and question type, untick an item to drop it, or cancel.
- **Batch safety.** Every selected item is checked through the existing FRQ note builder before the first write. One invalid item blocks the whole batch rather than leaving a half-imported set.
- **Ordinary notes.** Imported notes use the existing FRQ schema with `rubric_source: user`; they appear under `AP FRQs/<course>/` and work with history, second pass and the study-plan feed unchanged.

### How the split works

The importer reads the PDF text layer through the existing `readPdfPages` helper. It proposes up to 60 items from question labels (`Question N`, `Free Response Question N`, `FRQ N`, `N.`, `N)`) and rubric headings (`Scoring Guidelines`, `Scoring Rubric`, `Rubric`, `Answer Key`, `Points Possible`), with a first-criterion fallback. Prompt text before the rubric (including any stimulus) belongs to the prompt; bullet and Markdown-table rubrics both parse. Prompts are capped at 20,000 characters and rubrics at 12,000. An unrecognized rubric stays visible as invalid and is never replaced with a preset.

### Grade it like any hand-written FRQ

Type or dictate an answer in the existing FRQ grader. `gradeFrqWithAi` compares it against the imported rubric, returns per-criterion scores and feedback, and keeps the usual second pass and history. No new AI feature ID, provider or model allow-list entry was added. The grader remains an aid; no accuracy claim is made.

### Limits

- **Text-layer PDFs only.** An image-only or scanned PDF is refused with a Notice; this import does not run OCR or a vision call. The PDF is read in place: it is not copied, uploaded or stored by the importer.
- No bundled AP content, no new runtime dependency and no new note schema.
- The headless test harness stubs pdf.js, so the end-to-end test injects page text at the `readPdfPages` boundary; a real Obsidian desktop/mobile PDF should still be checked by hand. The three owner-run visual/device/screenshot passes remain open.
