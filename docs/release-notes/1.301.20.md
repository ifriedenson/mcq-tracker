# 1.301.20 — Recent files opens without an error in the log

The live pass behind [1.301.19](1.301.19.md) opened every plugin view. One of
them, **Recent files**, drew its list correctly but Obsidian logged
`Failed to open view TypeError: o.startsWith is not a function` while loading the
leaf.

## Cause

`RecentFilesView` extends `ItemView` and keeps no per-leaf state. `ItemView`'s
default `getState()` reports `this.file`, which this view never sets, so when
Obsidian restored or loaded the leaf it called its external-file resolver with
`undefined` and the resolver called `startsWith` on it.

## Fix

The view now answers `getState()` with `{}` and ignores `setState()`, because it
has no state of its own to restore. Nothing about the list, its pins, the filter
or the file it opens changed.

## Verified

In the live 1.15.1 window, **Recent files: open** now opens the view with no
`Failed to open view` event at all (`Runtime.exceptionThrown` and console errors
were watched for the action), and the view renders the same rows, pins and
buttons as before. `tests/feature-surfaces.test.js` pins the empty state.

No note format, setting key, review schedule or network default changed.
