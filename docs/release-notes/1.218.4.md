# MCQ Tracker 1.218.4

Fixes silent data loss when splitting a PDF that has fillable form fields.
`splitPdf` copied pages only, and a page copy carries a field's widget but not
the document's AcroForm, so every split part opened with no fields at all — the
filled values were simply gone.

## What changed

`splitPdf` now detects a form, serialises the document, flattens that copy
through the existing `flattenForm` path, and extracts the parts from it. Split
files keep what the form showed, with the values baked into the pages, and the
result reports `flattened: true`; the document being edited keeps its live,
fillable form and its history. A form that cannot be flattened refuses the split
with the flatten error instead of writing parts that lost it.

## Verification

`tests/pdf-editor.test.js` adds "splitting a PDF with a form bakes the values in
instead of dropping the form": a three-page fixture with a filled `student` field
splits into parts of two and one pages, both parts reload with no form fields and
no widget annotations, the split reports `flattened: true`, and the edited
document still has its one live field. The window's split test still writes
`(split 1)` and `(split 2)` with the same page counts.

**1,687 tests pass / 0 fail**, `npm run check` is clean, `main.js` is rebuilt and
`git diff --check` is clean.
