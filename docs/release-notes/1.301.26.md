# 1.301.26 — A waiting answer check shows its age

## What changed
- **The checking line counts up.** `PdfImportModal.waitClock(makeText)` repaints the
  status every second as `Checking answer 4 of 27: <note>... (2:14)`, so an import
  that has stopped moving is visible in a minute instead of looking like a frozen
  sentence. Both check paths use it: the per-note check in `finishAgentNotes` and
  the check after a review in `verifyDraftAnswers`, where the clock follows the
  `onProgress` position. The clock stops when the answer arrives and the last line
  stays on screen.
- Nothing about how long a check may take changed. The count is information, not a
  deadline; what ends a request that truly stopped answering is the client's own
  guard (`OpenCodeClient.send` writes-nothing-new bound, 60 s OpenCode request
  timeout, 120 s Direct API timeout).

## Why
The owner's import sat on `Checking answer 4 of 27` for nine hours and nothing on
screen showed that time was passing. The underlying unbounded wait is already gone
in 1.301.17+ (per-request idle guard, and Stop cancels the wait), but a silent
status line still made a long check look identical to a stuck one.

## Verification
- `tests/import-batch-window.test.js`: a fresh `waitClock` prints `(0:00)`, still
  prints `(0:01)` a second later, and the text no longer changes after the clock is
  stopped.
- The full suite is run at this release; `npm run check` stays clean.
- No note format, setting, review schedule or network default changed.
