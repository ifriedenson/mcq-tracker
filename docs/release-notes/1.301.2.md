# 1.301.2 — Stop an import cleanly

The running import now has explicit stop choices instead of one blunt Stop.
**Undo everything** removes what the import made, **Finish this file, then
stop** saves the current file before stopping, and **Discard this file** keeps
finished files while removing only the current one. Hanging AI or OpenCode
requests end promptly, stopped work is cleaned up, and the summary reports
what was kept, stopped or undone.

## What changed

### Three explicit stop choices

- The running import screen now offers **Undo everything**, **Finish this
  file, then stop**, and **Discard this file**.
- **Undo everything** deletes every note, source copy and picture the import
  session made, including files from already finished batch entries, then
  stops without offering Practice.
- **Finish this file, then stop** keeps working on the current PDF, saves it
  when it finishes, and stops before the next PDF.
- **Discard this file** stops now, keeps PDFs that already finished, and
  deletes only the current attempt.

### Prompt cancellation and cleanup

- Import waits are cancellable, so Stop ends a hanging Direct AI request or a
  stalled OpenCode send instead of leaving it running.
- Undo tracks session artifacts across the whole import, while Discard only
  removes the current attempt.
- A stopped single-file import gets the larger stopped summary rather than a
  bare error line.

### OpenCode prompt handling

- The OpenCode client adds `prompt_async` and uses it when the server offers
  it, while still watching messages and written notes to decide when a file is
  really finished.

### Documentation

- The README import section now shows the separate import window, the
  long-lived main-window progress notice, the completion popup and the stopped
  summary, alongside the installed-plugins screenshot.
