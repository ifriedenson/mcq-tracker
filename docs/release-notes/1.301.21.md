# 1.301.21 — The five dialogs work with real content

The 1.301.19 live pass ran against an empty vault, so five dialogs had nothing
to draw, and Obsidian notices were treated as unreadable because the sweep only
looked in the main window. This pass seeded the same disposable vault with real
PDFs, question notes and a due note, read every notice as rendered text, and
fixed what the filled states exposed.

## Recent files: the real cause

1.301.20 blamed `ItemView.getState()` for the `Failed to open view TypeError:
o.startsWith is not a function` error. That diagnosis was incomplete. The view
also defined a method called `open(path)` for its row buttons. `View.open()` is
an Obsidian lifecycle method called when a leaf attaches the view, so Obsidian
called our row opener with no argument; it asked the vault for a file at
`undefined`, the external-file resolver called `startsWith` on it, and the leaf
failed to open.

The row opener is now `openRow()`. `getState()`/`setState()` stay as they were:
the view has no per-leaf state, and saying so is correct, but it was not what
broke the leaf. Re-driven in the live window with
`leaf.setViewState({ type: "question-tracker-recent-files" })`: the list draws,
pins and filter are present, and no error event is emitted. The full 22-view
sweep is clean.

## The due queue's Practice button

The due queue counted never-attempted questions as "due or new" and offered
**Practice 2 due questions**, then started Quick Practice in `"due"` mode.
That mode requires `attempts > 0`, so both entries were filtered out and the
only feedback was `No questions match questions due today.` The queue now
practices exactly the items it listed (mode `smart`), from both the per-row
**Practice** button and the bulk button. Re-driven live: the practice view
opened on question 1 of 2 and the session label read "the due queue".

## The five-minute warning

A five-minute Quick Practice starts at exactly the warning threshold, so
`shouldWarnFive(300, false)` fired half a second in and announced
**Five minutes remaining in Quick Practice**. `shouldWarnFive` now takes the
session length and only warns when the session is longer than five minutes.
Re-driven live over eight seconds: no notice, timer running.

## Empty dialogs and a silent failure

With no question notes, **Find a question** and **Practice a folder** opened an
empty picker with no explanation. Both now say there are no question notes yet
and name the two ways to add some. `practiceWith` also used to return in
silence when the Practice view could not open; it now says what to check.

## Notices read as text

Notices render into the focused window's document, not the main one, which is
why the earlier pass reported them as unreachable. With an observer on every
window, the filled states produced readable text: `Saved the annotation in
Papers/Unit A.annotations.md.`; `That is not a PDF deep link. Copy one from a
PDF deep link.`; the import review's `2 choices · answer B (written by AI) ·
explanation written by AI · answer checked`; the completion summary
`Created 2 notes … 2 have an answer or explanation written by the AI.`; and on a
damaged PDF, `Couldn't import — I couldn't open that PDF. It may be damaged or
password-protected. Remove its password or export a new PDF with selectable
text, then try again.` Each was checked against what the app actually did and
none needed rewording.

## The renderMarkdown component warning

The one warning seen in the previous sweep is framework noise, not this plugin.
All 23 `renderMarkdownInto` call sites pass a Component (views, modals and the
plugin itself), and driving all 22 registered views with an error hook produced
no warning. `tests/render-markdown-component.test.js` fails if a call site ever
stops passing one, and pins the helper's own argument order.
