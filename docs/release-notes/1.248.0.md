# 1.248.0 — Move a link's clickable area

Released Nov 4, 2026.

## What changed

- **Rewrite a link's rectangle in place.** `updateLink` now takes an optional `area` —
  `{ x, y, width, height }`, each a fraction of the page — and replaces the annotation's `/Rect`
  with it. The link keeps its page, its `/Border`, its `/F` flags, its destination and its identity:
  it is the same annotation, moved, not a new one, so nothing else on the page changes.
- **Rotation is handled the way adding a link handles it.** The box is mapped through the page's own
  `/Rotate` with the same `displayRect` helper `addLink` uses, so a box drawn on a rotated page lands
  where it was asked for and reads back unchanged.
- **Area only, or area and destination.** `updateLink({ index, area })` moves the box and leaves the
  address alone; `updateLink({ index, area, target, url | to })` does both in one undo step.
- **The editor row.** **Add content → Links** gains **Area left %**, **Area top %**,
  **Area width %** and **Area height %** with a **Move link** button, beside the existing
  **Change** and **Change link**. It is one undo step, and only **Save a copy** writes.
- **Refusals, each with a message and no change:** a file with no links, a number outside 1 to the
  link count, a rectangle with a missing or non-numeric value, a zero or negative width or height, an
  area under 0.2% of the page each way, a rectangle that leaves the page, and a call that supplies
  neither a new area nor a new destination.

## Verification

- Three new real-byte tests, written first and run against the code before area editing existed:
  `64 pass / 3 fail`, with `expected: true` for the returned `ok`, the unchanged area
  `{"x":0.1,"y":0.1,"width":0.2,"height":0.1}` reported as "moved", and no `area` refusal. After the
  change: `67 pass / 0 fail`.
- What they assert: moving a link keeps one annotation and its address, writes the requested corners
  to `/Rect` in PDF points (`[200, 150, 300, 200]` for a box at 50%/60%, 25% by 10% of a 400×500
  page) and leaves `/Border [0 …]` and `/F 4` in place; a link can be moved and retargeted in the
  same edit; and every refusal leaves the original rectangle and address exactly as they were.
- Full suite **1897 pass**, `npm run check` clean across **297 source files**, `main.js` current
  across **298 modules** at **4,943,104 bytes**, and `git diff --check` clean.

## Limits

- The rectangle is given in percentages of the page box, not in measured points, and it applies to
  the page the link already lives on: a link cannot be moved to a different page.
- **Move link** and **Change link** are separate buttons, so moving and retargeting in one press is
  available to the engine (`updateLink` with both) but not yet to the panel itself.
