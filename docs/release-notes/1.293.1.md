# 1.293.1 — Tablets keep the desktop Settings layout

Settings chose its compact phone layout from `body.is-mobile`, so an iPad —
which Obsidian reports as mobile — lost the desktop category and page list and
fell back to the phone picker. The layout is now chosen when the settings tab
renders.

- **Phones** — `Platform.isPhone` marks the layout `is-phone`; the existing
  single-column body, grouped page picker, wrapped tabs and wrapped setting
  controls apply there.
- **Tablets** — `Platform.isPhone` is false on iPad, so the desktop two-column
  layout and page list stay, with the current category row and breadcrumb.
- **Older API builds** — when `isPhone` is unavailable, `Platform.isTablet`
  decides; a device with neither flag is treated as a phone, matching the
  existing practice-view fallback.
- **Narrow desktop panes** — the container-query picker below 540 px is
  unchanged, so a narrow pane still gets the grouped picker.

`src/settings-tab.js` and `styles.css` carry the change.
`tests/settings-navigation.test.js` adds the iPad, phone and older-platform
test and asserts that no settings rule is scoped to `body.is-mobile`. The split
is covered by the platform-driven tests; no iPad or phone was available for an
in-app capture. No dependency, provider, note schema, storage format or network
path changed.
