# MCQ Tracker 1.227.0

This release closes the page-extraction gap found by the reader-level PDF
editor tests: extracting selected pages from a fillable PDF no longer drops the
form and its filled values.

## What changed

- `extractPdfPages` now checks for AcroForm fields first. When a form is present,
  it serialises the document, flattens that copy and extracts pages from the
  flattened copy. Filled values are baked into the page content, so the
  extracted PDF shows them in any viewer.
- The document being edited keeps its live, fillable form. Extraction only
  prepares a throwaway copy.
- The result reports `flattened: true`, and the editor status names that form
  values were baked into the extracted pages.
- `splitPdf` now uses the same `prepareForPageCopy` helper, so split and extract
  share one tested form-handling path instead of maintaining separate copies.
- An unsupported form that cannot be flattened refuses the extraction with a
  form-specific message rather than silently producing blank pages.

## Honest limits

- The extracted copy is flattened, so its fields are visible but no longer
  fillable. This is required because a copied page cannot carry the source
  AcroForm; flattening is the safe way to keep the values.
- XFA, encrypted PDFs and signatures or button fields that cannot be flattened
  are still refused.
