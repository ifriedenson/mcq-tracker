# 1.302.6 — Empty folders from failed imports clean up with one command

## What the owner saw
After a 100-PDF run failed file after file and was undone, the vault kept one
empty folder per failed file: nothing was ever written into them, so undo —
which removes files — had nothing to remove. `Questions/good/` in the test
vault is one of them: a completely empty directory left behind by an earlier
failed run.

## What changed
The command palette's **Clean up empty import folders**
(`plugin.cleanupEmptyImportFolders()`) walks the import parent — the saved
import folder, else the question folder, else `Questions` — and removes every
empty folder under it, deepest first, so a chain of empty folders goes too.

Safety is a fresh check, not a hope about timing:

- each folder is listed again right before removal, and only a folder still
  holding nothing goes — a note anywhere inside keeps its whole chain, and
  folders holding leftover source copies are left alone too (real Obsidian
  refuses a non-recursive folder remove even when empty, which is why the
  old pattern silently left these folders behind);
- the import root itself is never removed;
- the command refuses while an overnight session or an import window is
  working, when a target folder can be briefly empty between the folder write
  and the first note, and says to run it after the import finishes.

A notice reports the result either way: `Removed N empty folders under
Questions. Notes were not touched.` or `No empty import folders under
Questions. Notes were not touched.`

## Evidence
Eight tests in `tests/cleanup-empty-folders.test.js` pin the behavior: empty
folders go while folders holding notes stay (including a nested note keeping
its whole chain), a chain of three empty folders is removed deepest first, a
folder with only a copied PDF is left alone, the root itself is never removed,
a missing root reports plainly, both a running overnight session and a
running import window refuse the cleanup, and a stand-in adapter that answers
every non-recursive remove with EISDIR (what real Obsidian does, found live)
still sees the empty folder removed and the note kept.

## Checks
`node --test`: 2,892 pass, 0 fail. `npm run check`: clean. `main.js` rebuilt
from source. No note format, setting key, review schedule or network default
changed.
