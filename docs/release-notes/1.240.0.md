# 1.240.0 — Time-block tags

Released **Nov 4, 2026**. Optional **Time blocks** module; off by default.

## What changed

- **Add a time block** and the block editor gain a **Tags (optional)** field. A block keeps up
  to six local tags, entered as a comma or space separated list; a leading `#` is optional.
- Tags are normalised to lowercase, restricted to `a-z 0-9 / _ -` and shown as chips on the
  block card in the Day view.
- The Day view gains a **Filter by tag** field. It filters the day's blocks with
  `blocksForTag` and reports the active tag when nothing matches, instead of claiming the day
  is empty.
- **Write day note** now writes a block's tags after the title (`- 09:00 - 10:30 Cells #focus`),
  so an exported plan keeps the same labels the planner shows.
- `normalizeBlockTags`, `blocksForTag` and `tagSummary` are pure and bounded; the data lives in
  each block inside `settings.timeBlocks.blocks`. No note is written, no tag is created in the
  vault and no dependency, provider or network request was added.

## Refusals

Empty, unsafe or over-long tags are dropped; a seventh tag is ignored. An unknown filter tag
returns no blocks and the view says which tag is active rather than writing anything.
