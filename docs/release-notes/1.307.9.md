# 1.307.9 — Every delete has a way back

## Why
1.307.7 and 1.307.8 made study tasks recoverable on both surfaces. Nothing else
was. A sweep of every destructive control in the plugin found roughly two dozen
Delete, Remove and Discard buttons over settings-backed user content, each of
them removing the record on one click with no notice, no confirm and no undo —
while the task list next door offered both. Two surfaces even answered the same
kind of click differently.

## The one implementation
`plugin.deleteWithUndo({ label, remove, onChange })` in `src/plugin.js`:

- snapshots `this.settings` (JSON) before the delete;
- runs the same `remove()` the button always ran, so no behaviour moved;
- shows `Deleted “<name>”.` for 8 seconds with the existing `.qt-notice-undo`
  Undo button (58×32, 8.37:1 label contrast — the task list's own notice);
- Undo restores only the settings keys the delete changed, and only while they
  still hold exactly what the delete left behind. If anything in those keys
  changed since, it says *“That part changed since the delete, so it was left as
  it is.”* and writes nothing, so a newer edit is never overwritten;
- the button disables itself, so one notice cannot restore twice;
- `capture`/`restore` cover data that does not live in settings: pending card
  grades in device storage and EPUB highlights in the book's sidecar.

`deleteStudyTaskWithUndo` is now a three-line wrapper over it, so the task list
and everything else share one notice rather than two look-alikes.

## Driven live — Obsidian 1.15.1, Primary, 1280×900
Sixteen kinds were seeded, deleted through their own rendered button, then
undone through the rendered notice. For each one: the button was found by its
accessible name, the stored settings changed, the notice named the record, the
Undo button measured 58×32, Undo restored the settings to a byte-identical
snapshot of every setting (`restoredExactly: true`), and the same button then
read `disabled: true`.

- annotation, vocabulary, deep notes, Feynman explanation, course grade,
  subject, subject project, absence, Study Flow excerpt, planner topic, planner
  plan, block task, time block, backlog item, local event, chat memory fact.

## Covered by tests, not this harness
- Saved-conversation delete, chat project removal, practice preset delete and
  the pending-grade panel are wired through the same helper but were not
  reachable in this window: the agent panel opens AI-off, and the practice
  preset and pending-grade controls need a live session.
- `tests/undo-everywhere.test.js` drives annotation, vocabulary, time block with
  its task, chat memory fact through its modal, and the concurrent-change
  refusal (a later edit keeps the undo from firing).

## Found already safe — left alone
- **Review sidebar → Remove from review** keeps the note: it clears review
  state in frontmatter, and the note itself is untouched.
- **PDF editor** “Reset changes”, “Remove all links”, “Delete field” and **PDF
  ink** “Clear page” act on an in-editor buffer; nothing is written until Save,
  and the ink editor has its own Undo.
- **Discard all** (AI proposals, agent edits, FRQ import), quiz generator
  Remove, paper scanner Remove/Reset crop and the staged image list: nothing is
  persisted yet.
- **Session-only state**: focus-day scratch tasks and Reset, chat “Clear plan”,
  simple-quiz “Clear marks”, practice “Remove set” and the Clear filter chips.
- **Settings with visible defaults**: FSRS “Reset”, reference “Reset view” and
  “Reset cut scores”, time-block colour Clear — a value returns to its default
  rather than content being destroyed.
