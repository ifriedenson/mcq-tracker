# MCQ Tracker 1.169.2

This patch fixes the import dialog crash that could appear as soon as a file was chosen:

> Couldn't import — extensionOf is not a function

## What was wrong

The shared document reader defined `extensionOf`, but did not export it. The question importer, the course-notes importer and the document-review dialog all use that helper to recognise the chosen file's format. Starting an import therefore threw a `TypeError` before the file was read.

## What changed

- Exported `extensionOf` from `src/documents.js`.
- Added a regression test that calls the import modal's real `readSource()` path with a text file and then reads it through the shared document reader.
- Rebuilt `main.js` from the fixed source.

No note formats, settings, schedules or saved data changed. Existing installations keep the same behaviour; imports simply work again.

## Verification

**1,320 tests pass / 0 fail**; `npm run check` is clean; `main.js` is rebuilt from `src/`. The new test confirms the modal reads the source and returns `ext: "txt"` without a `TypeError`.

## Upgrade

Install **1.169.2** with BRAT, the community directory when it updates, or by copying the three release assets into `<your vault>/.obsidian/plugins/mcq-tracker/`. Restart or reload Obsidian before trying the import again.
