# MCQ Tracker 1.225.0

This release audits the PDF editor against a full-editor capability set and
closes the two gaps the audit proved: copying selected text, and stale form-field
page labels after a page move. Every claimed editing capability is exercised on
real PDF bytes, saved, reopened with pdf-lib, and asserted; interactive paths use
the existing mocked-window tests.

## Capability checklist

| Capability | Result | Evidence and limits |
|---|---|---|
| Open, navigate and render a multi-page PDF | **Pass** | `loadEditorDocument`/`pageList` and the reader's Previous/Next/page field rendered every page at 1.225. That release was page-at-a-time; **1.226.0 replaces it with continuous scrolling**. |
| Select text and copy it | **Pass** | **Select text** reads the page's text layer. The quote dialog now has **Copy selected text** for the full selection, separate from the truncated preview. Clipboard failure is reported, never silent. |
| Highlights, underlines, strike-through, boxes, quotes, text boxes and freehand ink | **Pass** | One mark renderer and the pdf-lib burn path cover every style, colour and note. `flattenAnnotations` now proves underline, strike and box survive a save/reopen too. |
| Edit and delete existing annotations | **Pass** | The sidebar edits notes and tags inline, deletes rows, erases ink/text boxes, and writes every change to the `.annotations.md` sidecar without moving the page. |
| Read, fill and save form fields | **Pass** | Text, checkbox, radio, dropdown and multi-select fields are read and written. Values, choices and appearances survive save/reopen; read-only, unknown-choice and unsupported fields are refused. |
| Rotate, reorder, insert, duplicate, delete, merge, extract and split pages | **Pass** | Each operation is tested on real bytes and the saved copy is reopened. **Fixed here:** moving a page now refreshes every form field's page label; the page map keeps annotations on their original page. |
| Save/export a real PDF | **Pass** | Save, extract, split and merge write new files without touching the source PDF, its hash or its sidecar. The saved bytes are parsed again by pdf-lib. |
| Undo/redo | **Pass** | The bounded byte-backed history restores the exact opened bytes, names the action, drops the redo tail on a new edit, and clears after save. |
| Annotation/citation sidebar consistency | **Pass** | Sidecar edits and deletion are covered; burning after a reorder is covered by page-content assertions, so a moved page keeps its marks and no neighbouring page receives them. |

## What changed

- `PdfInkModal` passes the complete selected quote to the quote dialog, which
  offers **Copy selected text** and reports success or clipboard failure.
- `PdfEditorModal.reorder` calls `syncFields`, so a form field's `page N` label
  is rebuilt from the live document after a page move.
- The editor burn test now includes underline, strike-through and box marks, and
  a new engine test checks that a reordered page receives its annotation while
  every other page's content stream stays unchanged.
- The window test asserts both moved field page labels.

## Honest limitations

- Existing page text cannot be reworded or re-flowed; new text is drawn on top.
- At 1.225 the reader showed one page at a time; **1.226.0 supersedes this with continuous multi-page scrolling**.
- XFA and encrypted PDFs are refused. Annotations remain in the sidecar until
  they are burned into a saved copy; existing ink cannot be moved or resized.
- Scanned pages need OCR before text selection or copy has anything to read.
